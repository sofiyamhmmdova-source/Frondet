Şərti Operatorlar: qərar vermə məntiqinin 3 yolu

if / else, switch / case və ternary (?:) — kodun icra istiqamətini şərtə görə dəyişən üç əsas alət. Bu dərsdə hər birini sintaksisi, canlı nümunələri, tez-tez buraxılan səhvləri və düzgün istifadə tövsiyələri ilə addım-addım öyrənəcəksən.

01Giriş

Şərti operator nədir?

Demək olar ki, hər real proqramda məntiq bir sualdan keçir: istifadəçinin yaşı kifayətdirmi? Səbət boşdurmu? Server cavabı uğurludurmu? Şərti operatorlar məhz bu suala görə kodun hansı sətirlərinin icra olunacağını müəyyən edir. JavaScript şərti icra üçün üç əsas vasitə təklif edir — onları aşağıda ətraflı görəcəksən.

Bütün şərtlər arxa planda bir sualı verir: bu dəyər "true" kimi, yoxsa "false" kimi davranır? Bunun üçün əvvəlcə truthy / falsy anlayışını bilmək vacibdir — çünki if, ternary və hətta switch-in daxili müqayisələri məhz bundan asılıdır.

Falsy dəyərlər (yalnız bunlar)

  • false
  • 0 və -0
  • 0n (BigInt sıfır)
  • "" (boş sətir)
  • null
  • undefined
  • NaN

Truthy dəyərlər (qalan hər şey)

  • "0" — sətir kimi truthy
  • "false" — sətir olduğu üçün truthy
  • [] — boş massiv belə truthy
  • {} — boş obyekt belə truthy
  • istənilən müsbət/mənfi ədəd (0-dan başqa)
  • istənilən boş olmayan sətir
💡

Niyə vacibdir?

Falsy siyahısı yalnız 7 dəyərdən ibarətdir və əzbərlənə bilər. Qalan hər şey (boş massiv, boş obyekt, "0" sətri daxil) truthy sayılır. Bu, çox rast gəlinən bir səhvin — "boş massiv false olmalıdır" fikrinin — yanlış olduğunu göstərir.

02If · Else If · Else

if / else if / else

if ən çox istifadə olunan şərti operatordur. Şərt true olarsa bloku icra edir; olmazsa növbəti else if-ə, sonda isə else-ə keçir. Şərtlər yuxarıdan aşağı, ardıcıl yoxlanılır və ilk uyğun gələn şərtin bloku icra olunur, qalanları isə atlanır.

sintaksis.js
if (şərt1) {
  // şərt1 true olduqda işləyir
} else if (şərt2) {
  // şərt1 false, şərt2 true olduqda işləyir
} else {
  // heç bir şərt true olmadıqda işləyir
}
🧪 Canlı nümunə — yaş kateqoriyası
if (yas < 13) {
  netice = "Uşaq";
} else if (yas < 18) {
  netice = "Yeniyetmə";
} else {
  netice = "Yetkin";
}
Nəticə burada görünəcək…

⚠️ Tez-tez buraxılan səhvlər

🐞

1. = ilə ==-i qarışdırmaq

if (yas = 18) — bu müqayisə deyil, mənimsətmədir. Nəticə həmişə 18 (truthy) olacaq və şərt daim true kimi işləyəcək. Doğrusu: if (yas === 18).

🐞

2. == istifadə etmək (tip çevrilməsi)

"18" == 18 → true, çünki JS tipləri avtomatik çevirir. Amma "18" === 18 → false. Gözlənilməz nəticələrdən qaçmaq üçün həmişə === və !== istifadə et.

🐞

3. Fiqurlu mötərizələri unutmaq

if (şərt) sətir1(); sətir2(); — mötərizəsiz yalnız sətir1() şərtə bağlıdır, sətir2() həmişə icra olunur. Sonradan kod böyüyəndə bu, çətin tapılan bir buq yaradır.

🐞

4. else if ardıcıllığının səhv qurulması

Geniş şərt dar şərtdən əvvəl yazılarsa, dar şərt heç vaxt işə düşmür. Məsələn yas > 0 şərti yas > 18-dən əvvəl gəlsə, ikinci şərt praktik olaraq ölü koddur.

🐞

5. NaN ilə birbaşa müqayisə

NaN === NaN həmişə false qaytarır. Yoxlamaq üçün Number.isNaN(deyer) istifadə et, sadə bərabərlik yox.

✅

Tövsiyə

Dərin iç-içə if bloqları oxunaqlılığı azaldır. Mümkünsə "guard clause" (erkən qayıdış) modelindən istifadə et: uyğun olmayan halları funksiyanın əvvəlində return ilə kəs, əsas məntiqi isə mötərizə içində saxlama.

03Switch · Case

switch / case

switch bir dəyəri bir neçə case ilə ciddi bərabərlik (===) əsasında müqayisə edir — bir dəmiryol relsinin qatarı bir "yola" yönləndirməsi kimi düşün. Uyğun gələn case tapılan kimi icra başlayır və break əmrinə qədər (və ya blokun sonuna qədər) davam edir.

sintaksis.js
switch (deyer) {
  case 1:
    // deyer === 1 olduqda
    break;
  case 2:
    // deyer === 2 olduqda
    break;
  default:
    // heç bir case uyğun gəlmədikdə
}
🧪 Canlı nümunə — həftənin günü
switch (gun) {
  case 1: netice = "Bazar ertəsi"; break;
  case 2: netice = "Çərşənbə axşamı"; break;
  case 3: netice = "Çərşənbə"; break;
  case 4: netice = "Cümə axşamı"; break;
  case 5: netice = "Cümə"; break;
  case 6: netice = "Şənbə"; break;
  case 7: netice = "Bazar"; break;
  default: netice = "Naməlum gün";
}
Bir gün seç…
🧪 Canlı sınaq — break unudulanda nə baş verir?

Aşağıdakı düymələrdən başlanğıc addımı seç, sonra "break aktivdir" keçidini söndür və fərqi izlə. Bu, real JS kodunda işlədilir — heç nə saxtalaşdırılmayıb.

break aktivdir (normal davranış)

⚠️ Tez-tez buraxılan səhvlər

🐞

1. break unutmaq → fall-through

break olmasa icra növbəti case-ə də davam edir — şərtindən asılı olmayaraq. Yuxarıdakı canlı sınaqda bunu özün yoxlaya bilərsən.

🐞

2. case ciddi bərabərliklə (===) müqayisə edir

case '1': heç vaxt deyer 1 (ədəd) olduqda işə düşmür, çünki tiplər fərqlidir. Dəyəri müqayisədən əvvəl uyğun tipə çevir.

🐞

3. default-u unutmaq və ya səhv yerə qoymaq

default olmasa gözlənilməyən dəyərlər səssizcə heç nə etmədən keçib gedir. Adətən sonda yazılır, amma texniki olaraq istənilən yerdə ola bilər.

🐞

4. Təkrarlanan case dəyərləri

Eyni dəyərə malik iki case yazılsa, yalnız birincisi heç vaxt işə düşməyəcək ikincini "ölü kod"a çevirir — JS xəbərdarlıq vermədən bunu qəbul edir.

🐞

5. Obyekt/massiv üzərində switch

switch obyektləri istinad (reference) əsasında müqayisə edir. İki fərqli {} heç vaxt bərabər sayılmır, məzmunu eyni olsa belə.

✅

Tövsiyə

Hər case-i break (və ya funksiya daxilində return) ilə bitir. Qəsdən fall-through istifadə edirsənsə, oxucu üçün // fall through şərhi qoy. Əgər variantların sayı çoxdursa və sadəcə dəyər axtarırsansa, bəzən adi obyekt (lookup table) daha qısa və sürətli oxunur.

04Ternary

Ternary operator ( ? : )

Ternary — yeganə üç operandlı operatordur: şərt ? nəticə_true : nəticə_false. O, if-else-dən fərqli olaraq ifadədir (expression), yəni birbaşa dəyər qaytarır və dəyişənə mənimsədilə bilər.

sintaksis.js
const netice = şərt ? "true olarkən dəyər" : "false olarkən dəyər";

// if-else-in analoqu:
let netice2;
if (şərt) {
  netice2 = "true olarkən dəyər";
} else {
  netice2 = "false olarkən dəyər";
}
🧪 Canlı nümunə — cüt / tək ədəd
const netice = eded % 2 === 0 ? "cütdür" : "təkdir";
Nəticə burada görünəcək…

İç-içə ternary: mümkündür, amma ehtiyatlı ol

Ternary-ni zəncirləmək olar, amma 2-3 səviyyədən sonra oxumaq çətinləşir:

oxunması-çətin.js
// ❌ Oxumaq çətindir — hansı şərt hansı nəticəyə aiddir?
const qiymet = bal >= 90 ? "A" : bal >= 75 ? "B" : bal >= 60 ? "C" : "F";
daha-oxunaqli.js
// ✅ Eyni məntiq, amma aydın quruluşda
function qiymetHesabla(bal) {
  if (bal >= 90) return "A";
  if (bal >= 75) return "B";
  if (bal >= 60) return "C";
  return "F";
}

⚠️ Tez-tez buraxılan səhvlər

🐞

1. Çox sayda iç-içə ternary

2-3 səviyyədən çox iç-içə ternary kodu "oxu tapmacasına" çevirir. Bu halda if-else zənciri və ya lookup obyekt daha yaxşı seçimdir.

🐞

2. Ternary-ni yan-effekt üçün istifadə etmək

şərt ? funksiya1() : funksiya2(); — nəticə heç yerə mənimsədilmir, sadəcə iki funksiyadan birini çağırmaq üçün istifadə olunur. Bu, ternary-nin təyinatına uyğun deyil; belə hallarda adi if-else daha oxunaqlıdır.

🐞

3. Operator prioriteti qarışıqlığı

Ternary-ni digər operatorlarla (məsələn mənimsətmə və ya riyazi əməllərlə) qarışdıranda gözlənilməz nəticələr ola bilər. Aydınlıq üçün şərti mötərizəyə al: (şərt) ? a : b.

🐞

4. Uzun ifadələr mobil ekranda scroll yaradır

Ternary-nin hər iki tərəfi uzun ifadə olduqda sətir çox uzanır və kiçik ekranlarda oxunması çətinləşir. Uzun ifadələri adlandırılmış dəyişənlərə çıxarmaq daha rahatdır.

✅

Tövsiyə

Ternary-ni yalnız sadə, tək-sətirlik dəyər seçimi üçün saxla (məsələn UI-da şərti mətn göstərmək). Mürəkkəb məntiq üçün if-else və ya funksiyaya keç.

05Müqayisə

Hansını nə vaxt seçməli?

Üç operatorun da öz yeri var — vəziyyətə görə düzgün seçim kodu daha oxunaqlı edir.

Operator Nə vaxt istifadə et Oxunaqlılıq Tipik istifadə sahəsi
if / else Mürəkkəb, çox-şərtli və ya aralıq (range) əsaslı məntiq üçün Çoxlu şərtdə ən aydın seçimdir Formanın validasiyası, girişə görə fərqli axın
switch / case Bir dəyişənin bir neçə konkret, dəqiq qiymətini yoxlayanda Çoxlu variantda if-else-dən aydın ola bilər Menyu seçimi, status/gün/rol kimi sabit siyahılar
ternary ( ?: ) Tək, sadə şərtə görə bir dəyər seçəndə Yalnız qısa ifadələrdə aydındır UI-da şərti mətn/sinif, sadə default dəyər təyini
06Ümumi Tövsiyələr

Daha yaxşı kod üçün 6 qayda

01

Həmişə === və !== istifadə et

Tip çevrilməsi qaynaqlı gözlənilməz nəticələrin qarşısını alır.

02

Erkən qayıdış (guard clause)

Uyğun olmayan halları funksiyanın başında return ilə kəs, dərin iç-içəlikdən qaç.

03

Fiqurlu mötərizələri həmişə yaz

Tək sətirlik if belə olsa, { } gələcək dəyişikliklərdə xətanın qarşısını alır.

04

Böyük zənciri obyekt/Map ilə əvəzlə

10+ case və ya else if varsa, lookup obyekt həm qısa, həm sürətlidir.

05

Şərtləri adlandır

if (yas >= 18 && hasId) əvəzinə const isAdultVerified = yas >= 18 && hasId;

06

Ternary-ni sadə saxla

Maksimum 1 səviyyə iç-içə; daha mürəkkəb məntiq üçün funksiyaya keç.

07Yoxla Özünü

Bildiklərini yoxla

3 sürətli sual — düzgün cavabı seç, izahat dərhal görünəcək.

1. if (yas = 18) { ... } kodunda problem nədir?
Düzgün cavab: birinci variant. = mənimsətmə operatorudur və ifadə həmişə 18 (truthy) qaytarır, ona görə şərt daim true olur. Doğrusu === istifadə etməkdir.
2. switch-case-də break unudularsa nə baş verir?
Düzgün cavab: ikinci variant. break olmadıqda icra sonrakı case-lərin bloklarına da davam edir, şərtlərindən asılı olmayaraq — yuxarıdakı canlı sınaqda bunu gördün.
3. Ternary operatorunun düzgün sintaksisi hansıdır?
Düzgün cavab: üçüncü variant. Ternary üç hissədən ibarətdir: şərt, ?, true nəticəsi, :, false nəticəsi.
Bu dərs JavaScript-də if / else, switch / case və ternary (?:) operatorlarını əhatə edir. Canlı nümunələr üzərində özün sınaqdan keçir — dəyərləri dəyiş və nəticənin necə dəyişdiyini izlə.
