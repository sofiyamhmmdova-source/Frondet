JavaScript Dəyişənlər, Data Type-lar və Console

Bu dərsdə dəyişən nədir, var, let və const arasındakı fərqlər, JavaScript-in data type-ları, console obyektinin imkanları və başlanğıc səviyyəli developerlərin ən çox düşdüyü xətalar (bug-lar) addım-addım, real kod nümunələri ilə izah olunur. Hər bölmədə özünüz kod yazıb nəticəni canlı görə biləcəyiniz kiçik "console" simulyatoru var.

⏱ ~35-45 dəqiqə 🧪 İnteraktiv sınaq bölmələri 🐞 10+ real bug nümunəsi ✅ Best practice checklist
01 Əsas anlayış

Dəyişən (variable) nədir?

Dəyişəni ən sadə şəkildə etiketlənmiş qutu kimi düşünə bilərsiniz: içərisinə bir dəyər qoyursunuz (rəqəm, mətn, obyekt və s.) və sonra həmin qutuya adı ilə müraciət edirsiniz. JavaScript-də yaddaşdakı bu "qutunu" yaratmaq üçün var, let və ya const açar sözlərindən istifadə olunur.

nümunə.jsJavaScript
let ad = "Aygün";       // "ad" qutusuna mətn qoyulur
let yas = 24;           // "yas" qutusuna rəqəm qoyulur
let aktivdir = true;    // "aktivdir" qutusuna boolean qoyulur

console.log(ad, yas, aktivdir);
// "Aygün" 24 true

Bir dəyişən elan edərkən (declare) əslində üç şey baş verir:

  1. Elan (Declaration): JavaScript mühərriki yaddaşda dəyişən üçün yer ayırır.
  2. Təyinetmə (Initialization/Assignment): Həmin yerə ilk dəyər yazılır.
  3. İstifadə (Usage): Dəyişən adı vasitəsilə dəyərə istənilən yerdən müraciət olunur (scope daxilində).
💡 Adlandırma qaydaları

Dəyişən adları hərflə, $ və ya _ ilə başlaya bilər (rəqəmlə yox), böyük/kiçik hərfə həssasdır (ad ilə Ad fərqli dəyişənlərdir) və rezerv sözlər (let, class, function və s.) dəyişən adı kimi istifadə oluna bilməz. Konvensiya olaraq camelCase istifadə olunur: istifadeciAdi.

02 Elan üsulları

var, let və const arasındakı fərqlər

JavaScript-də dəyişən elan etməyin 3 yolu var. Onların fərqi yalnız sintaksis deyil — scope (əhatə dairəsi), hoisting davranışı və yenidən yazıla bilmə qabiliyyətinə görə tamamilə fərqlidirlər.

Yenidən elan (redeclare) Olar Olmaz (eyni scope-da) Olmaz

Scope fərqi — canlı nümunə

scope.jsJavaScript
if (true) {
  var a = "mən var-am";
  let b = "mən let-əm";
}

console.log(a); // "mən var-am"  → var funksiya/qlobal scope-a çıxır
console.log(b); // ReferenceError: b is not defined → let blokdan kənara çıxmır
Nəticə:Uncaught ReferenceError: b is not defined

const — sabit, amma "içi" dəyişə bilər

const onu göstərir ki, dəyişənin özünü yenidən başqa dəyərə bağlaya bilməzsiniz. Amma əgər dəyər obyekt və ya array-dirsə, onun daxili məzmununu dəyişmək mümkündür — çünki referens (yaddaş ünvanı) dəyişmir, yalnız məzmun dəyişir.

const-mutasiya.jsJavaScript
const meyveler = ["alma", "armud"];
meyveler.push("nar");     // ✅ işləyir — array-in içi dəyişir
console.log(meyveler);    // ["alma", "armud", "nar"]

meyveler = ["banan"];     // ❌ TypeError: Assignment to constant variable.
Nəticə:TypeError: Assignment to constant variable.

03 Data Type-lar

JavaScript-də data type-lar

JavaScript dinamik tipli (dynamically typed) dildir — dəyişən elan edərkən tip göstərmirsiniz, tip avtomatik olaraq verdiyiniz dəyərdən müəyyən olunur və proqram işlədikcə dəyişə bilər. Data type-lar iki qrupa bölünür: primitiv (primitive) və referens (reference).

🐞 Tarixi bug: typeof null === "object"

Bu, JavaScript-in ilk versiyalarından qalma məşhur bir xətadır. Məntiqlə typeof null "null" qaytarmalıdır, amma real nəticə "object"-dir. Səbəbi köhnə daxili implementasiyada tip yoxlamasının bit səviyyəsində səhv işləməsidir. Geriyə uyğunluğu (backward compatibility) pozmamaq üçün bu xəta heç vaxt düzəldilmədi. Ona görə null yoxlamaq üçün typeof yox, birbaşa x === null müqayisəsindən istifadə edin.

💡 undefined ilə null arasındakı fərq

undefined — JavaScript mühərriki tərəfindən avtomatik verilir: dəyişənə hələ dəyər verilməyib, funksiyaya arqument göndərilməyib, ya da mövcud olmayan obyekt property-sinə müraciət olunub. null isə — developer tərəfindən şüurlu şəkildə "burada heç nə yoxdur" mənasında yazılır. Fərq niyyətdədir: biri "unudulub", digəri "bilərəkdən boşdur".

04 Debug alətləri

console obyekti

console brauzerin (və Node.js-in) inkişaf etdiricilərə verdiyi alətdir — kodun içindən məlumatı, xəbərdarlıqları və xətaları ekrana ("DevTools → Console" bölməsinə) çıxarmaq üçün istifadə olunur. Yalnız console.log ilə kifayətlənmək səhvdir — aşağıdakı metodlar debug prosesini xeyli asanlaşdırır.

05 Diqqətli olun

Tez-tez rast gəlinən xətalar və bug-lar

Aşağıda başlanğıc və orta səviyyəli JavaScript developerlərinin ən çox düşdüyü 10 real problem toplanıb — hər biri "niyə baş verir" izahı və düzəliş nümunəsi ilə birlikdə.

1. const dəyişəni yenidən mənimsətmək

bug-1.js
const yas = 25;
yas = 26; // ❌ TypeError: Assignment to constant variable.
Düzəliş:Dəyər dəyişəcəksə əvvəldən let istifadə edin.

2. Temporal Dead Zone (TDZ)

let və const ilə elan olunan dəyişənlər də "hoisting"ə uğrayır, amma elan sətrinə qədər onlara toxunmaq mümkün deyil — bu aralığa Temporal Dead Zone deyilir.

bug-2.js
console.log(sheher); // ❌ ReferenceError: Cannot access 'sheher' before initialization
let sheher = "Bakı";

// müqayisə üçün var:
console.log(olke);   // ✅ undefined (xəta vermir, amma çaşdırıcıdır)
var olke = "Azərbaycan";

3. == ilə === arasındakı fərqi unutmaq

bug-3.js
console.log("5" == 5);   // true  → tip məcburi çevrilir (coercion)
console.log("5" === 5);  // false → tip də yoxlanılır
console.log(null == undefined);  // true
console.log(null === undefined); // false
console.log([] == false);        // true  → çaşdırıcı nümunə!
Qayda:Həmişə === və !== istifadə edin, ==-dən qaçın.

4. NaN özü-özünə bərabər deyil

bug-4.js
console.log(NaN === NaN); // false 😳
console.log(Number.isNaN(NaN)); // true → doğru yoxlama üsulu bu

let neticee = "abc" / 2;
console.log(neticee); // NaN
console.log(typeof neticee); // "number" — NaN "number" tipindədir!

5. String və Number qarışığı

bug-5.js
console.log(1 + "1");   // "11"  → toplama zamanı string-ə çevrilir
console.log("5" - 1);   // 4     → çıxma zamanı number-ə çevrilir
console.log("5" * "2"); // 10
console.log(1 + 2 + "3"); // "33"  → soldan sağa: 1+2=3, sonra 3+"3"="33"
console.log("1" + 2 + 3); // "123" → soldan sağa: "1"+2="12", sonra "12"+3="123"

6. Unutqanlıqla qlobal dəyişən yaratmaq

bug-6.js
function hesabla() {
  netice = 100; // ❌ var/let/const yazılmayıb → qeyri-strict modda avtomatik qlobal dəyişən yaranır
}
hesabla();
console.log(netice); // 100 — funksiya xaricindən görünür, bu təhlükəlidir!

// Həll: faylın/funksiyanın əvvəlinə "use strict" əlavə edin
"use strict";
function hesabla2() {
  netice2 = 100; // artıq ReferenceError verəcək
}

7. var ilə for dövründə closure problemi

Bu, JavaScript-in ən klassik "gotcha"-larından biridir:

bug-7.js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log("var:", i), 100);
}
// Nəticə: var: 3  var: 3  var: 3   (gözlənilməz!)

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log("let:", j), 100);
}
// Nəticə: let: 0  let: 1  let: 2   (gözlənilən nəticə)
Səbəb:var bir dəfə yaranır və dövr bitəndə 3 olur; let hər iterasiyada yeni block-scope yaradır.

8. Dəyişən adının böyük/kiçik hərfə həssaslığı

bug-8.js
let İstifadeci = "Elvin";
console.log(istifadeci); // ❌ ReferenceError: istifadeci is not defined
console.log(İstifadeci);  // ✅ "Elvin"

9. Floating-point (ondalık) dəqiqlik problemi

bug-9.js
console.log(0.1 + 0.2);          // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3);  // false 😱

// Düzəliş: kiçik "epsilon" fərqi ilə müqayisə et
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON); // true

10. Array-i typeof ilə yoxlamaq

bug-10.js
let siyahi = [1, 2, 3];
console.log(typeof siyahi); // "object" ❌ gözlədiyimiz kimi deyil
console.log(Array.isArray(siyahi)); // true ✅ doğru üsul budur
🐞 Bonus: reference tiplərin müqayisəsi

{ a: 1 } === { a: 1 } nəticəsi false-dur, çünki iki obyekt fərqli yaddaş ünvanlarında yaradılıb — məzmun eyni olsa belə referenslər fərqlidir. Obyektləri məzmunca müqayisə etmək üçün JSON.stringify() və ya dərin müqayisə funksiyalarından istifadə olunur.

06 Tövsiyələr

Ən yaxşı təcrübələr (Best Practices)

📦 Dəyişən elanı

  • Default olaraq həmişə const istifadə et.
  • Dəyər dəyişəcəksə let işlət.
  • var-dan tamamilə uzaq dur.
  • Bir sətirdə bir dəyişən elan et — oxunaqlılıq üçün.

🏷️ Adlandırma

  • camelCase istifadə et: istifadeciAdi.
  • Adlar mənalı olsun: x yox, toplamMebleg.
  • Boolean dəyişənlərə is/has prefiksi ver: isAktiv.
  • Sabitlər üçün UPPER_SNAKE_CASE ola bilər: MAX_LIMIT.

⚖️ Müqayisə və tip

  • Həmişə === / !== istifadə et.
  • null yoxlamaq üçün birbaşa === null yaz.
  • Array üçün Array.isArray(), typeof yox.
  • NaN yoxlamaq üçün Number.isNaN().

🖥️ Console istifadəsi

  • Debug üçün console.log, amma production kodundan təmizlə.
  • Xətalar üçün console.error, xəbərdarlıq üçün console.warn.
  • Çoxlu dəyəri etiketlə göstər: console.log("say:", say).
  • Böyük data üçün console.table() istifadə et.

🧵 String-lər

  • Birləşdirmə üçün + yerine template literal işlət: `Salam, ${ad}`.
  • Number/String qarışığından ehtiyatlı ol.

🛡️ Ümumi təhlükəsizlik

  • Faylın/modulun əvvəlinə "use strict" əlavə et (ES modullarda avtomatikdir).
  • ESLint/Prettier kimi alətlərlə kodu avtomatik yoxlat.
  • Dəyişəni istifadə etməzdən əvvəl elan et — hoisting-ə güvənmə.
