01 · Nəzəriyyə

HTTP nədir?

HTTP (HyperText Transfer Protocol) — brauzerlə server arasında məlumat mübadiləsini idarə edən "danışıq qaydaları"dır. Sən saytı açanda brauzer serverə bir sorğu (request) göndərir, server isə buna bir cavab (response) qaytarır. Fetch API dediyimiz şey də məhz bu mübadiləni JavaScript kodundan idarə etməyə yarayan alətdir.

Client–server modeli

Bu münasibətdə iki tərəf var: client (adətən brauzer — sorğunu göndərən tərəf) və server (sorğunu qəbul edib cavab hazırlayan tərəf). Server, adətən, stateless işləyir — yəni əvvəlki sorğunu "xatırlamır", hər sorğu öz-özlüyündə tam məlumat daşımalıdır.

URL-in anatomiyası

URL strukturu
https://api.sayt.az:443/users?id=5&aktiv=true
   │           │            │      │              │
 sxem        host         port   path      query parametrləri
  • Sxem (scheme) — hansı protokol istifadə olunur (http/https).
  • Host — serverin ünvanı (domen və ya IP).
  • Path — server daxilində hansı resursa müraciət olunur.
  • Query parametrləri — əlavə, könüllü parametrlər (filtr, axtarış, səhifələmə və s.).

Sorğu və cavabın quruluşu

Hər HTTP sorğusu üç hissədən ibarətdir: metod + URL, headers (başlıqlar) və (bəzən) body (məlumat gövdəsi). Cavab da eyni şəkildə: status kodu, headers və body. Aşağıdakı bölmələrdə bunların hər birini ayrı-ayrı araşdıracağıq.

02 · Nəzəriyyə

HTTP metodları

Hər sorğu nə etmək istədiyini bir metod vasitəsilə bildirir. Bu, verilənlər bazasındakı CRUD əməliyyatlarına birbaşa uyğun gəlir:

GET

Məlumat almaq üçün. Body daşımır. "Təhlükəsiz" sayılır — server üzərində heç nəyi dəyişmir.

Read
POST

Yeni məlumat yaratmaq üçün. Body ilə göndərilir (məs. yeni istifadəçi).

Create
PUT

Mövcud məlumatı tam əvəz etmək üçün. Bütün sahələr yenidən göndərilir.

Update (full)
PATCH

Mövcud məlumatın yalnız bir hissəsini yeniləmək üçün.

Update (partial)
DELETE

Məlumatı silmək üçün. Adətən body tələb olunmur.

Delete
💡 Yadda saxla
GET və DELETE adətən body daşımır (bəzi server konfiqurasiyaları qəbul etməyə bilər). Yeni məlumat göndərəndə (POST/PUT/PATCH) demək olar həmişə body və Content-Type header-i lazım olur.
03 · Nəzəriyyə

HTTP status kodları

Server cavab verəndə, sorğunun necə keçdiyini 3 rəqəmli bir kodla bildirir. Bu kodları tanımaq debugging zamanı vaxtına qat-qat qənaət etdirir.

KodMənaQısa izah
200OKSorğu uğurla yerinə yetirildi.
201CreatedYeni məlumat uğurla yaradıldı (adətən POST-dan sonra).
204No ContentUğurludur, amma body qaytarılmır (adətən DELETE-dən sonra).
301Moved PermanentlyResurs başqa URL-ə köçürülüb.
304Not ModifiedMəlumat dəyişməyib, keşdəkini istifadə et.
400Bad RequestGöndərilən məlumat düzgün formatda deyil.
401UnauthorizedGiriş tələb olunur — token yoxdur / yanlışdır.
403ForbiddenSən tanınırsan, amma bu əməliyyata icazən yoxdur.
404Not FoundSorğulanan resurs mövcud deyil.
429Too Many RequestsÇox tez-tez sorğu göndərilib, limitə düşmüsən.
500Internal Server ErrorServer tərəfində gözlənilməz xəta baş verdi.
502 / 503Bad Gateway / UnavailableServer müvəqqəti əlçatan deyil və ya həddən artıq yüklənib.
⚠️ Kritik nüans
response.ok yalnız status kodu 200–299 aralığında olduqda true olur. 404 və 500 kimi kodlar fetch-i uğursuz etmir — bunu 10-cu bölmədə ətraflı izah edəcəyik, çünki bu, ən çox rast gəlinən "gizli bug" mənbəyidir.
04 · Nəzəriyyə

Headers (başlıqlar)

Headers, sorğu və cavaba əlavə olunan "metadata"dır — məlumatın özü deyil, məlumat haqqında məlumatdır.

  • Content-Type — göndərilən body-nin formatını bildirir (məs. application/json).
  • Accept — client-in hansı formatda cavab gözlədiyini bildirir.
  • Authorization — giriş üçün token daşıyır (məs. Bearer eyJhbGciOi...).
headers nümunəsi
const headers = {
  "Content-Type": "application/json",
  "Authorization": "Bearer " + token
};
05 · Fetch API

Fetch API sintaksisi

fetch() brauzerə daxil olan, sorğu göndərmək üçün istifadə etdiyimiz funksiyadır. Nəticəsi bir Promise olur — yəni cavab dərhal deyil, "gələcəkdə" gəlir.

əsas sintaksis
fetch(url, options)
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error(error));
❌ Ən çox yayılmış anlaşılmazlıq
fetch()-in nəticəsi birbaşa data deyil — bir Response obyektidir. Faktiki datanı almaq üçün əlavə olaraq .json() (və ya .text()) çağırmaq lazımdır — o da öz növbəsində asinxrondur və Promise qaytarır. Bu, iki mərhələli asinxron zəncirdir, birmərhələli deyil.
06 · Fetch API

GET sorğusu

GET ən sadə haldır — sadəcə URL-i verirsən, heç bir əlavə parametr tələb olunmur (varsayılan metod məhz GET-dir).

GET nümunəsi — real API
fetch("https://jsonplaceholder.typicode.com/users/1")
  .then(res => res.json())
  .then(user => {
    console.log(user.name);   // "Leanne Graham"
  });

Aşağıda 11-ci bölmədə eyni sorğunu canlı şəkildə işə salıb, real cavabı görəcəyik.

07 · Fetch API

POST sorğusu

POST-da options obyekti daxilində metod, headers və body göstərməliyik. Body mütləq mətn (string) formatında olmalıdır — buna görə JS obyektini JSON.stringify() ilə çeviririk.

POST nümunəsi
fetch("https://jsonplaceholder.typicode.com/posts", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    title: "Salam",
    body: "Test paylaşım",
    userId: 1
  })
})
  .then(res => res.json())
  .then(data => console.log(data));
08 · Fetch API

JSON necə işlənir?

JSON (JavaScript Object Notation) — şəbəkə üzərindən məlumat daşımaq üçün istifadə olunan mətn formatıdır. JS obyekti şəbəkəyə çılpaq halda göndərilə bilməz, əvvəlcə mətnə çevrilməlidir.

JSON.stringify(obj)

JS obyektini JSON mətninə çevirir. Server-ə göndərəndə istifadə olunur.

JSON.parse(str)

JSON mətnini JS obyektinə çevirir. Serverdən mətn gələndə istifadə olunur.

response.json() əslində arxa planda JSON.parse()-i sənin əvəzinə çağırır — sadəcə həm də stream-i oxuyur, ona görə asinxrondur.

gediş-gəliş dövrü
JS obyekti  --stringify-->  JSON mətni  --şəbəkə-->  JSON mətni  --parse / .json()-->  JS obyekti
09 · Fetch API

Async / await ilə fetch

.then() zəncirləri uzunlaşdıqca oxunması çətinləşir. async/await eyni məntiqi, sinxron kod kimi görünən formada yazmağa imkan verir.

async/await nümunəsi
async function getUser() {
  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/users/1");
    const user = await response.json();
    console.log(user);
  } catch (error) {
    console.error("Xəta:", error);
  }
}

Diqqət et: iki dəfə await istifadə olunur — biri fetch() üçün, biri də .json() üçün. İkisi də ayrı-ayrı Promise-lərdir.

10 · Fetch API

Xətaların idarə olunması

Bu, Fetch API-nin ən çox insanları çaşdıran xüsusiyyətidir:

🐞 Ən vacib "gizli tələ"
fetch() yalnız şəbəkə səviyyəsində uğursuzluqda (internet yoxdur, DNS tapılmadı, CORS bloklandı) rədd olunur (catch-ə düşür). 404, 401, 500 kimi HTTP status kodları "xəta" sayılmır — fetch onları normal, "uğurlu" cavab kimi görür! Yəni response.ok-u özün yoxlamasan, tətbiqin server "üzr istəyəndə" belə sanki hər şey qaydasındaymış kimi davam edə bilər.
düzgün yanaşma
try {
  const response = await fetch(url);

  if (!response.ok) {
    throw new Error(`HTTP xətası: ${response.status}`);
  }

  const data = await response.json();
  return data;
} catch (error) {
  console.error("Sorğu uğursuz oldu:", error.message);
}

12 · Təcrübə

Ən çox buraxılan səhvlər

Aşağıdakılar yeni başlayanların (bəzən təcrübəlilərin də) ən çox rast gəldiyi problemlərdir — hər birinin yanında səhv və düzgün variantı var.

01

response.json()-un asinxron olduğunu unutmaq

await yalnız fetch()-ə yazılır, .json()-a yazılmır — nəticədə data dəyişəni real obyekt yox, həll olunmamış bir Promise olur.

❌ Səhv
const data = response.json();
console.log(data.name); // undefined
✅ Düzgün
const data = await response.json();
console.log(data.name);
02

response.ok yoxlanılmaması

404/500 kimi cavablar sükutla "uğurlu" kimi işlənir, istifadəçi niyə səhifənin boş qaldığını anlamır.

❌ Səhv
const res = await fetch(url);
const data = await res.json();
// 404 olsa belə buraya çatır
✅ Düzgün
const res = await fetch(url);
if (!res.ok) throw new Error(res.status);
const data = await res.json();
03

POST-da Content-Type başlığının unudulması

Server, body-nin hansı formatda olduğunu bilmir və məlumatı düzgün oxuya bilmir (JSON kimi deyil, sadə mətn kimi qəbul edə bilər).

❌ Səhv
fetch(url, {
  method: "POST",
  body: JSON.stringify(data)
  // headers yoxdur
});
✅ Düzgün
fetch(url, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(data)
});
04

body-ni JSON.stringify etmədən göndərmək

Fetch, body kimi JS obyektini birbaşa qəbul etmir — nəticədə server tərəfə "[object Object]" kimi mənasız bir mətn gedir.

❌ Səhv
body: { title: "Salam" }
// server "[object Object]" alır
✅ Düzgün
body: JSON.stringify({ title: "Salam" })
05

Fetch-ə timeout təyin etməmək

Fetch-in daxili timeout mexanizmi yoxdur — server cavab verməsə, sorğu sonsuza qədər asılı qala bilər. Bunu AbortController ilə həll edirik.

❌ Nəzarətsiz
const res = await fetch(url);
// server 30 saniyə cavab verməsə,
// istifadəçi hələ də gözləyir
✅ Timeout ilə
const controller = new AbortController();
setTimeout(() => controller.abort(), 5000);
const res = await fetch(url, { signal: controller.signal });
06

CORS xətasını "backend xarab işləyir" zənn etmək

Konsolda "has been blocked by CORS policy" yazısı görəndə bu, server-in kodunda "bug" olduğu anlamına gəlmir — bu, brauzerin təhlükəsizlik qaydasıdır. Server Access-Control-Allow-Origin başlığı ilə hansı domenlərə icazə verdiyini bildirməlidir. Frontend tərəfdən bunu "düzəltmək" mümkün deyil — dəyişiklik backend tərəfində edilməlidir (və ya inkişaf zamanı proxy istifadə olunur).

07

Axtarış input-unda "yarış vəziyyəti" (race condition)

İstifadəçi hər hərf yazanda yeni sorğu göndərilirsə, şəbəkə gecikməsinə görə köhnə sorğunun cavabı yeni sorğunun cavabından sonra gəlib ekranı səhv nəticə ilə əvəz edə bilər. Həll: hər yeni sorğu göndərməzdən əvvəl AbortController ilə əvvəlkini ləğv et, və ya "debounce" tətbiq et.

13 · Təcrübə

Nüanslar və diqqət ediləsi məqamlar

CORS (Cross-Origin Resource Sharing)

Brauzer, təhlükəsizlik məqsədilə fərqli domenə gedən sorğuları default olaraq məhdudlaşdırır. Server icazə vermədikcə (uyğun header-lərlə), brauzer cavabı JavaScript-ə çatdırmır — hətta server düzgün cavab versə belə.

Cookie və credentials

Fetch, default olaraq cookie göndərmir. Sessiya/cookie-əsaslı autentifikasiya lazımdırsa, aşkar şəkildə bildirmək lazımdır:

fetch(url, { credentials: "include" })

Keşləmə (caching)

GET sorğuları brauzer tərəfindən keşlənə bilər. Həmişə təzə məlumat lazımdırsa: cache: "no-store" təyin edilə bilər.

Fetch vs Axios

fetch brauzerə daxili gəlir, əlavə paket tələb etmir. axios isə ayrıca kitabxanadır və bir sıra rahatlıqlar təqdim edir: avtomatik JSON çevrilməsi, daha rahat xəta idarəetməsi (HTTP xətalarında avtomatik reject), daxili timeout dəstəyi və request/response "interceptor"ları. Kiçik layihələrdə fetch kifayətdir, böyük layihələrdə axios vaxta qənaət etdirə bilər.

Böyük cavablar / streaming

Çox böyük fayllarla işləyəndə response.body bir ReadableStream-dir — bütün faylın yüklənməsini gözləmədən parça-parça oxumaq mümkündür. Adi məlumat mübadiləsi üçün bu, adətən lazım olmur, amma bilmək faydalıdır.

14 · Təcrübə

Yaxşı təcrübələr

  • Hər zaman response.ok-u yoxla, yalnız onda .json()-a keç.
  • Oxunaqlılıq üçün .then() zəncirləri yerinə async/await üstünlük ver.
  • Fetch məntiqini təkrarlamaq yerinə bir helper funksiyada mərkəzləşdir (məs. apiClient.js).
  • UI-da loading, error və success vəziyyətlərini ayrıca idarə et — istifadəçi nə baş verdiyini bilməlidir.
  • Uzunmüddətli və ya lazımsız olmuş sorğuları AbortController ilə ləğv et.
  • Serverdən gələn məlumata kor-koranə güvənmə — lazım olan sahələrin mövcudluğunu yoxla.
  • Token kimi həssas məlumatları URL-də yox, header-də göndər.
  • Sorğu URL-lərini əl ilə birləşdirmək yerinə URLSearchParams istifadə et.
mərkəzləşdirilmiş helper nümunəsi
async function apiRequest(url, options = {}) {
  const res = await fetch(url, options);
  if (!res.ok) {
    throw new Error(`Sorğu uğursuz oldu: ${res.status}`);
  }
  return res.json();
}

// istifadəsi:
const user = await apiRequest("/api/users/1");

16 · Xülasə

Xülasə / Cheat sheet

Bu dərsin ən vacib nöqtələrini bir yerdə topladıq — sürətli xatırlatma üçün buraya qayıda bilərsən.

ƏSAS SİNTAKSİS

  • fetch(url) → Promise<Response>
  • response.json() → Promise<data>
  • İkisi də await tələb edir

HƏMİŞƏ YOXLA

  • response.ok (200–299)
  • Şəbəkə xətaları üçün try/catch
  • POST-da Content-Type header-i

UNUTMA

  • Body → JSON.stringify() ilə mətnə çevir
  • 404/500 fetch-i "sındırmır"
  • CORS — brauzer qaydasıdır, backend həll edir

DAHA YAXŞISI ÜÇÜN

  • Fetch məntiqini bir yerdə topla
  • Uzun sorğular üçün AbortController
  • Loading / error state-lərini UI-da göstər
