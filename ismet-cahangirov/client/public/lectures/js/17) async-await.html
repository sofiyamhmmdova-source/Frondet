Async / Await

JavaScript-də asinxron əməliyyatları sinxron kod kimi oxunaqlı yazmağın yolu — async function, await açar sözü və try/catch ilə xəta idarəetməsi bir yerdə.

🕒 ~20 dəqiqə oxuma 📊 Səviyyə: Orta 📎 Tələb olunur: Promise əsasları, funksiyalar
Sinxron — hər sorğu növbəsini gözləyir ≈3x vaxt
Sorğu 1 bitmədən Sorğu 2 başlamır, o bitmədən Sorğu 3 başlamır.
Async/Await + Promise.all — sorğular paralel gedir ≈1x vaxt
Bir-birindən asılı olmayan sorğular eyni anda göndərilir.
// 01 — Giriş

Niyə Async/Await?

JavaScript tək-axınlı (single-threaded) dildir — eyni anda yalnız bir iş görə bilər. Amma şəbəkə sorğusu, fayl oxumaq və ya taymer kimi əməliyyatlar vaxt aparır. Əgər JavaScript bunları gözləmək üçün dayansaydı, bütün səhifə "donardı". Bunun həlli asinxronluqdur — nəticəni gözləyərkən proqramın qalan hissəsi işləməyə davam edir.

Bu problemi həll etmək üçün JavaScript tarixində üç mərhələ olub:

1) Callback-lər (ilk üsul)

callback-hell.js
girisAl(function (istifadeci) {
  postlariGetir(istifadeci.id, function (postlar) {
    serhleriGetir(postlar[0].id, function (serhler) {
      console.log(serhler); // 3 səviyyəli "piramida"
    });
  });
});
"Callback Hell" — hər addım əvvəlkinin içinə yerləşir, kod sağa doğru sürünür və oxumaq çətinləşir.

2) Promise-lər (daha aydın)

promise-chain.js
girisAl()
  .then((istifadeci) => postlariGetir(istifadeci.id))
  .then((postlar) => serhleriGetir(postlar[0].id))
  .then((serhler) => console.log(serhler))
  .catch((xeta) => console.error(xeta));
Piramida düzəlir, amma uzun zəncirlərdə hələ də izləmək çətindir.

3) Async/Await (bugünkü mövzu)

async-await.js
async function melumatlariGoster() {
  try {
    const istifadeci = await girisAl();
    const postlar = await postlariGetir(istifadeci.id);
    const serhler = await serhleriGetir(postlar[0].id);
    console.log(serhler);
  } catch (xeta) {
    console.error(xeta);
  }
}
Eyni məntiq, amma yuxarıdan-aşağı, sinxron kod kimi oxunur.
💡 Vacib məqam

Async/await Promise-i əvəz etmir — onun üzərində qurulmuş "şəkərli sintaksisdir" (syntactic sugar). Kapotun altında hər şey yenə Promise-dir, sadəcə yazılış forması dəyişir.

🍽️

Analoji: Restoranda sifariş

Sinxron: ofisiantı çağırıb sifariş verirsən və mətbəxin qapısında dayanıb yeməyin bişməsini gözləyirsən — bu müddətdə başqa heç nə edə bilmirsən.

Async/Await: sifarişi verirsən, masana qayıdıb dostlarınla söhbət edirsən; yemək hazır olanda ofisiant onu masana gətirir. await elə "sifariş nişanını gözləmək" kimidir — funksiyanın o hissəsi dayanır, amma bütün restoran (proqram) işləməyə davam edir.

// 02 — Necə İşləyir

Sintaksisin Anatomiyası

İki açar söz kifayətdir: async funksiyanı işarələyir, await isə onun daxilində Promise-in nəticəsini gözləyir.

anatomiya.js
async function mesajGetir() {
  const cavab = await fetch('https://api.numune.az/mesaj');
  const data = await cavab.json();
  return data;
}

// Arrow funksiya forması:
const mesajGetir2 = async () => {
  const cavab = await fetch('https://api.numune.az/mesaj');
  return cavab.json();
};

// Class metodu forması:
class ApiXidmeti {
  async mesajGetir() {
    const cavab = await fetch('/mesaj');
    return cavab.json();
  }
}
  • 01async funksiyası həmişə Promise qaytarır — hətta içində return 5 yazsan belə, çağıran tərəf Promise<5> alacaq.
  • 02await yalnız async funksiyanın daxilində işləyir. İstisna: ES modullarda (type="module") faylın ən yuxarı səviyyəsində "top-level await" istifadə oluna bilər.
  • 03await yalnız cari funksiyanı dayandırır, bütün proqramı yox — Event Loop paralel olaraq başqa kodu icra etməyə davam edir.
  • 04await-dən sonra gələn sətirlər yalnız o Promise "resolve" (və ya "reject") olduqdan sonra işə düşür.
// 03 — Xəta İdarəetməsi

Try / Catch ilə Birlikdə

Promise zəncirində xətanı .catch() tutur. Async/await-də isə klassik try/catch/finally blokundan istifadə olunur — sinxron koddakı kimi tanış və rahat.

istifadeci-getir.js
async function istifadeciGetir(id) {
  try {
    const cavab = await fetch(`/api/istifadeci/${id}`);

    if (!cavab.ok) {
      throw new Error(`Server xetasi: ${cavab.status}`);
    }

    const data = await cavab.json();
    return data;

  } catch (xeta) {
    console.error('Istifadeci getirile bilmedi:', xeta.message);
    throw xeta; // yuxari qat bilsin deye yenidən at!

  } finally {
    console.log('Sorgu tamamlandi (ugurlu ve ya ugursuz farq etmir)');
  }
}
⚠️ Ən çox rastlanan tələ

fetch() yalnız şəbəkə xətasında (internet yoxdur, DNS tapılmadı və s.) "reject" olur. 404 Not Found və ya 500 Server Error kimi HTTP status kodları xəta SAYILMIR — sorğu "uğurla" tamamlanmış sayılır! Ona görə həmişə cavab.ok (və ya cavab.status) əl ilə yoxlanmalı və lazım gələrsə özün throw etməlisən.

✅ finally həmişə işləyir

finally bloku nəticədən asılı olmayaraq — istər uğurlu, istər xəta ilə bitsin — mütləq icra olunur. Bu, "loading" göstəricisini söndürmək və ya resurs təmizləmək üçün ideal yerdir.

// 04 — Real Nümunələr

Ardıcıl və Paralel Sorğular

Bu, async/await öyrənərkən ən çox qarışdırılan hissədir: hər await avtomatik olaraq öncəkini gözləyir — bu, çox vaxt lazım deyil və performansı öldürür.

Ardıcıl (Sequential) — yalnız asılılıq olanda

ardicil.js
// postlar getirmek ucun once istifadeciAId lazimdir -> ardicil olmalidir
const istifadeci = await istifadeciGetir(1);
const postlar = await postlariGetir(istifadeci.id);

Paralel (Promise.all) — asılı olmayanda

paralel.js
// YAVAS: hər sorğu 1san cəksə, cəmi ~3 saniyə
const istifadeci = await istifadeciGetir();
const parametrler = await parametrleriGetir();
const bildirisler = await bildirisleriGetir();

// SUREETLI: sorğular eyni anda gedir, cəmi ~1 saniyə
const [istifadeci2, parametrler2, bildirisler2] = await Promise.all([
  istifadeciGetir(),
  parametrleriGetir(),
  bildirisleriGetir(),
]);

Dövrələrdə (loop) await

for-of.js
// for...of ile await GOZLEYIR - hər elementi bir-bir, ardıcıl işləyir
for (const id of idSiyahisi) {
  const netice = await elementiProsesEt(id);
  console.log(netice);
}
Diqqət: .forEach() ilə await gözlənildiyi kimi işləmir — bunu növbəti bölmədə görəcəyik.
// 05 — Ən Çox Edilən Səhvlər

Tez-tez Rastlanan Bug-lar

Aşağıdakı 7 səhv, async/await öyrənən demək olar hər kəsin başına gəlir. Hər birinin ❌ səhv və ✅ düzgün versiyasına baxaq.

BUG 01

forEach() içində await işləmir

❌ Səhv 
items.forEach(async (item) => {
  await prosesEt(item);
});
console.log('Hamisi bitdi'); // YALAN!
✅ Düzgün 
for (const item of items) {
  await prosesEt(item);
}
console.log('Hamisi bitdi'); // Indi dogru
Səbəb: forEach callback-in qaytardığı Promise-ə heç vaxt baxmır və gözləmir. Bütün callback-lər dərhal "atılır", console.log onlardan əvvəl işə düşür. Paralel işləmək istəyirsənsə Promise.all(items.map(...)) istifadə et.
BUG 02

await-i unutmaq

❌ Səhv 
async function melumatGetir() {
  const data = fetch('/api/data');
  console.log(data);
  // Promise { <pending> } çıxacaq
}
✅ Düzgün 
async function melumatGetir() {
  const data = await fetch('/api/data');
  console.log(data); // Response obyekti
}
Səbəb: await olmadan dəyişən Promise-in özünü saxlayır, "içindəki" nəticəni yox. Redaktorda avtomatik xəbərdarlıq üçün ESLint-in require-await qaydasını aktiv et.
BUG 03

.map(async) massiv əvəzinə Promise massivi qaytarır

❌ Səhv 
const neticeler = items.map(
  async (item) => await prosesEt(item)
);
console.log(neticeler);
// [Promise, Promise, Promise]
✅ Düzgün 
const neticeler = await Promise.all(
  items.map((item) => prosesEt(item))
);
console.log(neticeler); // [deyer1, deyer2, ...]
Səbəb: async funksiya həmişə Promise qaytarır, map isə bunu avtomatik "açmır". Nəticələri istəyirsənsə mütləq Promise.all ilə "bağla".
BUG 04

Lazımsız ardıcıl await-lər (performans itkisi)

❌ Yavaş 
const user = await getUser();
const posts = await getPosts();
// getUser bitmesini gozlemeye ehtiyac yoxdur!
✅ Sürətli 
const [user, posts] = await Promise.all([
  getUser(),
  getPosts(),
]);
Səbəb: Əgər iki sorğu bir-birindən asılı deyilsə, onları ardıcıl await etmək saf vaxt itkisidir. Asılılığı olmayan bütün sorğuları həmişə paralelləşdir.
BUG 05

Boş catch bloku — xətanı "udmaq"

❌ Səhv 
try {
  await riskliEmeliyyat();
} catch (e) {
  // hec ne - xeta itdi!
}
✅ Düzgün 
try {
  await riskliEmeliyyat();
} catch (e) {
  console.error('Emeliyyat ugursuz:', e);
  // lazimdirsa: bildiris gonder, yenidən at və s.
}
Səbəb: Boş catch xətanı "səssizcə udur" — proqram normal işləyirmiş kimi davam edir, amma daxildə problem var və heç kim bundan xəbərsiz qalır. Ən azı console.error ilə logla.
BUG 06

Nəticəni gözləmədən istifadə etmək ("fire and forget")

❌ Səhv 
function render() {
  let data;
  getData().then((d) => (data = d));
  console.log(data); // undefined - helə gelmeyib
}
✅ Düzgün 
async function render() {
  const data = await getData();
  console.log(data); // deyer artiq hazirdir
}
Səbəb: .then() callback-i gələcəkdə, asinxron şəkildə işə düşür. console.log(data) isə dərhal, callback işə düşməzdən əvvəl icra olunur.
BUG 07

async funksiyanı try/catch olmadan çağırmaq

❌ Səhv 
async function melumatiYukle() {
  const data = await tehlukeliSorgu();
  isle(data);
}
melumatiYukle(); // catch yoxdur!
✅ Düzgün 
async function melumatiYukle() {
  try {
    const data = await tehlukeliSorgu();
    isle(data);
  } catch (e) {
    console.error(e);
  }
}
melumatiYukle();
Səbəb: Əgər funksiya reject olunsa və heç kim tutmasa, "Unhandled Promise Rejection" xətası yaranır — brauzerdə console-a düşür, Node.js-də isə tətbiqi çökdürə bilər.

Runtime Xəta Mesajları — nə deməkdir?

Xəta mesajıSəbəbNecə düzəldilir
await is only valid in async functions await, async olmayan funksiyada istifadə edilib Funksiyanın əvvəlinə async əlavə et

// 06 — Dərin Detallar

Nüanslar: Event Loop necə işləyir?

Bu, async/await-in ən çətin, amma ən vacib hissəsidir: kodun icra ardıcıllığı. Aşağıdakı nümunəni addım-addım izləyək.

tapmaca.js
console.log('1');

setTimeout(() => console.log('2'), 0);

Promise.resolve().then(() => console.log('3'));

(async () => {
  console.log('4');
  await null;
  console.log('5');
})();

console.log('6');
Sual: bu kod hansı ardıcıllıqla console-a nə çap edəcək? Aşağıdakı simulyatorda addım-addım gör 👇

🔑 Qızıl qayda

Hər dövrədə əvvəlcə bütün sinxron kod icra olunur → sonra Microtask Queue tam boşaldılır (Promise-lər, await davamı) → yalnız bundan sonra bir Macrotask (setTimeout, setInterval) götürülür. Buna görə yuxarıdakı nümunənin nəticəsi 1, 4, 6, 3, 5, 2 olur — setTimeout(…, 0) olsa belə ən sonda işə düşür!

Digər vacib nüanslar

Promise.all — "hamısı və ya heçnə"

Massivdəki Promise-lərdən biri belə reject olsa, Promise.all dərhal reject olur, digərlərinin nəticəsini gözləmir. Hamısının nəticəsini (uğurlu/uğursuz fərq etmədən) görmək istəyirsənsə Promise.allSettled istifadə et.

Promise.race və Promise.any

Promise.race ilk bitən Promise-i (uğurlu və ya xəta) qaytarır — məsələn "timeout" məntiqi üçün əladır. Promise.any isə ilk uğurlu nəticəni gözləyir, hamısı rədd olunmasa xəta vermir.

await adi dəyər üzərində

await 5 yazmaq da mümkündür — Promise olmayan dəyər avtomatik "resolve edilmiş Promise" kimi işlənir və dərhal (bir microtask sonra) davam edir. Xəta vermir, sadəcə lazımsızdır.

Top-level await

ES modullarında (<script type="module">) await-i funksiyanın xaricində, faylın ən üst səviyyəsində birbaşa istifadə etmək mümkündür — məsələn konfiqurasiya yükləmək üçün.

// 07 — Best Practices

Tövsiyələr

  • ✅ Şəbəkə sorğusu edən hər async funksiyada həmişə try/catch istifadə et.
  • ✅ Bir-birindən asılı olmayan sorğuları Promise.all ilə paralelləşdir.
  • ✅ Dövrədə await lazımdırsa for...of istifadə et, forEach yox.
  • ✅ Boş catch bloku saxlama — xətanı ən azı logla, ideal halda istifadəçiyə də bildir.
  • ✅ fetch istifadə edərkən response.ok yoxla — HTTP xətaları avtomatik reject olmur.
  • ✅ ESLint-də no-floating-promises və require-await qaydalarını aktivləşdir — səhvləri kod yazan kimi tapar.
  • ✅ Uzun sürən əməliyyatlarda istifadəçiyə loading vəziyyəti göstər (UI/UX üçün vacibdir).
  • ✅ Uzun sorğular üçün AbortController ilə timeout məntiqi əlavə et.
// 08 — Özünü Yoxla

Sürətli Test

Hər kod parçasında bir bug var. Tapa bilərsənmi? Cavabı görmək üçün üstünə klik et.

S1. Bu funksiyada nə səhvdir?▾ 
async function get() {
  const res = fetch('/data');
  return res.json();
}
Cavab: fetch('/data')-dan əvvəl await yoxdur. res əslində Response yox, Promise-dir, ona görə res.json() xəta verəcək. Düzəliş: const res = await fetch('/data');
S2. Bu kodun çıxışı nə olacaq?▾ 
[1, 2, 3].forEach(async (n) => {
  await gecikdir(100);
  console.log(n);
});
console.log('bitdi');
Cavab: 'bitdi' ƏVVƏLCƏ çap olunacaq, sonra 1, 2, 3 (təxminən eyni vaxtda). Səbəb: forEach callback-lərin Promise-ini gözləmir, dərhal keçib gedir.
S3. Bu funksiya niyə "yalan" nəticə verə bilər?▾ 
async function save(data) {
  try {
    await db.save(data);
  } catch (e) {
  }
  return true;
}
Cavab: catch bloku boşdur — db.save uğursuz olsa belə, funksiya heç bir xəta atmadan true qaytarır. Çağıran tərəf yazının uğursuz olduğunu heç vaxt bilməyəcək. Düzəliş: xətanı logla və/və ya yenidən at, ya da false qaytar.
// 09 — Tez İstinad

Cheat Sheet

cheatsheet.js
// --- Elan etmək ---
async function f() {}
const g = async () => {};
class C { async metod() {} }

// --- Xəta idarəetməsi ---
try {
  const data = await sorgu();
} catch (xeta) {
  console.error(xeta);
} finally {
  temizle();
}

// --- Ardıcıl (asılılıq varsa) ---
const a = await birinci();
const b = await ikinci(a);

// --- Paralel (asılılıq yoxdursa) ---
const [a2, b2] = await Promise.all([birinci(), ikinci()]);

// --- Hamısını gözlə, xəta olsa belə davam et ---
const neticeler = await Promise.allSettled([birinci(), ikinci()]);

// --- İlk bitəni götür ---
const ilk = await Promise.race([sorgu(), timeout(3000)]);

// --- Dövrədə ardıcıl gözləmə ---
for (const item of siyahi) {
  await prosesEt(item);
}

// --- Dövrədə paralel gözləmə ---
await Promise.all(siyahi.map((item) => prosesEt(item)));
