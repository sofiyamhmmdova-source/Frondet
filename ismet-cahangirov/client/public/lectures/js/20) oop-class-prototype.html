01

    
Niyə "class" deyirik, halbuki JS class-based dil deyil?

    

      
JavaScript əslində prototip əsaslı (prototype-based) dildir. Java, C# kimi dillərdən fərqli olaraq, burada obyektlər "sinifdən" yox, birbaşa başqa obyektlərdən miras alır. 2015-ci ildə (ES6) gələn class sintaksisi yeni bir mexanizm gətirmədi — mövcud prototip sistemini daha tanış və oxunaqlı formada yazmaq imkanı verdi. Ona görə tez-tez "sintaktik şəkər" (syntactic sugar) adlandırılır.

      

        
⚠

        
Bunu bilmək vacibdir, çünki class yazanda arxa planda əslində funksiya və prototip yaranır. Bir çox "qəribə" davranışın (məsələn this-in itməsi) səbəbini yalnız bu real mexanizmi anlayaraq başa düşmək mümkündür.

      

      
Aşağıda eyni şeyin iki yazılışını gör — class ilə və onun arxasında əslində nə baş verdiyini göstərən "köhnə üsul" ilə:

    


    

      

        
        
      

      
JavaScript

      

        
class Insan {
  constructor(ad) {
    this.ad = ad;
  }
  salamla() {
    return `Salam, mən ${this.ad}`;
  }
}

      

      

        
function Insan(ad) {
  this.ad = ad;
}
Insan.prototype.salamla = function() {
  return `Salam, mən ${this.ad}`;
};
// class yazanda JS mühərriki daxildə məhz bunu edir

      

    

  


  
  

    
02

    
constructor — obyekt yaranan an

    

      
constructor — new açar sözü ilə yeni instansiya (instance) yaradılan zaman avtomatik işə düşən xüsusi metoddur. Vəzifəsi obyektin ilkin vəziyyətini qurmaqdır.

    


    

      
JavaScript

      
class Insan {
  constructor(ad, yas) {
    this.ad = ad;
    this.yas = yas;
  }
  salamla() {
    return `Salam, mən ${this.ad}, ${this.yas} yaşındayam`;
  }
}

const ali = new Insan('Əli', 25);
ali.salamla(); // "Salam, mən Əli, 25 yaşındayam"

    


    
"new" açar sözü çağırılanda arxada tam olaraq 4 addım baş verir:

    

      
    
        
  1. Yeni, boş bir obyekt {} yaradılır.
    2. 
        
  2. Bu obyektin daxili [[Prototype]]-u Insan.prototype-a bağlanır.
    3. 
        
  3. constructor həmin yeni obyekt this qismində çağırılır.
    4. 
        
  4. constructor açıq şəkildə obyekt qaytarmırsa (adətən qaytarmır), yaradılmış obyekt avtomatik nəticə kimi qaytarılır.
    5. 
      

    


    

      
✕

      
new sözünü unutsan: Insan('Əli', 25) çağırışı TypeError: Class constructor Insan cannot be invoked without 'new' xətası verir. Adi funksiyalardan fərqli olaraq, class constructor-ları new olmadan işə düşmür — bu, təhlükəsizlik üçün bilərəkdən qoyulub.

    


    

      
✓

      
Class body-də yazılan metodlar (salamla() kimi) avtomatik olaraq Insan.prototype-a yazılır — yəni bütün instansiyalar arasında paylaşılır, hər instansiya üçün təkrar yaradılmır. Metodu constructor daxilində this.salamla = function(){...} kimi yazsan, hər instansiya öz funksiya nüsxəsini alar — bu, həm yaddaş israfı, həm də a.salamla === b.salamla müqayisəsinin false olması deməkdir.

    

  


  
  

    
03

    
Prototip zənciri: JS-in gizli mexanizmi

    

      
Bu, bütün mövzunun ən vacib hissəsidir. Hər JavaScript obyektinin gizli daxili keçidi var — [[Prototype]] (kod içində __proto__ vasitəsilə görünür). Bir property və ya metoda müraciət edəndə, JS mühərriki bunu belə axtarır:

    


    

      
1. Əvvəlcə obyektin özündə (own property) axtarır.

      2. Tapmasa, obyektin [[Prototype]]-una keçir və orada axtarır.

      3. Yenə tapmasa, zəncir boyu yuxarı qalxmağa davam edir — nəhayət Object.prototype-a çatır.

      4. Orada da yoxdursa, zəncirin sonu null-dur və nəticə undefined olur.

    


    

      
⚠

      
Ən çox qarışdırılan iki termin: prototype — funksiya/class-ın özündə olan property-dir, new ilə yaranacaq instansiyalar üçün "şablon" rolunu oynayır. __proto__ (yəni [[Prototype]]) isə hər bir konkret obyektin öz valideyninə keçid nöqtəsidir. ali.__proto__ === Insan.prototype — bu ifadə true qaytarır.

    


    
Vizual olaraq zəncir belə görünür: ali adlı instansiyadan başlayıb, sona qədər izləyək.


    

      

        
ali instance

        

          ad: "Əli"
          yas: 25
        

      

      
ali.__proto__

      

        
Insan.prototype class prototype

        

          salamla()
        

      

      
Insan.prototype.__proto__

      

        
Object.prototype built-in

        

          toString()
          hasOwnProperty()
        

      

      
Object.prototype.__proto__

      

        
null zəncirin sonu

        
— heç nə yoxdur —

      

    


    
İndi özün sına: aşağıdakı property/metodlardan birinə klik et və JS-in onu zəncirdə necə axtardığını izlə.

    

      
      
      
      
    

    
Yuxarıdakı düymələrdən birinə klik et.


    

      
✓

      
Praktikada "own" ilə "irsi (inherited)" property-ni ayırmaq üçün ali.hasOwnProperty('ad') — true, ali.hasOwnProperty('salamla') — false (çünki salamla instansiyada yox, prototipdə yerləşir). Zənciri əl ilə yoxlamaq üçün isə Object.getPrototypeOf(ali) istifadə et — köhnəlmiş __proto__-dan daha etibarlıdır.

    

  


  
  

    
04

    
Vərasət: extends necə bağlayır, super necə işləyir

    

      
extends sadəcə "əlaqə yaradır" — iki class arasında prototip zəncirinə bir həlqə əlavə edir: Talebe.prototype.__proto__ === Insan.prototype. Yəni Talebe-nin instansiyaları həm öz metodlarına, həm də Insan-ın metodlarına çıxış əldə edir.

    


    

      
JavaScript

      
class Talebe extends Insan {
  constructor(ad, yas, universitet) {
    super(ad, yas); // valideyn constructor-u çağırır
    this.universitet = universitet;
  }
  salamla() {
    return `${super.salamla()}, ${this.universitet}-də oxuyuram`;
  }
}

const aygun = new Talebe('Aygün', 20, 'BDU');
aygun.salamla();
// "Salam, mən Aygün, 20 yaşındayam, BDU-də oxuyuram"

    


    

      

        
super(...)

        
Valideynin constructor-unu çağırır. extends istifadə olunan class-da mütləqdir və this-dən istifadə etməzdən əvvəl çağırılmalıdır — çünki derived class-da this yalnız valideyn constructor işlədikdən sonra mövcud olur.

      

      

        
super.metod()

        
Valideynin metodunu çağırır. Bunu overriding zamanı valideyn davranışını tamamilə əvəz etmək yox, üzərinə əlavə etmək üçün istifadə edirik.

      

    


    

      
✕

      
super()-i çağırmadan this-dən istifadə etsən: ReferenceError: Must call super constructor before accessing 'this' or returning from derived constructor. Static metodlar da extends vasitəsilə subclass-a keçir — Talebe.staticMetod() valideyndə tərif olunsa belə işləyəcək.

    

  


  
  

    
05

    
Ən çox edilən səhvlər və buglar

    

      
Bunlar real layihələrdə ən tez-tez rast gəlinən problemlərdir. Hər birinin altında niyə baş verdiyi və necə düzəldiləcəyi var.

    


    


      

        
        

          
Problem

          
js
class Duyme {
  constructor(ad) { this.ad = ad; }
  basildi() { console.log(this.ad); }
}
const d = new Duyme('Göndər');
button.addEventListener('click', d.basildi);
// TypeError: Cannot read properties of undefined (reading 'ad')

          
Səbəb

          
Metod obyektdən "ayrılıb" ötürüləndə this bağlılığını itirir — click hadisəsi baş verəndə metod adi funksiya kimi çağırılır və this ya undefined (strict mode-da), ya da düymənin özü olur.

          
Həll

          
js
button.addEventListener('click', () => d.basildi());
// və ya class field kimi arrow function təyin et:
basildi = () => { console.log(this.ad); }

        

      


      

        
        

          
Problem

          
js
const ali = Insan('Əli', 25);
// TypeError: Class constructor Insan cannot be invoked without 'new'

          
Səbəb

          
Adi funksiyalardan fərqli olaraq, class constructor-ları yalnız new ilə çağırıla bilər — bu, dil səviyyəsində qəsdən qoyulmuş məhdudiyyətdir.

          
Həll

          
Sadəcə new Insan(...) yaz. Alternativ constructor lazımdırsa, static factory metod istifadə et (aşağıda, "Daha yaxşı yazmaq" bölməsində).

        

      


      

        
        

          
Problem

          
js
class Talebe extends Insan {
  constructor(ad, universitet) {
    this.universitet = universitet; // xəta!
    super(ad);
  }
}

          
Səbəb

          
Derived (extends olunmuş) class-da this obyekti yalnız super() icra olunduqdan sonra yaranır — çünki valideyn constructor obyektin ilkin qurulmasına cavabdehdir.

          
Həll

          
super(ad)-i həmişə constructor-un ilk sətrində, this-ə istinaddan əvvəl çağır.

        

      


      

        
        

          
Problem

          
Yeni başlayanlar tez-tez Insan.prototype ilə ali.__proto__-u eyni şey zənn edir və səhvən bir-birinin yerinə istifadə edir.

          
Fərq

          
Insan.prototype — class-ın özündə olan, instansiyalar üçün şablon rolunu oynayan obyektdir. ali.__proto__ — konkret instansiyanın öz valideyninə keçididir. Əslində: ali.__proto__ === Insan.prototype → true, amma ali.prototype → undefined (instansiyalarda prototype property-si yoxdur, yalnız funksiya/class-larda var).

        

      


      

        
        

          
Problem

          
js
Insan.prototype.dostlar = []; // bütün instansiyalar bunu PAYLAŞIR
ali.dostlar.push('Aygün');
veli.dostlar; // ['Aygün'] — Vəli də bunu görür!

          
Səbəb

          
Prototipdə yerləşən massiv/obyekt bir dənədir və bütün instansiyalar arasında paylaşılır — hər instansiya üçün ayrıca nüsxə yaranmır.

          
Həll

          
İnstansiyaya məxsus dəyişən data-nı həmişə constructor daxilində this.dostlar = [] kimi təyin et, prototipdə yox.

        

      


      

        
        

          
Problem

          
Köhnə üsulla (function + Insan.prototype.x = ...) prototipə yazılan property-lər enumerable olur və for...in dövründə instansiyanın öz property-ləri ilə qarışıq görünə bilər.

          
Həll

          
Dövr daxilində if (obj.hasOwnProperty(key)) yoxlaması et, yaxud sadəcə Object.keys(obj) istifadə et — o yalnız "own" property-ləri qaytarır. Qeyd: müasir class metodları defaultda enumerable deyil, ona görə bu problem daha çox köhnə prototip-əsaslı koda aiddir.

        

      


      

        
        

          
Problem

          
js
class Insan {
  static yarat(ad) { return new Insan(ad); }
}
const ali = new Insan('Əli');
ali.yarat('Vəli'); // TypeError: ali.yarat is not a function

          
Səbəb

          
static metodlar class-ın özündə yaşayır (Insan.yarat), instansiyaların prototip zəncirində deyil — ona görə instansiya üzərindən çağırıla bilməz.

          
Həll

          
Insan.yarat('Vəli') — birbaşa class adı üzərindən çağır.

        

      


      

        
        

          
Problem

          
js
class Hesab {
  #balans = 0;
}
const h = new Hesab();
h.#balans; // SyntaxError — class xaricindən əlçatan deyil

          
Səbəb

          
# ilə başlayan field-lər həqiqi private-dir — yalnız həmin class-ın öz daxilində görünür, subclass-lardan belə birbaşa çıxış yoxdur (adi _ prefiksdən fərqli olaraq, bu konvensiya deyil, dil səviyyəsində məcburiyyətdir).

          
Həll

          
Xaricdən çıxış lazımdırsa, public getter/setter metod yaz: getBalans() { return this.#balans; }

        

      


    

  


  
  

    
06

    
Nəyi necə etsək daha yaxşı olar

    
    
      
  • 01
    Dərin vərasət zəncirindən qaçın. 3+ səviyyəli extends zənciri (A → B → C → D) anlaşılması və dəyişdirilməsi çətin kod yaradır. Mümkünsə composition (kiçik obyektləri bir yerə yığmaq) üstün tut.
    • 
      
  • 02
    Encapsulation üçün #private field istifadə et, _prefix konvensiyası əvəzinə — _ sadəcə "toxunma" işarəsidir, real qorunma vermir; # isə dil səviyyəsində məcburidir.
    • 
      
  • 03
    Validasiya üçün getter/setter yaz. Məsələn set yas(deyer) { if(deyer < 0) throw new Error(...); this._yas = deyer; } — obyektin heç vaxt yanlış vəziyyətə düşməməsini təmin edir.
    • 
      
  • 04
    Alternativ constructor üçün static factory metod istifadə et: Insan.jsonDan(data) kimi — birbaşa yeni constructor overload etməkdənsə, JS-də bu daha oxunaqlıdır.
    • 
      
  • 05
    Built-in prototiplərə əl vurma (Array.prototype.xxx = ...) — "monkey-patching" adlanan bu texnika gələcək JS versiyaları ilə toqquşa, digər kitabxanalarla konflikt yarada bilər.
    • 
      
  • 06
    JSDoc ilə class-ları sənədləşdir — editor avtomatik tamamlama və tip yoxlaması təklif edir, komanda işində başqalarının kodu anlaması asanlaşır.
    • 
      
  • 07
    Dəyişməz (immutable) instansiyalar üçün Object.freeze() düşün — amma nəzərə al ki, bu shallow (səthi) işləyir: instansiyanın daxilindəki obyekt/massiv yenə dəyişdirilə bilər.
    • 
    

  


  
  

    
07

    
Nüanslar və incəliklər

    

      

        
Class-lar hoist olunmur (Temporal Dead Zone)

        
Function declaration-lardan fərqli olaraq, class-ı təyin olunmadan əvvəl istifadə etsən ReferenceError alarsan — hətta adı "yaddaşda" olsa belə. Bu, let/const-un davranışı ilə eynidir.

      

      

        
Class body avtomatik strict mode-dadır

        
Faylın əvvəlində 'use strict' yazmasan belə, class daxilindəki bütün kod strict mode qaydaları ilə işləyir (məsələn, elan olunmamış dəyişənə yazmaq xəta verir).

      

      

        
Class metodları defaultda enumerable deyil

        
Object.keys(ali) yalnız ad, yas kimi öz property-ləri göstərər, salamla metodunu göstərməz — çünki class prototip metodları enumerable: false ilə yaradılır. Adi obyekt literalındakı metodlar isə enumerable-dır — bu fərq for...in və JSON.stringify davranışına təsir edir.

      

      

        
Arrow function class field — hər instansiya öz nüsxəsini alır

        
basildi = () => {...} şəklində yazılan class field this-i avtomatik və düzgün bağlayır (yuxarıdakı #1 səhvinin başqa həlli), amma bu, prototip metodu deyil — hər instansiya üçün ayrıca funksiya yaradılır. Yəni rahatlıq üçün az miqdarda yaddaş qurban verilir.

      

      

        
instanceof necə işləyir

        
ali instanceof Insan əslində prototip zəncirini yoxlayır: Insan.prototype ali-nin zəncirində varmı? Buna görə instanceof bəzən gözlənilməz nəticə verə bilər (məs. müxtəlif iframe/realm-lərdən gələn obyektlərdə). Fərqli davranış lazımdırsa, Symbol.hasInstance ilə fərdiləşdirmək mümkündür.

      

      

        
static blok (ES2022)

        
Mürəkkəb static initialization üçün static { ... } bloku istifadə edilə bilər — bir neçə static property arasında əlaqəli hesablama aparmaq lazım olanda faydalıdır.
