Event Delegation & Advanced DOM

Kliklədiyin an brauzer bir hadisəni DOM ağacının kökünə doğru yola salır. Bu səyahəti idarə etməyi öyrənəndə, minlərlə ayrı-ayrı listener yazmaq əvəzinə, cəmi birini yazmağı bacaracaqsan.

Bu dərsdə: event bubbling necə işləyir, event.target ilə event.currentTarget arasındakı fərq, dinamik yaradılan elementlərlə iş, parentElement və digər DOM gəzinti üsulları, closest() metodu, ən çox rast gəlinən səhvlər və peşəkar tövsiyələr.

event.target dinamik DOM parentElement closest()

01

Bubbling: Hər Şeyin Təməli

DOM-dakı elementlər bir-birinin içində yerləşərək bir ağac formalaşdırır: body içində div, onun içində ul, onun içində li və s. İndi təsəvvür et ki, ən dərindəki li-yə klikləyirsən. Sual budur: bu klik hadisəsi yalnız o li-də qalır, yoxsa başqa yerə də gedir?

Cavab: gedir. Brauzer klik hadisəsini əvvəlcə həqiqətən klikləndiyi elementdə işə salır, sonra onu addım-addım valideynlərinə — li-dən ul-a, ul-dan div-ə, oradan body-ə, elə document-ə qədər — ötürür. Elə bil suya atılan daşın yaratdığı dalğalar mərkəzdən kənara doğru yayılır; fərq bir onda ki, burada dalğa aşağıdan yuxarıya, kökə doğru "qalxır". Buna event bubbling (hadisənin köpüklənməsi) deyilir.

HTML
<div id="ata">
  <div id="ana">
    <button id="ovlad">Klik et</button>
  </div>
</div>
JavaScript
document.getElementById('ata').addEventListener('click', () => console.log('ata işə düşdü'));
document.getElementById('ana').addEventListener('click', () => console.log('ana işə düşdü'));
document.getElementById('ovlad').addEventListener('click', () => console.log('övlad işə düşdü'));

// Butona klikləyəndə console-da bu ardıcıllıqla görünər:
// övlad işə düşdü
// ana işə düşdü
// ata işə düşdü
💡

Əlavə qeyd: Bubbling-in əksi olan capturing fazası da var — addEventListener-in üçüncü arqumenti {capture:true} versən, dinləyici bubbling-dən əvvəl, yuxarıdan aşağıya doğru gedən mərhələdə işə düşür.

99% hallarda buna ehtiyac olmur, amma mövcudluğunu bilmək faydalıdır — məsələn, bəzi kitabxanalar "xaricə klik" (click-outside) məntiqini məhz capturing ilə tənzimləyir.

02

event.target vs event.currentTarget

Bubbling anlayışını bilən kimi, bu iki xassənin fərqi asanlaşır — amma bu, yeni başlayanların ən çox qarışdırdığı məqamlardan biridir:

  • event.target — istifadəçinin həqiqətən kliklədiyi, ən dərin element. Bubbling boyunca bu dəyişmir, bütün valideynlərdə eyni qalır.
  • event.currentTarget — hazırda işləyən listener-in bağlı olduğu element. Eyni klik bir neçə fərqli elementdəki listener-i növbə ilə tetiklədiyi üçün, bu hər dəfə dəyişir.
JavaScript
document.getElementById('ata').addEventListener('click', function(e){
  console.log('target:', e.target.id);            // həmişə 'ovlad' (button klikləndisə)
  console.log('currentTarget:', e.currentTarget.id); // həmişə 'ata' — listener bura bağlıdır
  console.log('this === currentTarget:', this === e.currentTarget); // true
});
⚠️

Nüans: this yalnız adi function(){} sintaksisində currentTarget-ə bərabərdir. Listener-i arrow function (() => {}) kimi yazsan, this artıq element olmayacaq — arrow function-ların öz this-i yoxdur, əhatə edən (lexical) scope-dan miras alır.

Arrow function işlədirsənsə, həmişə e.currentTarget yaz, this-ə güvənmə.

03

Event Delegation: Bir Dinləyici, Minlərlə Element

İndi bu iki anlayışı (bubbling + target/currentTarget) birləşdirəndə, çox güclü bir texnika ortaya çıxır: event delegation. Fikir sadədir — hər bir uşaq elementə ayrı-ayrı addEventListener yazmaq əvəzinə, ortaq bir valideynə cəmi bir listener bağlayırsan. Klik istənilən uşaqda baş versə də, bubbling sayəsində bu tək listener-ə çatır, sən isə event.target-ə baxaraq dəqiq hansı uşağın klikləndiyini öyrənirsən.

❌ Pis — delegation olmadan
// 100 li varsa, 100 dəfə
// addEventListener çağırılır
document.querySelectorAll('.item').forEach(item => {
  item.addEventListener('click', function(){
    console.log('klikləndi:', this.textContent);
  });
});
✅ Yaxşı — delegation ilə
// Cəmi 1 listener —
// siyahının özünə bağlanır
document.querySelector('.list').addEventListener('click', function(e){
  if (!e.target.classList.contains('item')) return;
  console.log('klikləndi:', e.target.textContent);
});

Fərq nəyə görə vacibdir? Birincisi, performans — yüzlərlə listener yerinə bir dənəsi yaddaşda daha az yer tutur. İkincisi (və daha vacibi) — növbəti bölmədə görəcəyin kimi, bu üsul sən hələ yaratmadığın elementlər üçün də avtomatik işləyir.

04

Dinamik DOM: Hələ Mövcud Olmayan Elementlər

Real tətbiqlərdə DOM statik deyil — istifadəçi bir düyməyə basanda, API-dan data gələndə və ya axtarış nəticələri dəyişəndə, sən JavaScript ilə yeni elementlər yaradıb səhifəyə əlavə edirsən (document.createElement + appendChild). Sual budur: bu yeni elementlər köhnə listener-lardan "xəbərdar" olacaqmı?

Əgər listener-i birbaşa köhnə elementlərin özünə bağlamısansa — yox. Həmin addEventListener çağırışı yalnız o anda mövcud olan elementlərə tətbiq olunub; sonradan yaranan element haqqında heç nə bilmir. Bu, təcrübəsiz developerlərin ən çox rastlaşdığı "niyə mənim yeni elementim işləmir?" probleminin əsas səbəbidir.

Delegation isə bunu default olaraq həll edir, çünki listener heç vaxt dəyişməyən, həmişə mövcud olan bir valideyndə oturur (məsələn, səhifə yüklənəndən bəri var olan <ul class="list">). Yeni <li> əlavə olunanda, ona klikləmək yenə də eyni bubbling yolu ilə <ul>-a çatır və event.target avtomatik olaraq yeni elementi göstərir — əlavə heç bir kod yazmadan.

JavaScript
const list = document.querySelector('.todo-list');

// Bu TƏK listener HƏM mövcud, HƏM DƏ gələcəkdə əlavə olunacaq
// bütün .todo-item elementləri üçün işləyəcək:
list.addEventListener('click', function(e){
  const item = e.target.closest('.todo-item');
  if (!item) return;
  item.classList.toggle('done');
});

// Sonradan yeni element əlavə etsən belə...
const yeni = document.createElement('li');
yeni.className = 'todo-item';
yeni.textContent = 'Yeni tapşırıq';
list.appendChild(yeni);
// ...yuxarıdakı listener onu da tutur, çünki delegation bubbling-ə əsaslanır.
💡

Digər üsul: MutationObserver DOM-a elementlərin əlavə olunmasını izləmək üçündür (məsələn, "yeni sətir gəldi, ona stil ver" kimi hallarda). Event delegation isə hadisələri (klik, submit və s.) tutmaq üçündür.

İkisi fərqli problemləri həll edir, çox vaxt bir layihədə çiyin-çiyinə istifadə olunurlar.

05

parentElement və DOM-da Gəzinti

Delegation-da bəzən aşağıdan yuxarıya əl ilə gəzmək lazım gəlir. Bunun üçün DOM bir neçə hazır xassə təqdim edir:

99% halda parentElement və parentNode eyni nəticəni verir, amma fərq bəzən özünü göstərir: document.documentElement (yəni <html>) üçün .parentNode → document qaytarır (bu bir node-dur, element deyil), amma .parentElement → null qaytarır, çünki document element sayılmır.

Odur ki, əgər "yuxarıya doğru gedərkən mütləq ELEMENT-lə işləyəcəyəm" deyə düşünürsənsə, parentElement daha təhlükəsiz seçimdir — naməlum node tipləri ilə qarşılaşıb səhv almazsan.

06

closest(): Yuxarı Doğru Ağıllı Axtarış

parentElement səni cəmi bir səviyyə yuxarı aparır. Bəs valideynin tam olaraq neçə səviyyə yuxarıda olduğunu bilmirsənsə, sadəcə "hansısa yuxarı elementdə .card class-ı var, onu tap" demək istəyirsənsə? Məhz bunun üçün closest() var.

element.closest(selector) elementin özündən başlayır (özü daxil!) və valideynlər zənciri boyunca yuxarı doğru gedərək, verilmiş CSS selector-a uyğun gələn ilk elementi qaytarır. Heç bir uyğun element tapılmasa, null qaytarır.

Bu, delegation-da həyati əhəmiyyət daşıyır, çünki real UI-da kliklədiyin element çox vaxt sənin "əsl" istədiyin element olmur. Aşağıdakı nümunəyə bax:

HTML
<button class="btn" data-id="42">
  <span class="icon">✎</span> Redaktə et
</button>
JavaScript
document.addEventListener('click', function(e){
  // İstifadəçi ikona (<span>) klikləsə,
  // e.target elə o span olacaq — button yox!
  const btn = e.target.closest('.btn');
  if (!btn) return; // .btn-dən kənar bir yerə klikləndi
  console.log('Redaktə ID:', btn.dataset.id); // ikona klikləsən belə işləyir
});

Özün sına: icon-in-button problemi

Aşağıdakı düyməyə həm mətnindən, həm də kiçik qələm ikonundan klik et — hər iki halda da closest('.btn') düz düyməni tapır.

07

Canlı Laboratoriya: Bubbling-i Öz Gözünlə Gör

Aşağıda kiçik bir DOM ağacı var: document → .card → ul.list → li (yaşılımtıl "yarpaq" elementlər). İstənilən yarpağa klik et və hadisənin necə yuxarı doğru "köpükləndiyini" izlə.

  1. Bir yarpağa (🍃) klik et — narıncı işıq yuxarı doğru necə hərəkət edir, izlə.
  2. "Dinləyici haradadır?" seçimini dəyiş, sonra yenidən klik et — event.target sabit qalır, amma event.currentTarget dəyişir.
  3. "closest('.card') nəticəsini işıqlandır" qutusunu işarələ və yenidən klik et.
  4. "+ Element əlavə et" düyməsinə bas və yeni yarpağa klik et — o da işləyir, çünki bu widget-in özü məhz delegation ilə qurulub!

08

Ən Çox Rast Gəlinən Səhvlər və Buglar

Bu bölmədəki səhvlərin əksəriyyəti "kod işləyir, amma gözlənilməz yerdə sınır" tipindəndir — məhz buna görə tapılması çətindir. Növbəti dəfə qəribə bir bug-la qarşılaşanda, bu siyahını yoxla.

!

tagName həmişə BÖYÜK hərflərlədir

Problemif (e.target.tagName === 'li') — bu şərt heç vaxt true olmayacaq, çünki tagName 'LI' formatında (böyük hərflərlə) qaytarılır.

Həlle.target.tagName === 'LI' yaz, ya da daha etibarlı olan e.target.matches('li') və ya class/data-attribute əsaslı yoxlamadan istifadə et.

!

closest() nəticəsini yoxlamadan işlətmək

Problemconst card = e.target.closest('.card'); card.classList.add('active'); — klik .card-dan tamamilə kənar bir yerə düşübsə, closest() null qaytarır və növbəti sətir xəta ilə çökür.

Həllclosest()-i işlətdiyin HƏR yerdə if (!card) return; yoxlaması əlavə et.

!

event.target-i "gözlədiyin dəqiq element" güman etmək

Problemİçində ikon, <span>, <strong> və ya şəkil olan bir elementə klik edəndə, event.target çox vaxt bu daxili elementlərdən biri olur — sənin "əsas" saydığın valideyn deyil.

HəllDəqiq valideynə ehtiyacın varsa, event.target yerinə event.target.closest('.əsas-element') işlət.

!

parentNode ilə parentElement-i qarışdırmaq

ProblemƏksər halda fərq görünmür, amma document-ə yaxın node-larda parentElement gözlənilmədən null qaytara bilər, halbuki parentNode qeyri-element bir node qaytarır və kod səssizcə səhv nəticə verir.

HəllElement gözlədiyin yerdə həmişə parentElement işlət — heç olmasa "element deyilsə null al" davranışı proqnozlaşdırılandır.

!

stopPropagation()-in düşünülmədən istifadəsi

ProblemBir komponentin içində e.stopPropagation() çağırmaq bubbling-i həmin nöqtədə tam dayandırır. Səhifənin başqa yerində (məsələn document-ə bağlı) bir delegation listener varsa, o bu hadisədən heç vaxt xəbər tutmayacaq.

HəllstopPropagation()-i yalnız niyə lazım olduğunu bilərək çağır və yanına qısa şərh yaz.

!

Dinamik elementlər üçün delegation-u unutmaq

ProblemSiyahıya JS ilə yeni element əlavə edirsən, amma köhnə vərdişlə hər elementə ayrı-ayrı addEventListener yazmağa çalışırsan — nəticədə ya unudulur, ya da eyni kod təkrar-təkrar yazılır.

HəllDinamik siyahı/kart/sətir yaradan hər yerdə default olaraq delegation-dan istifadə et.

!

Arrow function-da this-in currentTarget olacağını güman etmək

Problemlist.addEventListener('click', (e) => { console.log(this); }) — arrow function-ların öz this-i yoxdur, nəticədə this gözlədiyin element olmur.

HəllArrow function işlədəndə element lazım olan hər yerdə e.currentTarget-dən istifadə et.

!

Delegation-u həddindən artıq "geniş" qurmaq

ProblemHər şeyi rahatlıq üçün birbaşa document-ə bağlamaq işləyir, amma layihə böyüdükcə debug etmək çətinləşir və hər klikdə lazımsız yerə çoxlu şərt yoxlanılır.

HəllDelegation-u mümkün qədər ən yaxın sabit valideynə bağla (document yox, konkret .list, .table-body, .modal və s.).

09

Daha Yaxşı Etmək Üçün: Peşəkar Tövsiyələr

  • ✓Delegation üçün həmişə ən yaxın sabit valideyni seç, document-i son çarə kimi saxla.
  • ✓closest()-dən sonra həmişə null yoxlaması et — bu, bir sətirlik vərdişdir, amma saatlarla debug vaxtına qənaət etdirir.
  • ✓Element tipini tagName-ə deyil, data-* atributlarına və ya class-lara əsaslanaraq müəyyən et (data-action="sil" kimi) — kod həm oxunaqlı olur, həm HTML strukturunu dəyişəndə sınmır.
  • ✓Delegated handler-i kiçik bir "router"a çevir: e.target.closest('[data-action]')-dan dataset.action-ı oxu və uyğun funksiyanı çağır — uzun if/else yığınından qaçmış olursan.
  • ✓Yeni funksiyanı yazandan sonra, mütləq dinamik əlavə olunan bir elementlə də test et — səhifə yüklənəndə mövcud olanlarla kifayətlənmə.
  • ✓stopPropagation()-i son çarə kimi saxla və hər çağırışın yanında niyə lazım olduğunu şərh et.
  • ✓Performans üçün: yüzlərlə uşaq elementə tək-tək listener bağlamaq əvəzinə, həmişə bir delegation listener-i seç.
