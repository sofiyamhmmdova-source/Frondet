Local Storage & Session Storage — brauzerin öz "anbarı"

Server-ə heç bir sorğu göndərmədən, məlumatı birbaşa istifadəçinin brauzerində saxlamaq üçün istifadə olunan iki sadə, amma çox işlək alət. Bu dərsdə setItem, getItem, JSON.stringify/parse metodlarını, ən çox rast gəlinən səhvləri və mini proyektlərdə düzgün istifadə qaydalarını addım-addım öyrənəcəksən.

🌐 Server sorğusu yoxdur — hər şey brauzerdə
📦 ~5–10MB saxlama limiti
🔤 Yalnız string saxlanır
🧩 Mini proyektlər üçün vacib mövzu
Əsas

Nədir bu ikisi, nə fərqi var?

Hər ikisi brauzerin Web Storage API-sinin hissəsidir və açar–dəyər (key–value) formatında məlumat saxlayır. API-ları eynidir, fərq yalnız məlumatın nə qədər yaşadığında və kimlərlə paylaşıldığındadır.

🔒

localStorage

Saxladığın məlumat sən özün silənə qədər qalır — brauzeri bağlasan, kompüteri söndürsən belə itmir.

Eyni sayt (origin) üçün bütün tablarda və pəncərələrdə paylaşılır. Məsələn tema seçimi, "məni xatırla" tokeni, səbət (cart) məlumatı üçün əla seçimdir.

⏳

sessionStorage

Saxladığın məlumat yalnız həmin tab açıq olduğu müddətdə yaşayır. Tab-ı bağlayan kimi avtomatik silinir.

Səhifəni yeniləsən (refresh) qalır, amma yeni tab açsan artıq görünmür — hər tab öz ayrıca "kağız qutusuna" malikdir.

Xüsusiyyət localStorage sessionStorage
Saxlama müddəti Sonsuz — özün silənə qədər Tab bağlanana qədər
Tablar arası paylaşım Bəli, eyni origin-də bütün tablar Xeyr, hər tab özəldir
Səhifə yeniləyəndə (F5) Qalır Qalır
Ölçü limiti ~5–10MB (brauzerdən asılı) ~5–10MB (brauzerdən asılı)
Data tipi Yalnız string Yalnız string
Tipik istifadə Tema, dil seçimi, token, səbət Form addımları, tab-a xas müvəqqəti data

Metodlar

6 metod — hamısı bunu bilməklə kifayətdir

localStorage və sessionStorage tamamilə eyni metodlara malikdir. Fərq yalnız hansı obyekti çağırdığındadır.

setItem(key, value)

Açar–dəyər cütünü yazır. Açar artıq varsa, üzərinə yazılır (overwrite).

getItem(key)

Açara uyğun dəyəri qaytarır. Açar yoxdursa, null qaytarır — undefined yox.

removeItem(key)

Yalnız göstərilən açarı silir, qalanlarına toxunmur.

clear()

Həmin storage-dakı bütün açar–dəyərləri təmizləyir.

key(index)

İndeksə görə açarın adını qaytarır — az istifadə olunur, amma bütün açarları gəzmək üçün lazımdır.

length

Storage-da neçə açar–dəyər cütü olduğunu göstərən rəqəm (property, funksiya deyil).

misal.js
// Yazmaq
localStorage.setItem('theme', 'dark');

// Oxumaq
const theme = localStorage.getItem('theme');
console.log(theme); // "dark"

// Olmayan açarı oxumaq
console.log(localStorage.getItem('yoxdur')); // null

// Silmək
localStorage.removeItem('theme');

// Hamısını təmizləmək
localStorage.clear();

// Neçə element var?
console.log(localStorage.length); // 0
⚠️ Diqqət: Dot notasiya ilə də yaza bilərsən — localStorage.ad = 'Vüsal' — işləyir, amma setItem istifadə etmək daha düzgün vərdişdir, çünki açar adı JS-in rezerv sözü (məs: length) ilə üst-üstə düşərsə, dot notasiya problem yaradır.
Vacib qayda

JSON.stringify / JSON.parse — niyə məcburidir?

localStorage və sessionStorage yalnız string saxlaya bilir. Object və ya array saxlamaq istəsən, əvvəlcə onu string-ə "yastılamalısan" (stringify), oxuyanda isə yenidən object-ə "geri qaytarmalısan" (parse).

json-nümunə.js
const user = { name: 'Vüsal', age: 22, isAdmin: false };

// ❌ Bu YANLIŞDIR — object birbaşa saxlanmaz
localStorage.setItem('user', user);
// nəticə: "[object Object]" — bütün data itdi!

// ✅ Düzgün yol — əvvəlcə JSON.stringify
localStorage.setItem('user', JSON.stringify(user));
// saxlanan: '{"name":"Vüsal","age":22,"isAdmin":false}'

// ✅ Oxuyanda JSON.parse ilə geri çeviririk
const raw = localStorage.getItem('user');
const savedUser = JSON.parse(raw);
console.log(savedUser.name); // "Vüsal" — indi normal object-dir
🧠 Yadda saxla: stringify = object → string (yazmazdan əvvəl). parse = string → object (oxuduqdan sonra). İkisi bir-birinin əksidir və həmişə cüt işlədilir.
Diqqət

Ən çox edilən səhvlər və rastlaşacağın buglar

Bunlar yeni başlayanların demək olar hamısının bir dəfə düşdüyü tələlərdir. Hər birini tanısan, mini proyektində saatlarla vaxt itirməzsən.

1

Object-i JSON.stringify etmədən saxlamaq

Object və ya array-i birbaşa setItem-ə versən, JavaScript onu avtomatik mətnə çevirir — nəticə "[object Object]" olur və içindəki bütün real data itir.

canlı sına
// localStorage.setItem('bugDemo', {ad: 'Test'})
// nəticəni görmək üçün düyməyə bas
✅ Həll: JSON.stringify() ilə saxla, JSON.parse() ilə oxu
2

JSON.parse-i try/catch olmadan çağırmaq

Açar heç vaxt yazılmayıbsa, getItem sadəcə null qaytarır — problem deyil. Amma saxlanan mətn əl ilə (devtools-da) korlanıbsa və ya köhnə formatdadırsa, JSON.parse "SyntaxError" ataraq bütün proqramı çökdürə bilər.

canlı sına
// JSON.parse("{ad: 'Ali'") — korlanmış JSON
// nəticəni görmək üçün düyməyə bas
✅ Həll: try { JSON.parse(...) } catch(e) { /* fallback */ }
3

Rəqəmin əslində string olduğunu unutmaq

setItem('count', 5) yazsan da, geri aldığın getItem('count') həmişə '5' — yəni string-dir. '5' + 1 riyazi toplama deyil, mətn birləşməsi olub '51' verir.

✅ Həll: Number(getItem(...)) və ya parseInt(...) ilə çevir
4

sessionStorage-ın tablar arası paylaşılmadığını unutmaq

Yeni tab açıb "niyə mənim datam yoxa çıxdı?" deyə düşünmək — bu, əslində bug deyil, sessionStorage-ın normal davranışıdır. Hər tab özünə məxsus ayrı yaddaşa malikdir.

✅ Həll: Tablar arası ortaq data lazımdırsa localStorage istifadə et
5

Storage limitini aşmaq — QuotaExceededError

Böyük həcmli data (məsələn base64 formatında şəkil) saxlamağa çalışsan, brauzer QuotaExceededError xətası atır və proqram gözlənilmədən dayana bilər.

✅ Həll: try/catch ilə əhatə et, böyük data üçün IndexedDB düşün
6

Server-side render mühitində birbaşa istifadə

Next.js kimi framework-lərdə kod əvvəlcə serverdə işlədiyi üçün window obyekti mövcud olmur — nəticədə "localStorage is not defined" xətası çıxır.

✅ Həll: typeof window !== 'undefined' yoxla, ya da useEffect içində çağır
7

Həssas məlumatı (şifrə, tam token) saxlamaq

localStorage-a yazılan hər şeyə səhifədəki istənilən JS kodu asanlıqla çata bilər — XSS hücumu zamanı zərərli skript də daxil. Bu, httpOnly cookie qədər qorunmur.

✅ Həll: Yalnız az həssas data saxla; token üçün httpOnly cookie düşün
8

"storage" event-in harada işlədiyini qarışdırmaq

window.addEventListener('storage', ...) yalnız digər açıq tablarda tetiklənir — dəyişikliyi edən tabın özündə yox. "Niyə event işləmir?" sualının çox vaxt cavabı elə budur.

✅ Həll: Eyni tab daxilində dəyişikliyi izləmək üçün öz funksiyanı çağır
Yaxşı təcrübə

Nəyi necə etsək daha yaxşı olar?

Mini proyektdə bu vərdişləri tətbiq etsən, kod həm təmiz olar, həm də yuxarıdakı buglara düşməzsən.

1

Wrapper funksiya yaz

saveToStorage(key, value) və loadFromStorage(key) kimi köməkçi funksiyalar yaz ki, JSON.stringify/parse və try/catch hər yerdə təkrarlanmasın.

2

Açar adlarına prefiks ver

'myapp_theme', 'myapp_user' kimi — başqa skriptlər və ya brauzer əlavələri ilə açar adı toqquşmasının qarşısını alır.

3

Data strukturunu versiyalaşdır

{ version: 1, data: {...} } formatında saxla — gələcəkdə strukturu dəyişəndə köhnə data ilə uyğunsuzluq problemini asanlıqla idarə edə bilərsən.

4

Böyük data üçün IndexedDB düşün

localStorage sinxron işlədiyi üçün böyük data ilə əməliyyat UI-ni bloklaya bilər. Şəkil, fayl və s. üçün IndexedDB daha uyğundur.

5

Storage-ın mövcudluğunu yoxla

Bəzi private/incognito rejimlərdə storage məhdud ola bilər. Kritik kod işə salınmazdan əvvəl kiçik bir test-yaz-sil əməliyyatı ilə yoxla.

6

Həssas data saxlama

Şifrə, tam ödəniş məlumatı və digər kritik datanı heç vaxt localStorage/sessionStorage-da saxlama.

wrapper-nümunə.js
function saveToStorage(key, value) {
  try {
    localStorage.setItem('myapp_' + key, JSON.stringify(value));
    return true;
  } catch (err) {
    console.error('Storage yazıla bilmədi:', err);
    return false;
  }
}

function loadFromStorage(key, fallback = null) {
  try {
    const raw = localStorage.getItem('myapp_' + key);
    return raw ? JSON.parse(raw) : fallback;
  } catch (err) {
    console.error('Data korlanıb, fallback istifadə olunur:', err);
    return fallback;
  }
}
Nüanslar

Diqqət yetirməli olduğun incə məqamlar

Bunlar birbaşa "bug" sayılmır, amma bilmədikdə səni çaşdıra bilər.

⚙️ Sinxron işləyir

localStorage və sessionStorage sinxron (synchronous) API-dır — böyük data ilə əməliyyat aparanda əsas thread-i bloklaya, səhifəni "donduraq" bilər.

🌐 Origin fərqi

Eyni domen, amma fərqli port və ya protokol (http vs https) — brauzer üçün fərqli origin deməkdir. Storage bu ikisi arasında paylaşılmır.

🧹 İstifadəçi silə bilər

Brauzerin "Clear browsing data" funksiyası ilə istifadəçi localStorage-ı istənilən an tamamilə silə bilər. Mühüm datanı yalnız buna etibar etmə.

🕵️ Private/Incognito rejim

Bəzi köhnə brauzer versiyalarında məxfi rejimdə storage limiti sıfır ola bilirdi. Yeni versiyalarda düzəlib, amma try/catch yenə də yaxşı vərdişdir.

🖼️ iframe məhdudiyyətləri

Üçüncü tərəf iframe-lərdə bəzi brauzerlər storage-a girişi məhdudlaşdıra bilər (third-party storage siyasətləri).

🔢 Object.keys ilə gəzmək

Bütün açarları görmək üçün key(i) əvəzinə çox vaxt Object.keys(localStorage) istifadə etmək daha rahatdır.

Xülasə

Mini proyekt üçün yadda saxla

Bu 5 qaydanı bilsən, localStorage/sessionStorage mövzusunda mini proyektdə çətinlik çəkməzsən.

  • localStorage = daimi, sessionStorage = tab bağlanana qədər.
  • İkisi də yalnız string saxlayır — object/array üçün mütləq JSON.stringify / JSON.parse.
  • getItem tapılmasa null qaytarır, undefined yox — bunu yoxla.
  • JSON.parse-i həmişə try/catch içində çağır, korlanmış data proqramı çökdürməsin.
  • Həssas məlumatı (şifrə, tam token) heç vaxt bu ikisində saxlama.
