Əsas anlayış

Promise nədir?

Promise — nəticəsi hələ məlum olmayan, gələcəkdə (adətən asinxron şəkildə) ya uğurla tamamlanacaq, ya da xəta ilə başa çatacaq bir əməliyyatın nəticəsini təmsil edən JavaScript obyektidir. Sadə dillə desək: "Bu iş bitəndə sənə nəticəni verəcəyəm" vədidir.

Hər Promise öz həyatı boyunca yalnız üç haldan birində ola bilər:

● Pending

Başlanğıc haldır. Əməliyyat hələ davam edir, nə uğur, nə də xəta baş verib.

✓ Fulfilled

Əməliyyat uğurla bitib. resolve() çağırılıb, nəticə hazırdır.

✕ Rejected

Əməliyyat xəta ilə bitib. reject() çağırılıb, xəta səbəbi ötürülüb.

Vacib qayda Promise "settled" (yəni fulfilled və ya rejected) olduqdan sonra öz halını BİR DƏHA DƏYİŞƏ BİLMƏZ. resolve() yenidən çağırılsa belə, heç bir təsiri olmaz — yalnız ilk çağırış hesaba alınır. Bu, Promise-in immutable (dəyişməz) təbiətidir.
Yaratmaq

new Promise()

Yeni Promise new Promise(executor) konstruktoru ilə yaradılır. executor — iki arqument qəbul edən funksiyadır: resolve və reject. Siz əməliyyatınızın nəticəsinə görə bunlardan birini çağırırsınız.

const sorgu = new Promise((resolve, reject) => {
  // "executor" funksiyası — DƏRHAL, sinxron şəkildə işə düşür
  setTimeout(() => {
    const ugurlu = true;
    if (ugurlu) {
      resolve("Server cavab verdi ✅");
    } else {
      reject(new Error("Şəbəkə xətası ❌"));
    }
  }, 1000);
});
Nüans "Executor" funksiyası (yəni (resolve, reject) => {...} hissəsi) dərhal və sinxron şəkildə işə düşür — new Promise() sətri icra olunan kimi. Yalnız resolve/reject içindəki asinxron kod (məsələn, setTimeout və ya şəbəkə sorğusu) gecikir. Yəni new Promise() yaratmaq əməliyyatı özü "gözlətmir".
Nəticəni götürmək

.then()

.then(onFulfilled, onRejected) Promise uğurla (və ya istəyə görə, xətayla) bitəndə işə düşəcək funksiyaları qeyd edir. Praktikada adətən yalnız birinci arqument istifadə olunur, xətalar üçün isə ayrıca .catch() yazılır.

sorgu
  .then(nəticə => {
    console.log(nəticə); // "Server cavab verdi ✅"
    return nəticə.toUpperCase();
  })
  .then(boyukHerflerle => {
    console.log(boyukHerflerle);
  });

Ən vacib xüsusiyyət: hər .then() özü YENİ bir Promise qaytarır — məhz buna görə .then().then().then() şəklində zəncirvarı (chaining) yazmaq mümkündür. Əgər .then() daxilində sadə dəyər return edilsə, bu dəyər növbəti .then()-ə ötürülür. Əgər başqa bir Promise return edilsə, zəncir onun nəticələnməsini gözləyir (yastılanma / flattening baş verir).

Praktik məsləhət .then() daxilində mütləq return edin. Return unudulsa, növbəti .then()-ə undefined ötürülür və zəncir "qırılır" — bu, ən çox rast gəlinən səhvlərdən biridir (aşağıda ətraflı bax).
Xətaları tutmaq

.catch()

.catch(onRejected) — əslində .then(undefined, onRejected) üçün rahat qısaltmadır (syntactic sugar). Zəncirdə istənilən əvvəlki addımda baş verən xətanı tutur — təkcə bilavasitə özündən öncəki .then()-i deyil.

sorgu
  .then(nəticə => {
    throw new Error("Emal zamanı xəta baş verdi");
  })
  .then(başqaNəticə => {
    // Bura HEÇ VAXT çatmayacaq, çünki yuxarıda xəta atıldı
  })
  .catch(xəta => {
    console.error("Tutuldu:", xəta.message);
    // Tutuldu: Emal zamanı xəta baş verdi
  });
Necə işləyir? Zəncirdə bir yerdə xəta atılan (və ya reject() çağırılan) kimi, JavaScript avtomatik olaraq bütün aradakı .then()-ləri ötürüb, ən yaxın .catch()-ə "tullanır". Buna görə uzun zəncirlərdə tək bir .catch() kifayət edir.
Təmizlik

.finally()

.finally(onFinally) — Promise necə nəticələnməsindən asılı olmayaraq (istər fulfilled, istər rejected) həmişə işə düşür. Funksiya heç bir arqument qəbul etmir, çünki məqsədi nəticə ilə işləmək deyil, təmizlik (cleanup) işləridir.

göstərYuklenmeIkonu();

sorgu
  .then(nəticə => renderEt(nəticə))
  .catch(xəta => gosterXetaMesaji(xəta))
  .finally(() => {
    gizletYuklenmeIkonu(); // nəticədən asılı olmayaraq işləyir
  });
Nə üçün faydalıdır? "Loading" ikonunu gizlətmək, bağlantını bağlamaq, resurs təmizləmək kimi işləri həm .then(), həm də .catch() içində təkrar yazmaq əvəzinə, birdəfəlik .finally()-də yazmaq kifayətdir. Bu, kodun təkrarlanmasının qarşısını alır.
Paralel icra

Promise.all()

Promise.all(iterable) bir massiv (və ya digər iterable) daxilindəki bütün Promise-lərin eyni vaxtda (paralel) tamamlanmasını gözləyir və tək bir Promise qaytarır.

const istifadeciler = fetch("/api/istifadeciler");
const mehsullar    = fetch("/api/mehsullar");
const sifarisler   = fetch("/api/sifarisler");

Promise.all([istifadeciler, mehsullar, sifarisler])
  .then(([res1, res2, res3]) => {
    // Nəticələr GÖNDƏRİLDİYİ SIRA ilə qayıdır,
    // hansının daha tez bitdiyindən asılı olmayaraq
  })
  .catch(xəta => {
    // İSTƏNİLƏN biri rədd olunsa, bura düşür
  });
Fail-fast davranışı Əgər massivdəki Promise-lərdən YALNIZ BİRİ rədd olunarsa (reject), Promise.all() dərhal rədd olunur — digərlərinin nəticəsini gözləmir. Diqqət: digər Promise-lər arxa planda icra olunmağa davam edir, sadəcə onların nəticəsi artıq sizə lazım olmur.

Bu "hamısı və ya heç biri" davranışı hər zaman istənilən nəticə deyil. Ona görə oxşar, lakin fərqli davranan qohum metodları tanımaq vacibdir:

MetodNə vaxt bitirDavranışı
Promise.all()Hamısı bitəndəBiri rədd olunsa, dərhal rədd olunur (fail-fast)
Promise.allSettled()Hamısı bitəndəHeç vaxt rədd olunmur, hər birinin nəticəsini (status: "fulfilled"/"rejected") qaytarır
Promise.race()Birincisi bitəndəİlk nəticələnən (uğur və ya xəta, fərq etməz) qalib gəlir
Promise.any()İlk uğurlu olandaİlk fulfilled olanı qaytarır; hamısı rədd olunsa, xəta verir
Diqqət edin

Ən çox edilən səhvlər və buglar

Aşağıda başlanğıc və orta səviyyəli developerlərin Promise-lərlə işləyərkən ən tez-tez etdiyi səhvlər verilib. Hər kartda əvvəlcə problemi görün, sonra "Düzgün həll"ə klikləyərək düzəlişi açın.

Bug .catch() əlavə etməməklə "unhandled rejection"

Xəta baş verə biləcək zəncirin sonunda .catch() olmadıqda, xəta "tutulmamış" qalır və brauzer konsolunda "Uncaught (in promise)" xəbərdarlığı görünür.

sorgu.then(nəticə => {
  isle(nəticə);
}); // .catch() yoxdur!
Düzgün həllə bax 
sorgu
  .then(nəticə => {
    isle(nəticə);
  })
  .catch(xəta => {
    console.error("Xəta:", xəta);
  });

Bug .then() daxilində return etməyi unutmaq

Əgər .then() içində nəticə return edilmirsə, növbəti .then()-ə undefined ötürülür.

sorgu
  .then(nəticə => {
    nəticə.toUpperCase(); // return YOXDUR
  })
  .then(deyer => {
    console.log(deyer); // undefined 😕
  });
Düzgün həllə bax 
sorgu
  .then(nəticə => {
    return nəticə.toUpperCase();
  })
  .then(deyer => {
    console.log(deyer); // düzgün dəyər
  });

Bug Promise-ləri lazımsız yerə "nest" etmək

Callback-hell-i Promise-lərlə təkrarlamaq — chaining əvəzinə iç-içə yazmaq, kodu oxunmaz edir.

getIstifadeci(id).then(istifadeci => {
  getSifarisler(istifadeci.id).then(sifarisler => {
    getOdenisler(sifarisler[0].id).then(odenis => {
      console.log(odenis); // "piramida" strukturu
    });
  });
});
Düzgün həllə bax 
getIstifadeci(id)
  .then(istifadeci => getSifarisler(istifadeci.id))
  .then(sifarisler => getOdenisler(sifarisler[0].id))
  .then(odenis => console.log(odenis))
  .catch(xəta => console.error(xəta));

Bug Artıq Promise olanı yenidən new Promise() ilə bükmək

Bu, "Promise constructor antipattern" adlanır. fetch() artıq Promise qaytarır — onu yenidən bükməyə ehtiyac yoxdur.

function getMelumat() {
  return new Promise((resolve, reject) => {
    fetch("/api/melumat")
      .then(res => resolve(res))
      .catch(err => reject(err));
  });
}
Düzgün həllə bax 
function getMelumat() {
  return fetch("/api/melumat"); // artıq Promise-dir
}

Bug setTimeout daxilində atılan xətanı tutmamaq

Asinxron callback (məsələn setTimeout) içində birbaşa throw etmək Promise tərəfindən avtomatik tutulmur — çünki bu, artıq executor-un sinxron icra dövrəsindən kənardadır.

new Promise((resolve, reject) => {
  setTimeout(() => {
    throw new Error("Bu tutulmayacaq!");
  }, 1000);
});
Düzgün həllə bax 
new Promise((resolve, reject) => {
  setTimeout(() => {
    reject(new Error("İndi düzgün tutulacaq"));
  }, 1000);
});

Bug Promise.all-ın "hamısı və ya heç biri" olduğunu unutmaq

3 sorğudan biri uğursuz olanda, digər 2-si uğurlu olsa belə, Promise.all() HAMISINI rədd edilmiş sayır və nəticələrini itirirsiniz.

Promise.all([sorgu1, sorgu2, sorgu3])
  .then(nəticələr => { /* ... */ })
  .catch(xəta => {
    // Yalnız 1 sorğu xəta versə belə, HAMISI itir
  });
Düzgün həllə bax 
Promise.allSettled([sorgu1, sorgu2, sorgu3])
  .then(nəticələr => {
    nəticələr.forEach(n => {
      if (n.status === "fulfilled") console.log(n.value);
      else console.warn(n.reason);
    });
  });
Tövsiyələr

Nəyi etsək daha yaxşı olar

  • Hər zəncirin sonunda mütləq .catch() yazın (və ya try/catch ilə async/await istifadə edin) — "unhandled rejection" heç vaxt olmasın.
  • .then() daxilində dəyəri həmişə return edin, əks halda zəncir "qırılır" və undefined yayılır.
  • Artıq Promise qaytaran funksiyanı (fetch, kitabxana metodları) yenidən new Promise() ilə bükməyin — bu, lazımsız mürəkkəblikdir (antipattern).
  • Bir-birindən asılı olmayan bir neçə asinxron işi ardıcıl await etmək əvəzinə, Promise.all() ilə paralel işə salın — sürəti artırır.
  • Hamısının nəticəsini bilmək istədiyiniz, amma biri uğursuz olsa belə davam etmək istədiyiniz halda Promise.allSettled() seçin, Promise.all() yox.
  • Xəta obyektlərini həmişə Error instansiyası kimi atın (sadə string yox) — bu, stack trace və debug imkanı verir.
  • Təmizlik (loading gizlətmə, bağlantı bağlama) əməliyyatlarını .finally()-də toplayın, .then() və .catch()-də təkrarlamayın.
  • Kod oxunaqlılığı üçün, Promise-in məntiqini başa düşdükdən sonra mürəkkəb zəncirlərdə async/await-ə keçməyi düşünün — o, Promise üzərində qurulmuş sintaktik şəkərdir.
Dərinə enək

Diqqət ediləsi nüanslar

Bunlar Promise-ləri "işlədə bilmək"lə "həqiqətən başa düşmək" arasındakı fərqi yaradan detallardır.

Microtask queue: niyə .then() setTimeout-dan da tez işə düşür?

JavaScript-in event loop-unda iki növbə var: microtask queue (Promise callback-ləri, .then/.catch/.finally) və macrotask queue (setTimeout, setInterval, UI hadisələri). Cari sinxron kod bitən kimi, event loop əvvəlcə bütün microtask-ları tamamlayır, yalnız sonra növbəti macrotask-a keçir. Ona görə Promise.resolve().then(...) həmişə setTimeout(..., 0)-dan ÖNCƏ işə düşür — nə qədər "0 saniyə" desəniz də.

console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// Nəticə: 1, 4, 3, 2
Settled Promise dəyişməzdir (immutable)

Bir dəfə fulfilled və ya rejected olan Promise əbədilik o haldadır. resolve() və ya reject()-in ikinci çağırışı sadəcə nəzərə alınmır — heç bir xəta da vermir, sadəcə heç nə etmir.

Zəncirdəki xəta ən yaxın .catch()-ə "tullanır"

Bir .then() daxilində throw edilən xəta, avtomatik olaraq həmin Promise-i rədd edilmiş vəziyyətə salır və nəzarəti zəncirdəki ilk .catch()-ə ötürür — aradakı bütün .then()-lər ötürülür. Amma diqqət: .then(uğur, xəta) formasında yazılmış İKİNCİ arqument yalnız ƏVVƏLKİ Promise-in rədd olunmasını tutur, öz "uğur" funksiyasının İÇİNDƏ atılan xətanı YOX.

Promise.all-da "uğursuz olanlar" yox olmur, sadəcə nəzərə alınmır

Promise.all() ilk rədd olunanı görən kimi dərhal rədd olunsa da, digər Promise-lər arxa planda icra olunmağa davam edir (məsələn, şəbəkə sorğuları geri çağırılmır). Sadəcə onların nəticəsi artıq sizin kodunuza ötürülmür — bu, resurs sızması demək deyil, amma yaddan çıxarılmamalıdır.

async funksiyanı executor kimi istifadə etməyin

new Promise(async (resolve, reject) => {...}) yazmaq antipatterndir. Əgər async executor daxilində xəta atılarsa, bu xəta reject()-ə çevrilmir — sükutla "udulur" (unhandled rejection). Executor-u həmişə sinxron (adi) funksiya kimi saxlayın.
