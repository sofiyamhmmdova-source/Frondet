01Əsas anlayış

Regex nədir və nə üçün lazımdır?

Regular Expression (qısaca regex) — mətn içində müəyyən bir "naxışı" (pattern) təsvir etməyin universal üsuludur. JavaScript-də regex /pattern/flags şəklində yazılır və RegExp növü kimi mövcuddur.

Adi includes() və ya indexOf() yalnız sabit, dəqiq mətn axtara bilir. Amma real həyatda çox vaxt "dəqiq mətn" yox, qayda axtarırıq: "bu, e-poçt formatındadırmı?", "bu sətirdə hər hansı rəqəm varmı?", "bütün tarixləri tap və formatını dəyiş". Məhz burada regex işə düşür.

Ən çox rast gəlinən istifadə sahələri:

🔎 Axtarış və doğrulama

E-poçt, telefon, şifrə, istifadəçi adı kimi sahələrin düzgün formatda olub-olmadığını yoxlamaq.

✂️ Ayırma və çıxarma

Uzun mətndən tarixləri, qiymətləri, hashtag-ları və ya linkləri "tutub" çıxarmaq.

🔁 Kütləvi əvəzləmə

Min sətirlik mətndə bir formatı başqasına çevirmək (məs. tarix formatını dəyişmək).

🧹 Təmizləmə

İstifadəçi girişindən artıq boşluqları, icazəsiz simvolları təmizləmək.

02Təməl

Sintaksisin əsasları

Regex öz "əlifbasına" malikdir. Aşağıdakı simvollar demək olar ki, hər pattern-də qarşına çıxacaq.

SimvolMəna
.İstənilən bir simvol (yeni sətir xaric — s bayrağı olmadan)
\d / \DRəqəm [0-9] / rəqəm olmayan
\w / \WSöz simvolu [A-Za-z0-9_] / əksi — Azərbaycan hərflərini əhatə etmir!
\s / \SBoşluq (space, tab, sətir sonu) / boşluq olmayan

Bayraqlar (flags) isə regex-in necə işləyəcəyini müəyyən edir:

03Metod

test() metodu

regex.test(mətn) — mətni özü qaytarmır, sadəcə true / false qaytarır: "uyğunluq varmı, yoxdurmu?". Bunun üçün ən uyğun yer — forma validasiyasıdır, çünki adətən bizə yalnız "keçərlidirmi" cavabı lazımdır.

nümunə
const pinRegex = /^\d{4}$/;

console.log(pinRegex.test("2026")); // true
console.log(pinRegex.test("abcd")); // false

Diqqət: əgər regex-in g bayrağı varsa, test() "yaddaşlıdır" — hər çağırışdan sonra daxili lastIndex dəyərini yadda saxlayır. Bu, aşağıdakı ilk bug-da geniş izah olunur.

04Metod

match() və matchAll()

str.match(regex) — mətnin özündən uyğun gələn hissələri qaytarır. Davranışı g bayrağından asılı olaraq tamamilə dəyişir:

❌ g bayrağı yoxdur

İlk uyğunluğu, qruplarla və indekslə birlikdə tam obyekt (array-abənzər) kimi qaytarır. Uyğunluq yoxdursa — null.

✅ g bayrağı var

Bütün tam uyğunluqların sadə sətir array-i qaytarılır, amma qruplar itir. Uyğunluq yoxdursa — yenə null.

g bayrağı olmadan — qruplarla
const str = "Görüş 12.05.2026 tarixində olacaq.";
const re = /(\d{2})\.(\d{2})\.(\d{4})/;

const m = str.match(re);
console.log(m[0]);       // "12.05.2026"
console.log(m[1], m[2], m[3]); // "12" "05" "2026"
console.log(m.index);    // 6
g bayrağı ilə — qruplar itir
const re2 = /\d{2}\.\d{2}\.\d{4}/g;
console.log(str.match(re2)); // ["12.05.2026"] — qruplar YOXDUR

Həm bütün uyğunluqları, həm də onların qruplarını birlikdə almaq istəsək — matchAll() köməyə çatır (mütləq g bayrağı tələb edir):

matchAll() — adlı qruplarla
const re3 = /(?<gun>\d{2})\.(?<ay>\d{2})\.(?<il>\d{4})/g;

for (const m of str.matchAll(re3)) {
  console.log(m.groups.gun, m.groups.ay, m.groups.il);
  // "12" "05" "2026"
}
05Metod

replace() və replaceAll()

str.replace(pattern, əvəzedici) — tapılan hissəni yenisi ilə dəyişir. Əvəzedici həm sətir (xüsusi $1, $&, $<ad> işarələri ilə), həm də funksiya ola bilər.

qruplarla format dəyişmək
const tarix = "2026-05-12";
const yeni = tarix.replace(/(\d{4})-(\d{2})-(\d{2})/, "$3.$2.$1");

console.log(yeni); // "12.05.2026"
funksiya ilə — kart nömrəsini maskalamaq
const kart = "4169 4501 2233 8890";
// hər rəqəmi, sonrasında ən azı 4 rəqəm gələn yerlərdə * ilə əvəz et
const maskali = kart.replace(/\d(?=\D*\d{4})/g, "*");

console.log(maskali); // "**** **** **** 8890"

ES2021-dən etibarən replaceAll() var — sadə sətirlə işlədikdə avtomatik bütün uyğunluqları dəyişir (regex-də isə yenə g bayrağı məcburidir, əks halda xəta verir):

replaceAll()
const cumle = "pişik, pişik və pişik";
console.log(cumle.replaceAll("pişik", "pişik balası"));
// "pişik balası, pişik balası və pişik balası"
06Praktika

Praktiki nümunə: forma validasiyası

Aşağıdakı sahələr canlıdır — yazdıqca test() əsasında yoxlanılır. Bu, regex-in real layihələrdə ən çox işlədiyi yerdir.

/^[^\s@]+@[^\s@]+\.[^\s@]+$/
/^(\+994|0)(10|50|51|55|60|70|77|99)\d{7}$/
/^\p{L}+(\s\p{L}+)*$/u
07Diqqət

Ən çox edilən səhvlər və buglar

Regex özü sadədir, amma JavaScript-in onu necə icra etməsi barədə bir neçə "tələ" var. Aşağıda ən çox rast gəlinən 8 səhvi — səbəbi və düzəlişi ilə birlikdə tapa bilərsən.

Bug«g» bayrağı + test() — lastIndex tələsi+

g bayraqlı regex öz vəziyyətini (lastIndex) yadda saxlayır. Eyni regex obyektini dəfələrlə çağırsan, nəticə hər dəfə fərqli ola bilər — halbuki mətn dəyişməyib.

❌ Səhv
const re = /ab/g;
console.log(re.test("ab")); // true
console.log(re.test("ab")); // false  ← eyni sətir, nəticə dəyişdi!
console.log(re.test("ab")); // true
✅ Düzgün
// sadəcə true/false lazımdırsa, "g" bayrağını çıxar
const re2 = /ab/;
console.log(re2.test("ab")); // həmişə true

// və ya hər yoxlamadan əvvəl lastIndex-i sıfırla
re.lastIndex = 0;
Bugİstifadəçi girişini escape etmədən regex qurmaq+

Axtarış qutusundakı mətni birbaşa new RegExp()-ə versən, istifadəçi ., *, ( kimi xüsusi simvollar yazarsa, pattern gözlənilməz işləyər və ya xəta verər.

❌ Səhv
function axtar(sozler, metn) {
  const re = new RegExp(sozler, "gi");
  return metn.match(re);
}
axtar("qiymet 5.99", metn); // "." istənilən simvolu tutur!
✅ Düzgün
function escapeRegex(str) {
  return str.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
}
function axtar(sozler, metn) {
  const re = new RegExp(escapeRegex(sozler), "gi");
  return metn.match(re);
}
BugAclı (greedy) vs tənbəl (lazy) kvantifikator+

.+ defolt olaraq aclıdır — mümkün qədər çox simvolu "udur". Bu, ikinci bağlayan işarəyə qədər hər şeyi tutmasına səbəb ola bilər.

❌ Səhv
const html = "<b>qalın</b> və <i>əyri</i>";
console.log(html.match(/<.+>/)[0]);
// "<b>qalın</b> və <i>əyri</i>"  ← hamısını uddu!
✅ Düzgün
console.log(html.match(/<.+?>/)[0]);
// "<b>"  ← "?" onu tənbəl edir, ilk bağlanışda dayanır
BugAnchor-ların (^ $) unudulması+

^ və $ olmadan regex mətnin hər hansı hissəsində uyğunluq axtarır — nəticədə "yarımçıq doğru" mətnlər də keçərli sayıla bilər.

❌ Səhv
const sifreRegex = /\d{8,}/;
console.log(sifreRegex.test("zibil 12345678 zibil")); // true!
✅ Düzgün
const sifreRegex2 = /^\d{8,}$/;
console.log(sifreRegex2.test("zibil 12345678 zibil")); // false
console.log(sifreRegex2.test("12345678"));              // true
Bug«i» bayrağının unudulması+

Defolt olaraq regex böyük/kiçik hərfi fərqləndirir. İstifadəçi girişi ilə işləyəndə bu, gözlənilməz "uyğunsuzluqlara" səbəb olur.

❌ Səhv
const re = /baki/;
console.log(re.test("Mən Bakıda yaşayıram")); // false
✅ Düzgün
const re2 = /bak[ıi]/i;
console.log(re2.test("Mən Bakıda yaşayıram")); // true
BugAzərbaycan hərfləri \w və [a-z] daxilində deyil+

JavaScript-in \w və a-z diapazonu yalnız latın əlifbasının 26 hərfini tanıyır. ə, ı, ğ, ş, ç, ö, ü bu diapazona daxil deyil!

❌ Səhv
const adRegex = /^[a-zA-Z]+$/;
console.log(adRegex.test("Cəlil")); // false — "ə" tanınmadı!
✅ Düzgün
// 1) hərfləri əl ilə əlavə et
const adRegex1 = /^[a-zA-ZƏəIıİiĞğŞşÇçÖöÜü]+$/;

// 2) və ya unicode hərf sinfindən istifadə et ("u" bayrağı ilə)
const adRegex2 = /^\p{L}+$/u;

console.log(adRegex2.test("Cəlil")); // true
Bugreplace()-də «g» olmadan yalnız ilk uyğunluq dəyişir+

Çox zaman gözlənilir ki, replace() bütün uyğunluqları dəyişəcək — amma g bayrağı olmadan cəmi biri dəyişir.

❌ Səhv
const metn = "pişik pişik pişik";
console.log(metn.replace(/pişik/, "it"));
// "it pişik pişik"  ← cəmi biri dəyişdi!
✅ Düzgün
console.log(metn.replace(/pişik/g, "it"));   // "it it it"
console.log(metn.replaceAll("pişik", "it")); // "it it it"
Bugİç-içə kvantifikatorlar və regex ilə "parse" etmək+

Bəzi mürəkkəb pattern-lər (məs. (a+)+ kimi iç-içə təkrarlar) uzun mətndə catastrophic backtracking-ə səbəb ola bilər — brauzer/server saniyələrlə, hətta dəqiqələrlə "asılı" qalır. Həmçinin HTML və ya JSON kimi strukturlu formatları regex ilə "parse" etməyə çalışmaq da tipik səhvdir.

❌ Riskli
const supheliRegex = /^(a+)+$/;
supheliRegex.test("aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa!");
// brauzer bir müddət tamamilə donur
✅ Düzgün
// 1) iç-içə kvantifikatorlardan çəkin — /^a+$/ kifayətdir
// 2) strukturlu formatlar üçün hazır parser işlət:
const data = JSON.parse(jsonString); // regex yox, düz parser
08Tövsiyələr

Nəyi etsək daha yaxşı olar?

  • Mürəkkəb pattern qurmadan əvvəl onlayn regex test alətindən istifadə et — hər hissənin nəyə uyğun gəldiyini canlı gör.
  • Uzun pattern-ləri adlandırılmış qruplarla ((?<ad>...)) böl — 6 ay sonra özün də oxuyanda anlayacaqsan.
  • Azərbaycan və digər unicode simvollarla işləyəndə u bayrağı və \p{L} kimi unicode sinifləri düşün.
  • Təkrar istifadə olunan regex-i funksiya içində yox, modulun yuxarısında bir dəfə təyin et — hər çağırışda yenidən yaratmaq performansa təsir edir.
  • İstifadəçi girişindən qaynaqlanan hər hissəni mütləq escape et — özün yazdığın escapeRegex() funksiyası kifayətdir.
  • Frontend validasiyası yalnız UX üçündür — heç vaxt etibar edilən son nöqtə deyil, backend-də mütləq təkrar yoxla.
  • Bir "hamısını edən" nəhəng regex yazmaqdansa, məntiqi olaraq bir neçə sadə regex-ə böl.
  • Test case-lərinə sərhəd halları əlavə et: boş sətir, yalnız boşluqlar, çox uzun mətn, emoji, Azərbaycan hərfləri.
09Yoxla özünü

Yekun və özünüyoxlama

Sualın üstünə klikləyib cavabı yoxla:

1. «g» bayraqlı regex-i eyni sətir üzərində iki dəfə test() ilə çağırsaq, nəticələr niyə fərqli ola bilər?+

Cavab: çünki g bayrağı regex-ə vəziyyət (lastIndex) qazandırır — hər uğurlu axtarışdan sonra sonrakı axtarış həmin nöqtədən başlayır. Nəticədə eyni mətn üçün nəticə "true, false, true..." arasında dəyişə bilər.

2. match() metodunu «g» bayrağı ilə çağırsaq, tutulan qruplar nəticədə olurmu?+

Cavab: Xeyr. «g» ilə match() yalnız tam uyğunluqların sadə sətir siyahısını qaytarır, qruplar itir. Qrupları saxlamaq üçün matchAll() və ya «g» olmadan tək uyğunluqla işləmək lazımdır.

3. "Əli" sözü /^[a-z]+$/i pattern-inə niyə uyğun gəlmir?+

Cavab: çünki [a-z] diapazonu yalnız latın əlifbasının 26 hərfini əhatə edir; "ə" bu diapazona daxil deyil. Hərfi əl ilə diapazona əlavə etmək və ya /^\p{L}+$/u kimi unicode hərf sinfindən istifadə etmək lazımdır.

4. replace()-in ilk arqumenti adi sətir (regex yox) olduqda neçə uyğunluq dəyişir?+

Cavab: cəmi biri — ilk rast gəlinən. Hamısını dəyişmək üçün ya g bayraqlı regex, ya da replaceAll() lazımdır.

5. İstifadəçi girişini birbaşa new RegExp(input) şəklində işlətmək niyə risklidir?+

Cavab: çünki istifadəçi ., *, ( kimi xüsusi regex simvolları yaza bilər — bu, gözlənilməz uyğunluqlara, xətalara, hətta mürəkkəb hallarda performans problemlərinə (ReDoS) səbəb ola bilər. Girişi əvvəlcə escape etmək lazımdır.

Bu dərs JavaScript-də Regular Expressions mövzusunu əhatə edir — test() · match() · replace(). Öz layihələrində yeni regex qurarkən mütləq sərhəd hallarını (boş sətir, uzun mətn, Azərbaycan hərfləri) sına.
