01 — state anlayışı

State nədir? Props-dan fərqi

State — komponentin öz daxilində saxladığı və zaman keçdikcə dəyişə bilən məlumatdır. Props isə valideyn (parent) komponentdən uşaq (child) komponentə ötürülən, komponentin özü tərəfindən dəyişdirilə bilməyən (read-only) məlumatdır.

Ən sadə analogiya: props — sənə kənardan verilən tapşırıq vərəqəsidir, onu dəyişə bilməzsən, sadəcə oxuyub istifadə edirsən. State isə öz şəxsi qeyd dəftərindir — istənilən vaxt özün yaza, poza, dəyişə bilərsən.

Bir komponentin state-i çox vaxt uşaq komponentlərə props kimi ötürülür. Yəni "state" və "props" bir-birini istisna etmir — state-in özü, aşağıya ötürüləndə, uşaq üçün props-a çevrilir. Bu React-də məlumat axınının "yuxarıdan aşağıya" (top-down / one-way data flow) olmasının səbəbidir.

02 — hook

useState hook-unun sintaksisi

useState — funksional komponentlərə state əlavə etməyə imkan verən React hook-udur. React-dən import olunur və çağırıldıqda iki elementdən ibarət massiv qaytarır: cari dəyər və onu yeniləyən funksiya.

useState-syntax.jsx 
import { useState } from "react";

const [count, setCount] = useState(0);
// count    → cari dəyər (başlanğıcda 0)
// setCount → count-u yeniləmək üçün funksiya
// useState(0) → 0 başlanğıc (ilkin) dəyərdir

Bu massiv-destrukturlaşdırma sintaksisidir. Adları özünüz seçirsiniz — vacib olan sıradır: birinci element həmişə dəyər, ikinci həmişə yeniləyici funksiyadır. Buna görə də konvensiya olaraq [thing, setThing] adlandırma qaydasına əməl olunur: [user, setUser], [isOpen, setIsOpen] və s.

NİYƏ MASSİV, OBYEKT YOX?

Massiv destrukturlaşdırmasında adları istədiyiniz kimi seçə bilirsiniz (const [a, b] = useState(0)), obyekt olsaydı hər dəfə eyni açar adını (məsələn state, setState) istifadə etməli və hər çağırışda yenidən adlandırmalı (renaming) olardınız. Massiv bu baxımdan daha rahatdır.

Bir komponentdə istədiyiniz qədər useState çağıra bilərsiniz — hər biri öz müstəqil state-ini saxlayır:

Profile.jsx 
function Profile() {
  const [name, setName] = useState("Aygün");
  const [age, setAge] = useState(21);
  const [isOnline, setIsOnline] = useState(false);
  // hər useState öz yaddaşını saxlayır, biri digərinə təsir etmir
}

03 — render dövrü

State dəyişəndə nə baş verir?

Yeniləyici funksiyanı (məsələn setCount) çağırdığınız an React üç addım atır:

  1. React yeni dəyəri yadda saxlayır və komponenti "yenilənməli" (dirty) kimi işarələyir
  2. Komponent funksiyası — yeni state dəyəri ilə — yenidən çağırılır (render olunur) və təzə JSX qaytarır
  3. React əvvəlki nəticə ilə yenisini müqayisə edir (bu proses "reconciliation" adlanır) və yalnız real DOM-da fərqlənən hissələri yeniləyir
BÜTÜN TƏTBİQ YENİDƏN RENDER OLUNURMU?

Xeyr. Yalnız state-i dəyişən komponent (və əgər həmin state props kimi uşaqlara ötürülübsə, o uşaq komponentlər) yenidən render olunur. Tətbiqin əlaqəsiz digər hissələri toxunulmaz qalır. Bu React-in effektivliyinin əsas səbəblərindən biridir.

Daha iki vacib detal:

  • Avtomatik batching: React 18-də, bir hadisə handler-i daxilində bir neçə setState çağırılsa belə, React onları bir yerə yığıb tək render icra edir (performans üçün) — hər çağırış ayrıca render yaratmır.
  • Referans müqayisəsi: Massiv və ya obyekt state-i eyni referansla (məsələn state.push(...) ilə) "dəyişsəniz", React bunu dəyişiklik hesab etmir, çünki daxildə səthi (shallow) müqayisə aparılır. Buna görə həmişə yeni massiv/obyekt yaratmaq lazımdır (bunu "Xətalar" bölməsində ətraflı görəcəyik).

04 — hadisələr

Event Handling: onClick, onChange, onSubmit

React-də HTML hadisələri camelCase formatında yazılır: onclick deyil onClick, onchange deyil onChange. Handler kimi bir funksiya referansı ötürülür.

events.jsx 
function LoginForm() {
  const [email, setEmail] = useState("");

  function handleChange(e) {
    setEmail(e.target.value); // e.target.value — input-un cari mətni
  }

  function handleSubmit(e) {
    e.preventDefault(); // səhifənin yenidən yüklənməsinin qarşısını alır
    console.log("Göndərildi:", email);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={email} onChange={handleChange} />
      <button type="submit">Göndər</button>
    </form>
  );
}
ƏN TEZ-TEZ RAST GƏLİNƏN SƏHV

onClick={handleClick} — funksiyanın özünü (referansını) ötürürsən, React onu klik olanda çağıracaq. onClick={handleClick()} — mötərizələr funksiyanı dərhal, render zamanı çağırır, klikə heç bir aidiyyəti olmur. Parametr ötürmək lazım gələndə isə onClick={() => handleClick(id)} kimi anonim ox (arrow) funksiyadan istifadə edin.

onSubmit üçün e.preventDefault() demək olar həmişə vacibdir — əks halda brauzer formu ənənəvi üsulla göndərməyə çalışır və səhifə yenidən yüklənir (React state-i itir).

05 — şərti görüntüləmə

Conditional Rendering

JSX daxilində şərtdən asılı olaraq fərqli məzmun göstərmək üçün üç əsas üsul var:

conditional.jsx 
// 1) && operator — şərt doğrudursa göstər, yoxdursa heç nə
{isLoading && <p>Yüklənir...</p>}

// 2) ternar operator — iki variantdan biri
{isLoggedIn ? <p>Xoş gəldin!</p> : <p>Zəhmət olmasa daxil ol</p>}

// 3) if / else — return-dən əvvəl dəyişəndə və ya
//    komponentin özündə "erkən qayıdış" (early return) kimi
function Status({ isLoading }) {
  if (isLoading) {
    return <p>Yüklənir...</p>;
  }
  return <p>Hazırdır</p>;
}
"0" GÖSTƏRİLMƏSİ TƏLƏSİ

{items.length && <List />} yazsanız və items.length 0 olsa, ekranda "0" rəqəmi görünəcək — boş heç nə deyil! Səbəb: && operatoru sol tərəf falsy olduqda onun özünü qaytarır, JSX isə 0-ı "boş" hesab etmir, ekrana çıxarır. Düzəliş: {items.length > 0 && <List />} və ya ternar operatordan istifadə edin.

06 — siyahılar

List Rendering: .map() istifadəsi

Massivdəki hər elementdən JSX yaratmaq üçün adi JavaScript-in .map() metodundan istifadə olunur — React üçün xüsusi sintaksis yoxdur, sadəcə JSX-i JavaScript ifadəsi kimi {} daxilində qaytarırsınız.

list.jsx 
const fruits = ["alma", "armud", "üzüm"];

<ul>
  {fruits.map((fruit) => (
    <li key={fruit}>{fruit}</li>
  ))}
</ul>

Diqqət yetirin: hər <li>-ə key adlı xüsusi bir prop verilib. Bu, təsadüfi deyil — React bunu tələb edir. Səbəbini növbəti bölmədə açıqlayırıq.

07 — key

key prop-un rolu və niyə vacibdir

key — React-ə siyahıdakı hər elementi unikal şəkildə tanımaqda kömək edən xüsusi prop-dur. React siyahını yenidən render edəndə, əvvəlki və yeni siyahını key dəyərlərinə görə müqayisə edir: hansı element qalıb, hansı silinib, hansı yenidən əlavə olunub — bunu key ilə müəyyən edir. Bu proses "reconciliation" adlanır.

Əgər key verilməsə (və ya səhv seçilsə), React elementləri düzgün izləyə bilmir və nəticədə:

  • Yanlış elementin state-i (məsələn input-un mətni) başqa sıraya "keçə" bilər
  • Lazımsız yenidən render-lər baş verə bilər (performans itkisi)
  • Animasiyalar və fokus (focus) səhv elementə tətbiq oluna bilər
İNDEX-İ KEY KİMİ İSTİFADƏ ETMƏK OLARMI?

Texniki cəhətdən bəli, React sizi məcbur etmir. Amma yalnız bu şərtlərdə təhlükəsizdir: siyahı heç vaxt sıralanmır, ortadan element əlavə/silinmir, siyahı statikdir. Əks halda (əlavə etmə, silmə, sıralama olan hər hansı siyahıda — məsələn to-do list) index key kimi işlədilsə, sıra dəyişəndə React elementləri səhv uyğunlaşdırır. Ən düzgün yol — məlumatın özündəki unikal id-dən istifadə etməkdir.

08 — praktiki hissə

Canlı nümunələr

Aşağıdakı üç nümunə bu səhifədə real React kodu ilə işləyir — kodu oxuyun, sağdakı (və ya aşağıdakı) canlı paneldə sınayın.

1. Sayğac (Counter) app-i

Bu nümunə həm useState-in əsas işləmə məntiqini, həm də köhnə state-ə əsaslanan yeniləmənin (prev => prev + 1) niyə vacib olduğunu canlı göstərir. "+1 × 3 (adi üsul)" düyməsinə basanda nəticənin gözlədiyiniz kimi çıxmadığını görəcəksiniz.

Counter.jsx 
function Counter() {
  const [count, setCount] = useState(0);

  function addOnce() {
    setCount(count + 1);
  }

  function addThreeBad() {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
    // ❌ hər çağırışda eyni "köhnə" count
    // istifadə olunur → nəticədə +1
  }

  function addThreeGood() {
    setCount(prev => prev + 1);
    setCount(prev => prev + 1);
    setCount(prev => prev + 1);
    // ✅ hər dəfə ən son dəyərdən davam edir → +3
  }

  return ( /* ... düymələr ... */ );
}

2. To-Do list-in ilkin versiyası

Yalnız əlavə etmə və silmə funksionallığı — checkbox (tamamlama) hissəsini aşağıdakı tapşırıqda özünüz əlavə edəcəksiniz. Diqqət: siyahı .map() ilə render olunur və hər elementə unikal id əsasında key verilir.

TodoApp.jsx 
function TodoApp() {
  const [todos, setTodos] = useState([
    { id: 1, text: "React state-i öyrən" },
  ]);
  const [value, setValue] = useState("");

  function handleSubmit(e) {
    e.preventDefault();
    if (value.trim() === "") return;
    setTodos(prev => [
      ...prev,
      { id: Date.now(), text: value.trim() },
    ]);
    setValue("");
  }

  function handleDelete(id) {
    setTodos(prev => prev.filter(t => t.id !== id));
  }

  return ( /* form + todos.map(...) */ );
}

function LoadingDemo() {
  const [loading, setLoading] = useState(false);

    setLoading(true);
    setResult(null);
    setTimeout(() => {
      setLoading(false);
      setResult("Məlumat uğurla yükləndi ✓");
    }, 1400);
  }

  return ( /* button + conditional mesajlar */ );
}

09 — tapşırıq

Tapşırıq: İşarələnə bilən (checkbox) tapşırıq siyahısı

Yuxarıdakı To-Do list nümunəsini əsas götürərək, hər tapşırığın tamamlanıb-tamamlanmadığını izləyən funksionallıq əlavə edin:

  1. Hər todo obyektinə done: false sahəsi əlavə edin.
  2. Hər sətrin əvvəlinə bir <input type="checkbox"> qoyun. Checkbox-un checked dəyəri todo-nun done sahəsindən asılı olmalıdır (controlled input).
  3. Checkbox dəyişəndə (onChange) yalnız uyğun id-yə malik todo-nun done sahəsini əks etdirin — qalan todo-lara toxunmadan, immutable şəkildə (yəni .map() və spread operator {'{'}...{'}'} ilə, birbaşa mutasiya etmədən).
  4. Tamamlanmış tapşırıqları vizual olaraq fərqləndirin — məsələn üstündən xətt (text-decoration: line-through) və solğun rəng.
  5. Bonus: Üç filtr düyməsi əlavə edin — "Hamısı", "Aktiv", "Tamamlanmış" — və yalnız uyğun tapşırıqları göstərin.BONUS
  6. Bonus: Neçə aktiv tapşırığın qaldığını göstərən sayğac əlavə edin (məsələn "3 tapşırıq qalıb").BONUS

10 — tipik xətalar

Tez-tez rast gəlinən xətalar və bug-lar

Bu bölmədə başlanğıc səviyyəsində ən çox rast gəlinən 6 xətanı — səbəbi və düzəlişi ilə birlikdə — nəzərdən keçiririk.

01

State-i birbaşa mutasiya etmək

❌ SƏHV
todos.push(newTodo);
setTodos(todos);
✅ DÜZGÜN
setTodos(prev =>
  [...prev, newTodo]
);
React referansa görə müqayisə aparır. Eyni massivi birbaşa dəyişsəniz, referans eyni qalır və React dəyişikliyi görmür — komponent yenidən render olunmur. Həmişə yeni massiv/obyekt yaradın.
02

Ardıcıl setState çağırışlarında köhnə (stale) dəyərdən istifadə

❌ SƏHV — nəticə +1
setCount(count + 1);
setCount(count + 1);
setCount(count + 1);
✅ DÜZGÜN — nəticə +3
setCount(p => p + 1);
setCount(p => p + 1);
setCount(p => p + 1);
Hər üç çağırış da eyni render-in count dəyişənini "yaddaşa alır" (closure). Funksional yeniləmə (prev => ...) isə React-in növbədəki ən son dəyərindən davam edir.
03

Funksiyanı render zamanı çağırmaq

❌ SƏHV
<button onClick={
  handleClick()
}>
✅ DÜZGÜN
<button onClick={
  handleClick
}>
Mötərizələr funksiyanı dərhal çağırır — klikə görə deyil, hər render-də. Əgər handleClick daxilində setState varsa, bu sonsuz render dövrünə (infinite loop) səbəb ola bilər.
04

onSubmit-də preventDefault unudulması

❌ SƏHV
function handleSubmit(e) {
  saveTodo();
}
✅ DÜZGÜN
function handleSubmit(e) {
  e.preventDefault();
  saveTodo();
}
Brauzerin standart form davranışı səhifəni yenidən yükləyir — bu zaman bütün React state-i sıfırlanır. e.preventDefault() bunun qarşısını alır.
05

Dinamik siyahılarda index-i key kimi istifadə etmək

❌ RİSKLİ
{todos.map((t, i) => (
  <li key={i}>...</li>
))}
✅ DÜZGÜN
{todos.map((t) => (
  <li key={t.id}>...</li>
))}
Siyahının ortasına əlavə/silmə olduqda index-lər sürüşür, React elementləri səhv uyğunlaşdırır (məsələn input-lardakı mətn səhv sətirdə qalır). Unikal id istifadə edin.
06

&& ilə "0" göstərilməsi

❌ SƏHV (0 olanda "0" çıxır)
{items.length &&
  <List items={items} />}
✅ DÜZGÜN
{items.length > 0 &&
  <List items={items} />}
0 JSX-də "boş" sayılmır, ekranda göstərilir. Şərti həmişə açıq boolean ifadəyə çevirin (length > 0) və ya ternar operatordan istifadə edin.

11 — tövsiyələr

Nələri etsək daha yaxşı olar?

✓

State-i minimal saxlayın

Yalnız zamanla dəyişən və başqa dəyərlərdən hesablana bilməyən məlumatı state edin. Başqa state-dən hesablana bilən dəyəri (məsələn cəm, filtrlənmiş siyahı) ayrıca state kimi saxlamayın — render zamanı hesablayın.

✓

State-i mümkün qədər aşağı səviyyədə saxlayın

State-i yalnız ona ehtiyacı olan komponentdə saxlayın. Bir neçə komponent arasında paylaşmaq lazım gələndə, state-i onların ortaq valideynə "qaldırın" (lifting state up).

✓

Immutable yeniləmə naxışına əməl edin

Massiv və obyektləri həmişə spread operator (...) ilə yeni nüsxə şəklində yeniləyin — heç vaxt birbaşa mutasiya etməyin.

✓

Köhnə state-dən asılı yeniləmələrdə funksional forma işlədin

Yeni dəyər köhnə dəyərdən asılıdırsa, həmişə setState(prev => ...) formasını seçin — xüsusilə ardıcıl və ya sürətli çağırışlarda.

✓

Unikal və sabit key-lərdən istifadə edin

Siyahı elementləri üçün mümkün qədər verilənlərin öz id-sini işlədin — index-dən yalnız siyahı tamamilə statikdirsə istifadə edin.

✓

Handler funksiyalarını aydın adlandırın

handleClick, handleChange, handleSubmit kimi handle prefiksli adlandırma konvensiyası kodu daha oxunaqlı edir.

12 — tez-tez verilən suallar

FAQ

?key niyə mütləqdir, index-i key kimi istifadə etmək olarmı?

key React-ə siyahıda hansı elementin "kim olduğunu" deyir — bu, React-in reconciliation zamanı elementləri düzgün uyğunlaşdırması üçün vacibdir. Key olmadan (və ya səhv key ilə) React elementləri yalnız mövqeyinə görə uyğunlaşdırmağa çalışır ki, bu da səhv nəticələrə (input-larda mətnin qarışması, yanlış animasiya, lazımsız yenidən render) səbəb ola bilər.

İndex-i key kimi istifadə etmək texniki olaraq mümkündür və React heç bir xəbərdarlıq vermədən qəbul edir, amma yalnız aşağıdakı şərtlərin hamısı doğrudursa təhlükəsizdir: siyahı heç vaxt yenidən sıralanmır, elementlər ortadan əlavə/silinmir, siyahı tamamilə statikdir. Dinamik siyahılarda (to-do list kimi) isə həmişə verilənin öz unikal id-sindən istifadə edin — Date.now(), backend-dən gələn id, və ya crypto.randomUUID() kimi.

?State dəyişəndə bütün komponent yenidən render olunurmu?

"Bütün komponent" dedikdə iki şeyi ayırmaq lazımdır. Birincisi — həmin komponentin özü tam yenidən render olunur, yəni funksiyası başdan-başa yenidən icra olunur (bu normaldır və gözləniləndir). İkincisi — bütün tətbiq yenidən render olunmur; yalnız state-i dəyişən komponent və (əgər state ona props kimi ötürülübsə) onun uşaq komponentləri təsirlənir. Əlaqəsi olmayan digər komponentlər toxunulmaz qalır.

Əlavə olaraq, "yenidən render olunmaq" o demək deyil ki, real DOM da tam yenidən yazılır. React əvvəlcə virtual müqayisə aparır (reconciliation) və yalnız faktiki dəyişən DOM hissələrini yeniləyir — bu, performans baxımından vacib fərqdir.

?useState-də köhnə state-ə əsaslanaraq yeniləmə necə düzgün edilir?

Yeni dəyər köhnə dəyərdən asılıdırsa (məsələn "cari say + 1"), yeniləyici funksiyaya birbaşa dəyər əvəzinə funksiya ötürün: setCount(prev => prev + 1). React bu funksiyanı ən son, yeniləyici olan state dəyəri ilə çağırır — bu, xüsusilə eyni event handler daxilində bir neçə dəfə çağırış olanda (yuxarıdakı Sayğac nümunəsindəki kimi) fərqi göstərir.

setCount(count + 1) yazsanız, count həmin render-in closure-da "dondurulmuş" dəyəridir — React state-i faktiki yeniləyənə qədər dəyişmir. Ona görə də ardıcıl bir neçə çağırış eyni köhnə dəyərdən istifadə edir və gözlənilən nəticəni vermir. Qayda sadədir: yeni dəyər köhnə dəyərdən asılıdırsa → funksional forma işlədin.

Dərs 3 tamamlandı — indi state, useState və event handling artıq alətlər qutunuzdadır. Növbəti addım: bu bilikləri Tapşırıq bölməsindəki checkbox to-do list ilə möhkəmləndirin.
