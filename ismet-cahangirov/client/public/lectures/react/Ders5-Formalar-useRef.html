Formalar, Controlled Components və useRef

İstifadəçidən məlumat almaq React tətbiqlərinin ən çox rast gəlinən vəzifələrindən biridir. Bu dərsdə form dəyərlərini state ilə necə idarə edəcəyimizi, real-vaxtda validasiya aparmağı və DOM elementlərinə useRef vasitəsilə birbaşa müraciət etməyi addım-addım öyrənəcəyik.

⏱ ≈2 saat
🎯 Səviyyə: Orta
🧩 Praktiki tapşırıq: Login forması
📦 Tələb olunur: useState biliyi
01

Controlled vs Uncontrolled Input

React-də form elementləri (input, textarea, select) iki cür idarə oluna bilər: controlled (nəzarət olunan) və uncontrolled (nəzarətsiz). Bu fərq bütün form işinin təməlidir.

▸ Controlled Input

Controlled input-da elementin dəyəri (value) tamamilə React state-dən gəlir. İstifadəçi nə yazırsa yazsın, DOM özü heç nə "yadda saxlamır" — hər dəyişiklik onChange vasitəsilə state-ə ötürülür, state yenilənir, React isə yeni dəyəri yenidən input-a "geri qaytarır". Yəni React "yeganə həqiqət mənbəyi" (single source of truth) rolunu oynayır.

ControlledInput.jsx
function ControlledInput() {
  const [ad, setAd] = useState("");

  const handleChange = (e) => {
    setAd(e.target.value);
  };

  return (
    <input
      type="text"
      value={ad}
      onChange={handleChange}
      placeholder="Adınızı daxil edin"
    />
  );
}

▸ Uncontrolled Input

Uncontrolled input-da dəyər DOM-un öz daxili yaddaşında saxlanılır — brauzer bunu özü idarə edir. React yalnız lazım olduqda (məsələn, submit anında) useRef vasitəsilə həmin dəyəri "gedib oxuyur". Real-vaxt validasiya və ya şərti məntiq üçün əlverişli deyil, çünki hər simvol dəyişəndə React xəbərdar olmur.

UncontrolledInput.jsx
function UncontrolledInput() {
  const inputRef = useRef(null);

  const handleSubmit = () => {
    // Dəyəri yalnız lazım olanda DOM-dan oxuyuruq
    alert(`Daxil edilən dəyər: ${inputRef.current.value}`);
  };

  return (
    <>
      <input type="text" ref={inputRef} defaultValue="" />
      <button onClick={handleSubmit}>Göstər</button>
    </>
  );
}

Qayda

Ümumi tövsiyə: form validasiyası, şərti göstərmə (bir sahə digərindən asılıdırsa) və ya dəyəri kənardan dəyişmək lazımdırsa — controlled yanaşmadan istifadə edin. Yalnız DOM-a bir dəfəlik müraciət (məsələn fokuslanma, fayl seçimi) lazımdırsa — uncontrolled + useRef kifayətdir.

02

Formun state ilə idarə olunması

Formda bir neçə sahə olduqda, onları necə saxlamaq lazımdır: hər biri üçün ayrıca useState, yoxsa bir obyekt daxilində?

▸ Yanaşma 1: Ayrı-ayrı state

separate-state.jsx
const [ad, setAd] = useState("");
const [email, setEmail] = useState("");
const [parol, setParol] = useState("");

// Hər input üçün ayrı onChange handler lazımdır
<input value={ad} onChange={(e) => setAd(e.target.value)} />
<input value={email} onChange={(e) => setEmail(e.target.value)} />
<input value={parol} onChange={(e) => setParol(e.target.value)} />

2–3 sahəlik kiçik formalarda bu yanaşma sadə və oxunaqlıdır. Amma sahələrin sayı artdıqca (4, 5, 10 sahə) kod təkrarlanmağa başlayır.

▸ Yanaşma 2: Tək obyekt (tövsiyə olunur)

object-state.jsx
const [form, setForm] = useState({
  ad: "",
  email: "",
  parol: "",
});

// Bir universal handler bütün sahələr üçün işləyir
const handleChange = (e) => {
  const { name, value } = e.target;
  setForm((prev) => ({ ...prev, [name]: value }));
};

<input name="ad" value={form.ad} onChange={handleChange} />
<input name="email" value={form.email} onChange={handleChange} />
<input name="parol" value={form.parol} onChange={handleChange} type="password" />

Burada hər input-un name atributu state obyektindəki açarla (key) uyğun gəlir. Bu üsul, sahə sayı artsa belə, yalnız bir handleChange funksiyası ilə idarə olunmasını təmin edir — kod təkrarlanmır və genişlənməsi asandır.

⚠️
Diqqət: spread operatoru unutmayın

setForm({ [name]: value }) yazsanız, digər bütün sahələr itiriləcək! Həmişə { ...prev, [name]: value } şəklində əvvəlki state-i qoruyun.

03

Form validasiyası prinsipləri

Validasiya iki əsas mərhələdən ibarətdir: boş sahə yoxlanışı və format yoxlanışı. Bunlara əlavə olaraq, validasiyanın nə vaxt göstərilməsi də UX baxımından vacibdir.

▸ 1. Boş sahə yoxlanışı

Sahənin doldurulub-doldurulmadığını yoxlamaq üçün .trim() istifadə edilir ki, yalnız boşluqlardan ibarət dəyər də "boş" hesab olunsun.

▸ 2. Format yoxlanışı

E-poçt, telefon nömrəsi kimi sahələr üçün müəyyən formata uyğunluq regular expression (regex) ilə yoxlanılır.

validate.js
const EMAIL_REGEX = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

function validateField(name, value) {
  switch (name) {
    case "email":
      if (!value.trim()) return "E-poçt tələb olunur";
      if (!EMAIL_REGEX.test(value)) return "E-poçt formatı yanlışdır";
      return "";

    case "parol":
      if (!value) return "Parol tələb olunur";
      if (value.length < 6) return "Parol ən azı 6 simvol olmalıdır";
      return "";

    default:
      return "";
  }
}

▸ 3. Validasiyanın vaxtlaması (UX üçün vacibdir)

Xətanı istifadəçi hələ ilk dəfə yazarkən göstərmək pis təcrübədir — insan "e" hərfini yazan kimi "E-poçt formatı yanlışdır" görmək istəməz. Ən yaxşı praktika:

MərhələNə baş verir
İlk yazı zamanıXəta göstərilmir, sahə sadəcə doldurulur
onBlur (fokus itəndə)Sahə ilk dəfə yoxlanılır, lazım olsa xəta görünür
Xəta göründükdən sonraonChange zamanı davamlı yenidən yoxlanılır ki, düzələn kimi xəta yox olsun

04

useRef Hook

useRef — React-in DOM elementinə birbaşa müraciət etmək və ya render-lər arasında saxlanan, lakin UI-ni yeniləməyən dəyər saxlamaq üçün istifadə etdiyi hook-dur.

syntax.jsx
const myRef = useRef(initialValue);
// myRef = { current: initialValue }

// DOM elementinə bağlamaq üçün:
<input ref={myRef} />

// Dəyərə müraciət:
myRef.current // → DOM node və ya saxlanan dəyər

useRef(initialValue) { current: initialValue } formasında bir obyekt qaytarır. Bu obyekt komponentin bütün "ömrü" boyu eyni referans olaraq qalır — yəni hər render-də yenidən yaradılmır.

▸ Nümunə: input-a avtomatik fokuslanma

AutoFocusInput.jsx
function AutoFocusInput() {
  const emailRef = useRef(null);

  useEffect(() => {
    // Komponent ilk dəfə render olunanda inputa fokuslanır
    emailRef.current.focus();
  }, []);

  return <input ref={emailRef} type="email" placeholder="E-poçt" />;
}
📌
useRef nə üçün istifadə olunur?

1) DOM elementinə birbaşa müraciət — fokus, scroll, ölçü ölçmə (getBoundingClientRect).
2) Render-lər arasında "yaddaş" saxlamaq — məsələn əvvəlki dəyəri, timer ID-ni və ya sayğacı, bunlar UI-də göstərilmədiyi üçün useState lazım deyil.
3) Mutable (dəyişən) dəyər saxlamaq — dəyəri dəyişmək render tələb etmir.

Bu iki hook tez-tez qarışdırılır, çünki hər ikisi dəyər "saxlayır". Amma məqsədləri tamamilə fərqlidir.

06

Praktiki: Çoxsahəli qeydiyyat forması

İndi bütün öyrəndiklərimizi birləşdirib real-vaxt validasiyalı, useRef ilə avtomatik fokuslanan tam qeydiyyat forması quraq.

RegisterForm.jsx
import { useState, useRef, useEffect } from "react";

const EMAIL_REGEX = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

function validateField(name, value, form) {
  switch (name) {
    case "ad":
      return value.trim() ? "" : "Ad tələb olunur";
    case "email":
      if (!value.trim()) return "E-poçt tələb olunur";
      if (!EMAIL_REGEX.test(value)) return "E-poçt formatı yanlışdır";
      return "";
    case "parol":
      if (!value) return "Parol tələb olunur";
      if (value.length < 6) return "Parol ən azı 6 simvol olmalıdır";
      return "";
    case "parolTekrar":
      if (!value) return "Parolu təkrar daxil edin";
      if (value !== form.parol) return "Parollar uyğun gəlmir";
      return "";
    default:
      return "";
  }
}

export default function RegisterForm() {
  const [form, setForm] = useState({ ad: "", email: "", parol: "", parolTekrar: "" });
  const [errors, setErrors] = useState({});
  const [touched, setTouched] = useState({});
  const adRef = useRef(null);

  useEffect(() => {
    adRef.current.focus(); // Səhifə açılanda ilk sahəyə fokuslan
  }, []);

  const handleChange = (e) => {
    const { name, value } = e.target;
    const updatedForm = { ...form, [name]: value };
    setForm(updatedForm);

    // Xəta artıq göstərilibsə, hər yazışda yenidən yoxla
    if (touched[name]) {
      setErrors((prev) => ({ ...prev, [name]: validateField(name, value, updatedForm) }));
    }
  };

  const handleBlur = (e) => {
    const { name, value } = e.target;
    setTouched((prev) => ({ ...prev, [name]: true }));
    setErrors((prev) => ({ ...prev, [name]: validateField(name, value, form) }));
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    const newErrors = {};
    Object.keys(form).forEach((key) => {
      newErrors[key] = validateField(key, form[key], form);
    });
    setErrors(newErrors);
    setTouched({ ad: true, email: true, parol: true, parolTekrar: true });

    const hasError = Object.values(newErrors).some((msg) => msg !== "");
    if (!hasError) {
      alert("Qeydiyyat uğurludur!");
    }
  };

  return (
    <form onSubmit={handleSubmit} noValidate>
      <input
        ref={adRef}
        name="ad"
        value={form.ad}
        onChange={handleChange}
        onBlur={handleBlur}
        placeholder="Ad Soyad"
      />
      {touched.ad && errors.ad && <span className="error">{errors.ad}</span>}

      <input
        name="email"
        value={form.email}
        onChange={handleChange}
        onBlur={handleBlur}
        placeholder="E-poçt"
      />
      {touched.email && errors.email && <span className="error">{errors.email}</span>}

      <input
        type="password"
        name="parol"
        value={form.parol}
        onChange={handleChange}
        onBlur={handleBlur}
        placeholder="Parol"
      />
      {touched.parol && errors.parol && <span className="error">{errors.parol}</span>}

      <input
        type="password"
        name="parolTekrar"
        value={form.parolTekrar}
        onChange={handleChange}
        onBlur={handleBlur}
        placeholder="Parolu təkrarlayın"
      />
      {touched.parolTekrar && errors.parolTekrar && <span className="error">{errors.parolTekrar}</span>}

      <button type="submit">Qeydiyyatdan keç</button>
    </form>
  );
}
🔍
Diqqət edin

touched obyekti hər sahənin "toxunulub-toxunulmadığını" izləyir — beləliklə xətalar yalnız istifadəçi həmin sahədən çıxdıqdan (blur) sonra göstərilir, ilk yazı zamanı yox.

07

Tapşırıq: Login forması

Öyrəndiklərinizi tətbiq etmək üçün aşağıdakı tapşırığı yerinə yetirin.

🎯 Praktiki Tapşırıq

Email və parol validasiyalı Login forması qurun

  • İki controlled input yaradın: email və parol, bir obyekt state-də saxlayın.
  • Email formatını regex ilə yoxlayın; boşdursa və ya format yanlışdırsa müvafiq xəta mesajı göstərin.
  • Parolun boş olmadığını və minimum 6 simvoldan ibarət olduğunu yoxlayın.
  • Xəta mesajları real-vaxtda (onBlur-dan sonra onChange ilə) yenilənməlidir.
  • Submit düyməsini yalnız form tam düzgün doldurulanda aktiv edin (disabled atributu ilə).
  • useRef istifadə edərək səhifə açılan kimi email sahəsinə avtomatik fokuslanma edin.
  • Form göndəriləndə e.preventDefault() çağırmağı unutmayın.
Bonus: useRef ilə "parolu göstər/gizlət" düyməsi əlavə edin — düyməyə basanda parol input-unun type atributunu "password" ↔ "text" arasında dəyişdirin.
08

Ola biləcək xətalar və buglar

Formalarla işləyərkən başlanğıc səviyyədə tez-tez rast gəlinən problemlər və onların həlli.

⚠ Warning: A component is changing an uncontrolled input to be controlled

Başlanğıc dəyər olmadan controlled input

Əgər state-in başlanğıc dəyəri undefined olarsa (məsələn useState()), input əvvəlcə uncontrolled başlayır, sonra dəyər yazılanda controlled olur — React bu barədə xəbərdarlıq verir.

Həll: Həmişə başlanğıc dəyəri boş sətir olaraq təyin edin: useState("").
⚠ Səhifə submit zamanı yenilənir

e.preventDefault() unudulub

Form submit hadisəsi standart olaraq brauzeri səhifəni yeniləməyə vadar edir, bu da bütün React state-ini sıfırlayır.

Həll: handleSubmit funksiyasının ilk sətrində mütləq e.preventDefault() çağırın.
⚠ Cannot read properties of null (reading 'focus')

ref.current-ə render zamanı müraciət

Komponent hələ DOM-a "mount" olunmamış vaxt ref.current hələ null-dur. Render funksiyası daxilində birbaşa ref.current.focus() çağırmaq xətaya səbəb olur.

Həll: DOM-a müraciəti yalnız useEffect içində və ya hadisə handler-lərində (məsələn onClick) edin.
⚠ State düzgün yenilənmir

name atributu unudulub

Generic handleChange funksiyası e.target.name-dən istifadə edir. Əgər input-a name atributu verilməyibsə, bu dəyər undefined olacaq və state-də səhv açar yaranacaq.

Həll: Obyekt-əsaslı state istifadə edərkən hər input-a state-dəki açarla eyni name verməyi vərdiş edin.
⚠ Checkbox işləmir / həmişə eyni qalır

value əvəzinə checked lazımdır

Checkbox input-larda value yox, checked atributu istifadə olunmalıdır — əks halda checkbox real vəziyyəti əks etdirmir.

Həll: <input type="checkbox" checked={form.qebul} onChange={...} />
⚠ Pis UX: aqressiv xəta göstərmə

Hər simvolda xəta göstərmək

Real-vaxt validasiyanı ilk yazı anından aktiv etmək istifadəçini əsəbləşdirir — hələ sözü bitirməmiş "yanlış format" görmək qıcıqlandırıcıdır.

Həll: touched state ilə izləyin, xətanı yalnız sahədən blur olduqdan sonra göstərin.
⚠ Ekran yenilənmir, amma dəyər dəyişib

useRef-i UI göstərmək üçün istifadə etmək

ref.current dəyişəndə component yenidən render olunmur. Əgər həmin dəyəri ekranda göstərmək lazımdırsa, useRef bu iş üçün yanlış vasitədir.

Həll: Ekranda göstəriləcək hər hansı dəyər üçün useState istifadə edin, useRef-i yalnız "görünməz" datalar üçün saxlayın.
⚠ Köhnə (stale) dəyər istifadə olunur

setTimeout/closure daxilində köhnə state

setTimeout və ya asinxron funksiya daxilində istinad edilən state dəyəri, funksiya yaradıldığı andakı "donmuş" dəyərdir — sonradan state dəyişsə belə yenilənmir.

Həll: Ən son dəyərə ehtiyac varsa, ya funksional yeniləmə (setState(prev => ...)) istifadə edin, ya da lazım gələrsə useRef ilə ən son dəyəri paralel saxlayın.
09

Nələri etsək daha yaxşı olar

Formanı daha keyfiyyətli, əlçatan (accessible) və performanslı etmək üçün tövsiyələr.

1

Validasiya funksiyasını komponentdən çıxarın

Validasiya məntiqini komponent daxilində deyil, ayrıca fayl/funksiya kimi yazın ki, hər render-də yenidən yaradılmasın və test etmək asan olsun.

2

Custom hook — useForm

Təkrarlanan form məntiqini (state, handleChange, validasiya) öz useForm() hook-unuza çıxarın ki, digər formalarda yenidən istifadə edə biləsiniz.

3

Əlçatanlıq (accessibility)

Xəta mesajlarına aria-live="polite" əlavə edin ki, ekran oxuyucuları (screen reader) xətanı avtomatik səsləndirsin.

4

Submit düyməsini şərtləndirin

Form tam düzgün doldurulmayıbsa, submit düyməsini disabled edin — istifadəçi səhv göndərişdən qorunsun.

5

Debounce ilə optimizasiya

Əgər validasiya server sorğusu tələb edirsə (məsələn, e-poçtun artıq mövcudluğunu yoxlamaq), hər simvolda deyil, yazı dayandıqdan sonra (debounce) sorğu göndərin.

6

Başlanğıc dəyərləri həmişə təyin edin

Controlled input-larda başlanğıc state dəyəri heç vaxt undefined olmamalıdır — həmişə "", 0 və ya false kimi konkret dəyər verin.

7

Parol sahələrinə diqqət

Parolu heç vaxt console.log etməyin və ya lazımsız yerə state-də uzun müddət saxlamayın; type="password" istifadəsini qoruyun.

8

Böyük formalar üçün kitabxana düşünün

Formada 8-10-dan çox sahə, mürəkkəb şərti validasiya varsa, react-hook-form kimi hazır həllər kodu xeyli sadələşdirir.

10

Tez-tez verilən suallar

useRef state kimi render-ə səbəb olurmu?

+

Xeyr. useRef-in .current dəyəri dəyişəndə component yenidən render olunmur. Bu, useState-dən fərqli olaraq, useRef-i UI-yə birbaşa bağlı olmayan dəyərlər üçün ideal edir — DOM node referansı, timer ID, əvvəlki render-in dəyəri və s.

Əgər dəyişiklik nəticəsində ekranda nəsə görünməli, yenilənməlidirsə (mətn, say, sinif adı və s.) — useState istifadə etmək lazımdır, çünki yalnız state dəyişikliyi React-ə "yenidən render et" siqnalı verir.

Nə üçün controlled input-lar üstünlük təşkil edir?

+

Controlled input-lar React state-i ilə tam sinxrondur, buna görə:

• Real-vaxt validasiya və xəta mesajları asanlıqla həyata keçirilir.
• Bir sahənin dəyəri digərinə görə şərti dəyişə bilər (məsələn parol təkrarı yoxlanışı).
• Dəyəri proqram daxilində sıfırlamaq, formatlamaq və ya əvvəlcədən doldurmaq sadədir.
• Komponentin davranışını test etmək daha asandır, çünki hər şey state üzərindən idarə olunur.

Uncontrolled yanaşma daha az kod tələb edir, amma bu üstünlüklərin əksəriyyətini itirir.

Formda hər inputu ayrı state kimi saxlamaq, yoxsa bir obyektdə?

+

Kiçik formalarda (2–3 sahə) ayrı-ayrı useState çağırışları sadə və başa düşüləndir.

Orta və böyük formalarda (4+ sahə), xüsusilə sahələr bir-birindən asılıdırsa və ya dinamik siyahı təşkil edirsə, tək obyekt + generic handleChange daha təmiz, genişlənə bilən və az təkrarlanan kod verir. Çox mürəkkəb hallarda (çoxlu qarşılıqlı asılılıq) useReducer hook-u da nəzərdən keçirilə bilər.
