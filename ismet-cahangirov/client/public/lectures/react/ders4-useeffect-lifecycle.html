useEffect və Komponent Lifecycle

Hər React komponentinin bir həyatı var: doğulur (mount), yaşayır və dəyişir (update), sonra da səhnəni tərk edir (unmount). useEffect məhz bu üç anla danışmağınız üçün olan hook-dur.

MOUNT UPDATE UNMOUNT
01

Lifecycle anlayışı: mount, update, unmount

Nəzəri hissə

Hər React komponenti ekranda üç mərhələdən keçir. Bu mərhələləri bir insanın həyat dövrü kimi düşünə bilərsiniz — doğulur, yaşayır, gedir. React də komponentin bu üç anını izləyir və sizə həmin anlarda kod işə salmaq imkanı verir.

MərhələNə vaxt baş verirReal həyat nümunəsi
MountKomponent ilk dəfə DOM-a əlavə olunur (ekranda ilk dəfə görünür)Səhifəni açırsınız, komponent "doğulur"
UpdateKomponentin state və ya props-u dəyişir, komponent yenidən render olunurDüyməyə basırsınız, say dəyişir, ekran yenilənir
UnmountKomponent DOM-dan silinir (ekrandan yox olur)Başqa səhifəyə keçirsiniz, komponent "gedir"

Köhnə class komponentlərdə bu mərhələlər üçün ayrıca metodlar var idi: componentDidMount, componentDidUpdate, componentWillUnmount. Funksional komponentlərdə isə bütün bunları bir tək hook — useEffect idarə edir. Fərq isə ondadır ki, hansı mərhələdə işləyəcəyini siz dependency array vasitəsilə təyin edirsiniz (aşağıda 03-cü bölmədə).

💡 ANALOGIYA

useEffect-i bir "gözətçi" kimi düşünün: o, komponentin render olunmasından SONRA işə düşür və sizə deyir — "render bitdi, indi əlavə iş görə bilərsən" (API çağırışı, timer qurmaq, DOM-a birbaşa müdaxilə etmək və s.).

02

useEffect hook-unun sintaksisi

useEffect iki arqument qəbul edir: bir callback funksiya (effektin özü) və bir dependency array (nə vaxt işə düşəcəyini müəyyən edən siyahı).

SİNTAKSİS
useEffect(() => {
  // 1️⃣ Bu hissə "effekt" — render-dən sonra icra olunan kod
  console.log('Komponent render oldu');

  return () => {
    // 2️⃣ Bu hissə "cleanup" — növbəti effektdən əvvəl və ya unmount-da işə düşür
    console.log('Təmizlik aparılır');
  };
}, [dependency1, dependency2]); // 3️⃣ Dependency array
HissəNədir
() => { ... }Effekt funksiyası — DOM güncəlləndikdən sonra işə düşən kod
return () => { ... }İstəyə bağlı cleanup funksiyası (məcburi deyil, amma çox vaxt lazımdır)
[dependency1, dependency2]Effektin hansı state/props dəyişəndə yenidən işə düşəcəyini göstərən massiv
⚠️ DİQQƏT

Effekt funksiyası heç vaxt birbaşa async ola bilməz (useEffect(async () => {...}) — bu, React-in gözlədiyi cleanup funksiyası yerinə bir Promise qaytarır və xəbərdarlıq yaradır). Async məntiq lazımdırsa, effekt daxilində ayrıca async funksiya yazıb onu çağırmaq lazımdır. Bunu 06-cı bölmədə görəcəyik.

03

Dependency array-in üç variantı

Bu, useEffect-in ən vacib — və ən çox səhv edilən — hissəsidir.

1BOŞ ARRAY []
useEffect(() => {
  console.log('Yalnız MOUNT zamanı');
}, []); // boş array
2DOLU ARRAY [dep]

  console.log('count dəyişəndə');
}, [count]); // konkret dependency

  console.log('HƏR render-dən sonra');
}); // ikinci arqument yoxdur
Variantİşə düşmə tezliyiNə vaxt istifadə olunur

[dep] Dolu arrayMount zamanı + dep dəyişəndəProp dəyişəndə yeni data çəkmək (məs. userId dəyişəndə istifadəçini yenidən yükləmək)

🐞 ƏN ÇOX RASTLANAN SƏHV

Array-i tamamilə unutmaq (heç yazmamaq) ilə boş array [] yazmaq tamam fərqli davranışlardır. Bunun fərqini 09-cu bölmədəki suallarda ətraflı izah edirik.

04

Cleanup funksiyası (return içində)

Effekt funksiyasının içindən bir funksiya return etsəniz, React onu "cleanup" (təmizləmə) funksiyası hesab edir. Bu, açdığınız hər şeyi (timer, event listener, subscription) bağlamaq üçündür — əks halda "yaddaş sızması" (memory leak) yaranır.

setInterval + CLEANUP
useEffect(() => {
  const id = setInterval(() => {
    console.log('tick');
  }, 1000);

  return () => {
    clearInterval(id); // komponent silinəndə interval-ı dayandırırıq
  };
}, []);

Cleanup dəqiq nə vaxt işə düşür? İki halda:

HadisəCleanup işə düşürmü?
Komponent unmount olur (ekrandan silinir)✅ Bəli — son dəfə
Dependency array-dəki dəyər dəyişir (yeni effekt işə düşməzdən əvvəl)✅ Bəli — köhnə effekti "yığışdırmaq" üçün
Boş array [] ilə komponent yenidən render olunur❌ Xeyr — effekt heç vaxt təkrar işə düşmür, deməli cleanup da yalnız unmount-da çağırılır
💡 Vizual ardıcıllıq

Mount → Effekt işləyir → (dep dəyişir) → Cleanup (köhnə) → Effekt yenidən işləyir (yeni) → ... → Unmount → Cleanup (son dəfə). Cleanup həmişə "növbəti effektdən bir addım əvvəl" gəlir.

05

Class metoduuseEffect ekvivalenti

componentWillUnmount()useEffect(() => { return () => {...} }, []) — return edilən hissə
Hər üçü ayrı-ayrı yazılırdıBir useEffect daxilində birləşir — hətta bir komponentdə bir neçə useEffect yaza bilərsiniz, hər biri öz məsələsinə cavabdehdir
💡 NİYƏ BU DAHA YAXŞIDIR?

Class komponentlərdə əlaqəli məntiq (məs. bir subscription-un həm qoşulması, həm də söndürülməsi) iki fərqli metoda bölünmüş olurdu. useEffect-də isə eyni məntiq bir yerdə — həm qoşulma, həm söndürülmə (cleanup) — birgə yazılır. Bu, kodu oxumağı və saxlamağı asanlaşdırır.

06

Komponent yüklənəndə API çağırışının simulyasiyası

Praktiki hissə

Ən çox rast gəlinən nümunə: komponent ekrana çıxanda serverdən data çəkmək. userId dəyişəndə isə yeni istifadəçini yenidən yükləmək lazımdır.

USERPROFILE.JSX
function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    let isCancelled = false; // ləğv etmə bayrağı
    setLoading(true);

    async function loadUser() {
      const data = await fetchUser(userId); // simulyasiya olunmuş API
      if (!isCancelled) {
        setUser(data);
        setLoading(false);
      }
    }

    loadUser();

    return () => {
      isCancelled = true; // komponent silinərsə və ya userId dəyişərsə
    };
  }, [userId]); // userId dəyişəndə yenidən işə düşür

  if (loading) return <p>Yüklənir...</p>;
  return <h2>{user.name}</h2>;
}
⚠️ NİYƏ isCancelled LAZIMDIR?

Təsəvvür edin userId tez-tez dəyişir (məs. istifadəçi siyahıda sürətlə klikləyir). Əvvəlki sorğu hələ tamamlanmamış ola bilər, amma artıq köhnəlib. isCancelled bayrağı həmin köhnə nəticənin state-i səhv yeniləməsinin qarşısını alır — bunu 10-cu bölmədə "yarış vəziyyəti" kimi ətraflı görəcəyik.

07

Timer/interval yaradıb cleanup ilə təmizləmə

Aşağıdakı panel real komponent lifecycle-ını simulyasiya edir — düymələrə basın və log-a baxın.

Unmounted
--:--:--Gözləmədə. "Mount et" düyməsinə basın.

Bu demo arxa planda tam olaraq aşağıdakı React koduna bənzər məntiqlə işləyir:

TIMERDEMO.JSX
function TimerDemo() {
  const [tick, setTick] = useState(0);

  useEffect(() => {
    console.log('🟢 Effekt işə düşdü: interval quruldu');
    const id = setInterval(() => {
      setTick((prev) => prev + 1);
    }, 1000);

    return () => {
      console.log('🔴 Cleanup: interval təmizləndi');
      clearInterval(id);
    };
  }, []); // yalnız mount zamanı bir dəfə qurulur

  return <p>Tick: {tick}</p>;
}
🐞 UNMOUNT-DA NİYƏ MÜTLƏQ clearInterval LAZIMDIR?

Əgər cleanup yazılmasa, komponent ekrandan silinsə belə setInterval arxa planda işləməyə davam edir. Bu, həm lazımsız CPU/yaddaş istifadəsi, həm də "artıq mövcud olmayan komponentin state-ini yeniləməyə cəhd" xətası yaradır.

Dependency array-in fərqli ssenarilərdə sınanması

Bunu real hiss etmək üçün ən yaxşı yol — yuxarıdakı "Force Update" düyməsini bir neçə dəfə basıb log-a baxmaqdır: effekt yalnız mount zamanı bir dəfə işə düşür, "Force Update" isə heç bir yeni effekt tetiklemir, çünki array boşdur ([]). Əgər array-i [tick] etsəydik, hər tick dəyişəndə effekt təzədən işə düşərdi.

Tapşırıq: Hər saniyə yenilənən saat komponenti

useEffect + cleanup

Məqsəd: useState ilə cari vaxtı saxlayan, useEffect daxilində setInterval ilə hər saniyə yeniləyən və cleanup ilə komponent silinəndə interval-ı dayandıran bir Clock komponenti yazın.

CLOCK.JSX — HƏLL
function Clock() {
  const [time, setTime] = useState(new Date());

  useEffect(() => {
    const timerId = setInterval(() => {
      setTime(new Date());
    }, 1000);

    // Cleanup: komponent unmount olanda interval dayanır
    return () => clearInterval(timerId);
  }, []); // boş array — timer yalnız bir dəfə qurulur

  return (
    <h1>{time.toLocaleTimeString()}</h1>
  );
}
🎯 ÖZÜNÜZ SINAYIN

Tapşırığı bir addım da inkişaf etdirin: saatı 12-saatlıq/24-saatlıq formatlar arasında keçirən bir düymə əlavə edin (bunun üçün əlavə useEffect lazım deyil — sadəcə render zamanı format seçimini state-ə görə tətbiq edin).

09

Tez-tez verilən suallar

Ən tipik səbəb: effekt daxilində elə bir state-i yeniləyirsiniz ki, o state həm də effektin dependency array-indədir (və ya array ümumiyyətlə yoxdur). Nəticə: state dəyişir → komponent yenidən render olunur → effekt təzədən işə düşür → state yenə dəyişir → sonsuz dövr.

❌ SƏHV
useEffect(() => {
  setCount(count + 1); // hər render-də çağırılır
}); // array yoxdur!
✅ DÜZGÜN
useEffect(() => {
  setCount((prev) => prev + 1);
}, []); // yalnız 1 dəfə

Qarşısını almaq üçün: (1) dependency array-i dəqiq müəyyən edin, (2) mümkünsə funksional yeniləmə formasından (prev => prev + 1) istifadə edin ki, cari dəyərə asılı olmayasınız, (3) ESLint-in react-hooks/exhaustive-deps qaydasını aktiv saxlayın — o sizə əskik və ya lazımsız dependency-ləri göstərir.

İki konkret anda: (1) komponent unmount olanda — son dəfə, hər şeyi yığışdırmaq üçün; (2) dependency array-dəki dəyər dəyişəndə — yeni effekt işə düşməzdən bir addım əvvəl, köhnə effekti təmizləmək üçün.

Yəni array-siz useEffect-də cleanup hər render-dən əvvəl işə düşür (çünki effekt hər render-dən sonra təkrar qurulur). Boş array [] olduqda isə effekt heç vaxt təkrarlanmır, ona görə cleanup yalnız unmount zamanı — bir dəfə — çağırılır.

[] (boş array) — React-ə deyirsiniz: "bu effektin heç bir asılılığı yoxdur, ona görə yalnız mount zamanı bir dəfə işlət". Array-i ümumiyyətlə yazmamaq isə tam əksinədir: "asılılıqları izləmə, sadəcə hər render-dən sonra işlət" — yəni həmişə, dayanmadan.

Praktik nəticə: boş array performans baxımından təhlükəsizdir və ən çox istifadə olunan variantdır. Array-i unutmaq isə çox vaxt performans problemlərinə və ya (yuxarıda gördüyümüz kimi) sonsuz loop-lara aparır. Əgər niyyətiniz "hər render-dən sonra işlət" deyilsə, array-i heç vaxt boş qoymayın.

10

Ola biləcək xətalar və buglar

Yeni başlayanların useEffect ilə ən çox rastlaşdığı problemlər

BUG 1 · SONSUZ LOOP

State-i effekt daxilində şərtsiz yeniləmək

Dependency array-siz (və ya səhv array ilə) effekt daxilində state dəyişdirmək hər render-i yeni render-ə səbəb edir.

❌ SƏHV
useEffect(() => {
  setCount(count + 1);
});
✅ HƏLL
useEffect(() => {
  setCount((p) => p + 1);
}, []);
BUG 2 · YADDAŞ SIZMASI

Cleanup-ı unutmaq

Event listener, interval və ya subscription açılır, amma heç vaxt bağlanmır — komponent silinəndən sonra da arxa planda işləməyə davam edir.

❌ SƏHV
useEffect(() => {
  window.addEventListener(
    'resize', handleResize
  );
}, []);
✅ HƏLL
useEffect(() => {
  window.addEventListener('resize', handleResize);
  return () =>
    window.removeEventListener('resize', handleResize);
}, []);
BUG 3 · KÖHNƏLMİŞ CLOSURE (STALE CLOSURE)

Effekt daxilində köhnə state dəyərinin "yaddaşda qalması"

Dependency array-də göstərilməyən bir dəyişən effekt daxilində istifadə olunanda, effekt həmişə o dəyişənin ilk (yaradıldığı andakı) dəyərini "xatırlayır".

❌ SƏHV
useEffect(() => {
  const id = setInterval(() => {
    console.log(count); // həmişə ilkin dəyər
  }, 1000);
  return () => clearInterval(id);
}, []); // count əskikdir
✅ HƏLL
useEffect(() => {
  const id = setInterval(() => {
    console.log(count);
  }, 1000);
  return () => clearInterval(id);
}, [count]); // dependency əlavə edildi
BUG 4 · YARIŞ VƏZİYYƏTİ (RACE CONDITION)

Sürətlə dəyişən props zamanı köhnə API cavabının state-i "əzməsi"

userId sürətlə dəyişəndə əvvəlki sorğu sonradan tamamlana bilər və köhnə data yeni datanın üzərinə yazıla bilər.

❌ SƏHV
useEffect(() => {
  fetchUser(userId).then(setUser);
}, [userId]);
✅ HƏLL
useEffect(() => {
  let cancelled = false;
  fetchUser(userId).then((d) => {
    if (!cancelled) setUser(d);
  });
  return () => { cancelled = true; };
}, [userId]);
BUG 5 · ASYNC FUNKSİYA BİRBAŞA useEffect-Ə VERİLİR

useEffect(async () => {...}) yazmaq

Effekt funksiyası ya heç nə, ya da funksiya (cleanup) qaytarmalıdır. async funksiya isə həmişə Promise qaytarır — React bunu səhv kimi qəbul edir.

❌ SƏHV
useEffect(async () => {
  const d = await fetchUser(id);
  setUser(d);
}, [id]);
✅ HƏLL
useEffect(() => {
  async function load() {
    const d = await fetchUser(id);
    setUser(d);
  }
  load();
}, [id]);
BUG 6 · LAZIMSIZ EFFECT İSTİFADƏSİ

Render zamanı hesablana bilən dəyər üçün effekt yazmaq

Əgər dəyəri mövcud state/props-dan birbaşa hesablamaq mümkündürsə, buna görə əlavə state + effekt yaratmağa ehtiyac yoxdur — bu, lazımsız re-render yaradır.

❌ SƏHV
const [full, setFull] = useState('');
useEffect(() => {
  setFull(first + ' ' + last);
}, [first, last]);
✅ HƏLL
const full = first + ' ' + last;
// effekt lazım deyil, birbaşa render zamanı hesablanır

Nələri etsək daha yaxşı olar

Tövsiyələr və yaxşı təcrübələr

  • 01
    ESLint-in react-hooks/exhaustive-deps qaydasını aktiv saxlayınBu qayda əskik və ya lazımsız dependency-ləri avtomatik aşkarlayır — stale closure və sonsuz loop kimi bugların qarşısını erkən alır.
  • 02
    Bir useEffect — bir məsuliyyətƏlaqəsiz iki işi (məs. həm data yükləmək, həm resize dinləmək) bir effektə yığmayın — hər biri üçün ayrı useEffect yazın ki, kod oxunaqlı qalsın.
  • 03
    Asinxron sorğularda ləğv məntiqi əlavə edinisCancelled bayrağı və ya AbortController istifadə edərək köhnə sorğu nəticələrinin yeni state-i "əzməsinin" qarşısını alın.
  • 04
    Timer, listener və ya subscription açan hər effektdə cleanup qaytarınsetInterval → clearInterval, addEventListener → removeEventListener. Açdığınızı həmişə bağlayın.
  • 05
    Təkrarlanan effekt məntiqini custom hook-a çıxarınMəs. useInterval(callback, delay) və ya useFetch(url) — eyni useEffect məntiqini layihə boyu təkrar yazmaqdansa, bir dəfə hook yazıb hər yerdə istifadə edin.
  • 06
    Render zamanı hesablana bilən şey üçün effect yazmayınReact-in rəsmi tövsiyəsi: "əgər dəyəri mövcud props/state-dən birbaşa hesablaya bilirsinizsə, ona effekt lazım deyil".
  • 07
    Render-i tetikləməli olmayan dəyərlər üçün useRef işlədinInterval ID-si, əvvəlki dəyər kimi şeylər üçün state yerinə ref istifadə etmək lazımsız re-render-lərin qarşısını alır.
  • 08
    Effekti "niyə lazımdır" sualı ilə yoxlayınHər useEffect yazmazdan əvvəl özünüzə sual verin: "bu, xarici sistemlə (API, DOM, timer, brauzer) sinxronizasiyadırmı, yoxsa sadəcə hesablamadır?" Yalnız birincisi effekt tələb edir.
