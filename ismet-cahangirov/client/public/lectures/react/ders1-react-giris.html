1 NƏZƏRİYYƏ

React nədir və niyə yaranıb?

React — Facebook (indiki Meta) tərəfindən 2013-cü ildə açıq mənbə kimi təqdim edilmiş, istifadəçi interfeysi (UI) qurmaq üçün istifadə olunan JavaScript kitabxanasıdır. Diqqət edin: React framework deyil, kitabxanadır — o, yalnız "görünüşü necə qurmalı" sualına cavab verir, marşrutlama, HTTP sorğuları kimi digər məsələlər üçün ayrı kitabxanalar (React Router, Axios və s.) istifadə olunur.

jQuery və vanilla JS-in problemi nə idi?

React-dan əvvəl veb-saytlar əsasən imperativ yanaşma ilə qurulurdu — yəni proqramçı DOM-a "get element, sonra dəyəri dəyiş, sonra class əlavə et" kimi addım-addım əmrlər verirdi. Facebook-un "Bildirişlər" (Notifications) bölməsi bu problemin klassik nümunəsidir:

  • Data və DOM sinxronizasiyası əl ilə idi. Server-dən yeni bildiriş gələndə, proqramçı həm say göstəricisini, həm siyahını, həm də səhifə başlığındakı rəqəmi ayrı-ayrılıqda yeniləməli idi. Bir yeri unutsan, interfeys "yalan danışmağa" başlayırdı (say 5 göstərir, siyahıda isə 3 element var).
  • Kod böyüdükcə idarə olunmaz olurdu. jQuery ilə yazılan layihələrdə yüzlərlə $(".element").on("click", ...) tipli hadisə dinləyicisi bir-birinə qarışır, hansı kodun hansı DOM elementinə təsir etdiyini izləmək çətinləşirdi. Buna qeyri-rəsmi olaraq "spagetti kod" deyilir.
  • Yenidən istifadə (reusability) demək olar yox idi. Eyni "kart" və ya "düymə" dizaynını başqa səhifədə istifadə etmək üçün kodu köçürüb-yapışdırmaq (copy-paste) lazım gəlirdi — komponent anlayışı mövcud deyildi.
  • Test etmək çətin idi. Məntiq birbaşa DOM-a bağlı olduğu üçün, UI-ni DOM-suz (məsələn avtomatik testlərdə) yoxlamaq demək olar mümkün deyildi.

React bu problemləri deklarativ (declarative) yanaşma ilə həll etdi: proqramçı "necə etməli" (necə addım-addım DOM-u dəyişməli) yox, "nəyi görmək istəyirəm" izah edir, React isə bunu real DOM-a necə çevirəcəyinə özü qərar verir.

⚠ Yayılmış səhv anlayış
  • "React bütün problemi avtomatik həll edir, JS bilmək lazım deyil" — yanlışdır. React sadəcə JavaScript-in üzərində qurulmuş bir vasitədir; closures, array metodları (map, filter), destructuring kimi JS əsaslarını bilmədən React-ı öyrənmək çox çətin olacaq.
  • "React framework-dür" — texniki olaraq React özü kitabxanadır; Next.js kimi vasitələr onun üzərində qurulan framework-lərdir.
✓ Tövsiyə

Bu dərsə başlamazdan əvvəl JS-də let/const, arrow function, array metodları və destructuring mövzularını bir daha nəzərdən keçirin — React-ın 90%-i "sadəcə JavaScript"dir, sintaksis üstündə deyil, bu əsaslar üzərində çətinlik çəkəcəksiniz.

2 NƏZƏRİYYƏ

SPA (Single Page Application) anlayışı

SPA — istifadəçi saytda gəzərkən brauzerin yalnız bir dəfə tam HTML səhifəsi yüklədiyi, sonrakı bütün keçidlərin isə JavaScript vasitəsilə, səhifəni yenidən yükləmədən idarə olunduğu tətbiq növüdür.

Ənənəvi Multi-Page Application (MPA) necə işləyir?

Klassik saytda hər link kliklədikdə brauzer server-ə yeni sorğu göndərir, server tam yeni HTML faylı qaytarır və brauzer bütün səhifəni sıfırdan yenidən çəkir (o cümlədən CSS, JS də yenidən yüklənir). Nəticədə qısa bir "ağ ekran yanıb-sönməsi" (flicker) hiss olunur.

SPA necə işləyir?

SPA-da server ilk dəfə minimal bir index.html və JS bundle-ı göndərir. Bundan sonra "səhifə keçidi" kimi görünən hər şey əslində JavaScript-in (React Router kimi kitabxanaların) DOM-un müəyyən hissəsini dəyişməsidir — server-ə tam səhifə üçün yeni sorğu getmir, lazım gələrsə yalnız data (JSON) üçün kiçik sorğu (fetch/AJAX) atılır.

✕ Tez-tez rast gəlinən bug / problem
  • SEO problemi: Sırf client-side SPA-da axtarış botu səhifəyə gələndə boş <div id="root"></div> görə bilər, çünki məzmun JS icra olunandan sonra yaranır. Bu, ictimai (public) saytlar üçün ciddi problem yaradır.
  • İlkin yükləmə (First Load) yavaşlığı: Bütün tətbiqi bir bundle-da yükləmək JS faylının həddindən artıq böyük olmasına səbəb ola bilər.
  • "Geri" düyməsi qırılması: Marşrutlama düzgün qurulmayanda brauzerin "geri" düyməsi gözlənilən kimi işləməyə bilər.
✓ Yaxşı təcrübə
  • SEO vacib olan (bloq, e-ticarət, elan saytı) layihələr üçün Next.js kimi server-side rendering (SSR) dəstəkləyən həll seçin.
  • Bundle ölçüsünü azaltmaq üçün code-splitting və lazy loading (React.lazy) tətbiq edin.
  • Marşrutlama üçün əl ilə DOM manipulyasiyası yox, React Router kimi sınanmış kitabxana istifadə edin.
3 NƏZƏRİYYƏ

Virtual DOM konsepsiyası

Real DOM (Document Object Model) brauzerin səhifəni yaddaşda saxladığı ağac strukturudur. Problem ondadır ki, real DOM-a hər toxunuş (bir class əlavə etmək belə) brauzerə reflow və repaint — yəni layout-un yenidən hesablanması və ekranın yenidən çəkilməsi kimi baha başa gələn əməliyyatlar etdirir.

Virtual DOM — real DOM-un JavaScript obyekti şəklində yüngül surətidir. React state və ya props dəyişəndə birbaşa real DOM-a getmir; əvəzinə:

  1. Yeni Virtual DOM ağacı yaradılır (yaddaşda, çox sürətli).
  2. Bu yeni ağac köhnə Virtual DOM ağacı ilə müqayisə olunur — bu prosesə "diffing" (fərqlərin tapılması) deyilir.
  3. React yalnız faktiki dəyişən node-ları müəyyən edir və bu dəyişiklikləri bir yerə (batch) toplayaraq yalnız bir dəfə real DOM-a tətbiq edir — buna "reconciliation" (barışdırma) deyilir.

Aşağıdakı diaqram bu prosesi sadələşdirilmiş şəkildə göstərir: yalnız dəyişən node (narıncı) real DOM-da yenilənir, qalanlarına toxunulmur.

⚠ Diqqət — yayılmış yanlış anlayış

"Virtual DOM həmişə real DOM-dan sürətlidir" ifadəsi tam dəqiq deyil. Virtual DOM-un əsl üstünlüyü xam sürət deyil, proqramçının iş prosesini asanlaşdırması və orta hesabla effektiv performans verməsidir. Düzgün optimallaşdırılmamış komponentlərdə (məsələn hər kiçik dəyişiklikdə bütün böyük siyahının yenidən render olunması) Virtual DOM da performans problemi yarada bilər.

✕ Ən çox rast gəlinən bug: key prop-u

Siyahı (list) render edərkən React-a hər elementi fərqləndirmək üçün unikal key lazımdır. Bunu unutmaq və ya massivin indeksini (index) key kimi istifadə etmək aşağıdakı problemlərə səbəb olur:

  • Konsolda görəcəyiniz xəbərdarlıq: Warning: Each child in a list should have a unique "key" prop.
  • Siyahıya element əlavə/silinəndə və ya sıra dəyişəndə React səhv node-u "yenidən istifadə edir" — nəticədə input-un daxilindəki mətn, checkbox vəziyyəti kimi lokal state səhv elementə "yapışıb qala bilər".
❌ Səhv nümunə
const list = items.map((item, index) => (
  <li key={index}>{item.name}</li>
));
✅ Düzgün nümunə
const list = items.map((item) => (
  <li key={item.id}>{item.name}</li>
));
✓ Yaxşı təcrübə

Key üçün həmişə data-nın özündən gələn, dəyişməz və unikal dəyər (məsələn verilənlər bazasındakı id) istifadə edin. İndeksi yalnız siyahı statik olduğu, heç vaxt sıralanmadığı və element silinib-əlavə olunmadığı hallarda istifadə etmək olar.

4 NƏZƏRİYYƏ

React-ın işləmə prinsipi: komponent → render → DOM yeniləmə

React tətbiqi əslində komponentlərdən qurulan bir ağacdır. Bu ağacın "canlı" qalması üçün üç mərhələdən keçir: render, commit və yeniləmə (update).

Welcome.jsx 
function Welcome(props) {
  return <h1>Salam, {props.name}!</h1>;
}
  1. Komponent (Component): UI-nin bir hissəsini təsvir edən sadə JavaScript funksiyasıdır. Giriş kimi props qəbul edir, çıxış kimi JSX (əslində React elementi) qaytarır.
  2. Render: React komponent funksiyasını çağırır və qaytarılan JSX-dən Virtual DOM ağacı qurur. Bu mərhələdə hələ real DOM-a heç nə yazılmır — sadəcə "nə görünməli olduğu" hesablanır.
  3. Commit: React əvvəlki bölmədə izah olunan diffing prosesindən sonra, yalnız lazımi dəyişiklikləri real DOM-a yazır (əlavə edir, silir və ya yeniləyir).
  4. Yenidən render (Re-render): Komponentin state-i və ya valideynindən aldığı props dəyişəndə, React həmin komponenti (və onun uşaqlarını) yenidən çağırır və bütün proses təkrarlanır.
ℹ Qeyd

Bu dərsdə state anlayışına səthi toxunuruq — useState və digər hook-lar növbəti dərsdə ətraflı izah olunacaq. Hələlik bilmək kifayətdir ki, state dəyişən komponentin "yaddaşıdır" və state dəyişəndə komponent avtomatik yenidən render olunur.

✕ Başlanğıcda tez-tez edilən səhv
  • State-i birbaşa dəyişmək (mutasiya): state.value = 5 yazmaq React-a heç nə "demir" — React yalnız setState və ya useState-in qaytardığı funksiya (məsələn setCount) çağırılanda yenidən render etməli olduğunu bilir. Birbaşa dəyişiklikdə ekran köhnə vəziyyətdə "donub qalır".
  • Komponenti "saf funksiya" kimi yazmamaq: eyni props/state ilə çağırıldıqda komponent hər dəfə fərqli nəticə qaytarırsa (məsələn render zamanı təsadüfi dəyər və ya qlobal dəyişəni dəyişmək), bu, gözlənilməz və izlənməsi çətin bug-lara səbəb olur.
✓ Yaxşı təcrübə

Komponentə riyazi funksiya kimi baxın: eyni giriş (props/state) → eyni çıxış (JSX). Render funksiyası daxilində "yan effekt" (API çağırışı, timer qurmaq, dəyişən dəyişdirmək) etməyin — bunlar üçün növbəti dərslərdə öyrənəcəyimiz useEffect mövcuddur.

5 NƏZƏRİYYƏ

JSX sintaksisi: HTML-dən fərqləri

JSX (JavaScript XML) — HTML-ə çox bənzəyən, amma əslində JavaScript-in sintaktik genişlənməsidir. Brauzer JSX-i birbaşa anlamır: Babel adlı alət JSX kodunu adi React.createElement(...) çağırışlarına çevirir.

HTML kimi görünür
<div class="card">
  <img src="foto.jpg">
  <label for="ad">Ad</label>
  <input onclick="click()">
</div>
Doğru JSX
<div className="card">
  <img src="foto.jpg" />
  <label htmlFor="ad">Ad</label>
  <input onClick={click} />
</div>

Əsas fərqlər

  • class → className: class JavaScript-də rezerv olunmuş açar sözdür (siniflər üçün), ona görə JSX-də CSS klassı üçün className istifadə olunur.
  • camelCase atributlar: onclick → onClick, tabindex → tabIndex, maxlength → maxLength. Bunun səbəbi JSX-in JS obyekt xüsusiyyətləri (property) kimi işləməsidir, JS isə çox sözlü adları camelCase şəklində yazır.
  • for → htmlFor: for də JavaScript-də rezerv sözdür (dövr — loop üçün), ona görə label-in for atributu htmlFor adlanır.
  • Bütün teqlər bağlanmalıdır (self-closing): HTML-də <img>, <br>, <input> kimi teqlər bağlanmasa da brauzer bağışlayır. JSX-də isə bu mütləq şərtdir: ya <img /> yazılmalı, ya da açıq-bağlı cüt teq (<div></div>) istifadə olunmalıdır.
  • Inline stil obyekt kimi yazılır: HTML-də style="color: red; font-size: 14px" — string. JSX-də isə style={{color: 'red', fontSize: 14}} — JS obyekti (diqqət: font-size də camelCase-ə çevrilir və vahidsiz ədədlər üçün avtomatik px əlavə olunur).
  • Bir kök element qaydası: Bir komponent funksiyası yalnız bir JSX elementi qaytara bilər. Bir neçə element qaytarmaq lazımdırsa, onları <div> və ya görünməz <>...</> (Fragment) ilə əhatə etmək lazımdır.
Fragment istifadəsi
function Kart() {
  return (
    <>
      <h2>Başlıq</h2>
      <p>Mətn</p>
    </>
  );
}
✕ Tez-tez rast gəlinən JSX xətaları
  • "Adjacent JSX elements must be wrapped in an enclosing tag" — komponentdən iki və ya daha çox "kök" element qaytarmağa cəhd edəndə çıxan kompilyasiya xətası. Həlli: Fragment (<></>) və ya <div> ilə əhatələmək.
  • class istifadə etmək: Bu, kompilyasiya xətası vermir, amma konsolda Warning: Invalid DOM property "class". Did you mean "className"? xəbərdarlığı çıxır və stillər tətbiq olunmur.
  • Adi HTML şərhi istifadə etmək: <!-- şərh --> JSX-də sintaksis xətası verir. JSX daxilində şərh {'{/* bu şəkildə */}'} formatında yazılmalıdır.
  • Bağlanmamış teq: <img src="a.jpg"> unudulmuş slash — "Unterminated JSX contents" xətası verə bilər.
  • Açar sözlərin toqquşması: dəyişən adı kimi class və ya digər JS rezerv sözlərini istifadə etmək.
✓ Yaxşı təcrübə
  • Layihəyə əvvəlcədən ESLint + Prettier qoşun — bu, yuxarıdakı xətaların çoxunu kod yazan kimi, hələ brauzerə çatmadan aşkarlayacaq.
  • Kod redaktorunda (VS Code) ES7+ React/Redux/React-Native snippets kimi əlavələr istifadə edin — className, onClick kimi adları avtomatik təklif edir, əl xətalarını azaldır.
6 NƏZƏRİYYƏ

JSX-də JavaScript ifadələrinin istifadəsi

JSX-in ən güclü tərəfi — HTML-in içərisinə birbaşa JavaScript "qatmaq" imkanıdır. Bunun üçün tək qoşa mötərizə {'{ }'} istifadə olunur.

Dəyişən, funksiya çağırışı, riyazi ifadə
const ad = "Aysel";
const yas = hesablaYas(2001);

function Profil() {
  return (
    <div>
      <h2>Salam, {ad}!</h2>
      <p>Yaş: {yas}</p>
      <p>2 + 2 = {2 + 2}</p>
    </div>
  );
}

Şərti render (ternary və &&): if operatoru "statement" olduğu üçün {} daxilində birbaşa işləmir — çünki {} yalnız ifadə (expression) qəbul edir, əmr (statement) yox. Ona görə şərti göstərmək üçün ternary operator və ya && istifadə olunur:

Şərti render
{isLoggedIn ? (
  <p>Xoş gəldiniz!</p>
) : (
  <p>Zəhmət olmasa daxil olun</p>
)}

{istifadeciSayi > 0 && (
  <span>{istifadeciSayi} istifadəçi onlayn</span>
)}

Siyahı render (.map()): massivi JSX elementlərinə çevirmək üçün ən çox istifadə olunan üsuldur — unutmayın, hər elementin unikal key-i olmalıdır (3-cü bölmədə izah olundu).

Siyahı render
<ul>
  {meyveler.map((meyve) => (
    <li key={meyve.id}>{meyve.ad}</li>
  ))}
</ul>
✕ Tez-tez rast gəlinən xətalar
  • {'{'} daxilində if yazmaq: {'{if (x) { ... }}'} — "Unexpected token" sintaksis xətası verir, çünki if statement-dir, expression deyil.
  • Obyekt qaytarmaq üçün mötərizə çaşqınlığı: style={'{{color: "red"}}'} yazısındakı ikinci cüt mötərizə — birincisi JSX-in {'{ }'}-i, ikincisi isə JS obyekt literalıdır. Bunu qarışdırmaq (məsələn tək mötərizə yazmaq) xətaya səbəb olur.
  • 0 render problemi: {'{count && Var}'} — əgər count dəyəri 0-dırsa, ekranda gözlənilmədən "0" rəqəmi göstərilir (çünki 0 "falsy" olsa da, React onu render edir). Düzəliş: count > 0 && ... və ya Boolean(count) && ....
  • Array yerinə obyekt qaytarmaq: {'{}'} daxilinə birbaşa sadə JS obyekti ({'{ad: "Ali"}'}) yazmaq — "Objects are not valid as a React child" xətası ilə nəticələnir, çünki React obyekti necə göstərəcəyini bilmir.
✓ Yaxşı təcrübə
  • Mürəkkəb şərti məntiqi (bir neçə if/else if) JSX daxilinə yığmaq yerinə, render-dən əvvəl ayrıca dəyişənə və ya köməkçi funksiyaya çıxarın — JSX-i sadə və oxunaqlı saxlayın.
  • .map() istifadə edərkən key-i həmişə ən yaxın valideyn elementə verin, uşaq komponentin öz daxilinə yox.

Bonus: İlk React layihəsinin qurulması

Dərsin adında qeyd olunan "Layihə Qurulumu" hissəsi üçün qısa təcrübi bələdçi — bu gün ən çox tövsiyə olunan üsul Vite ilə qurulumdur (köhnə create-react-app artıq rəsmi olaraq tövsiyə olunmur və dəstəklənmir).

terminal 
# 1. Yeni layihə yarat
npm create vite@latest menim-ilk-react-layihem

# 2. Framework seç → React, sonra → JavaScript (və ya TypeScript)

# 3. Qovluğa keç
cd menim-ilk-react-layihem

# 4. Asılılıqları yüklə
npm install

# 5. Dev server-i işə sal
npm run dev

Bundan sonra terminalda görünən linki (adətən http://localhost:5173) brauzerdə açmaqla layihəni canlı görə bilərsiniz. Vite-in üstünlüyü — Hot Module Replacement (HMR): kodda dəyişiklik etdikdə səhifə tam yenidən yüklənmədən, yalnız dəyişən hissə anında yenilənir.

✕ Qurulum zamanı tez-tez rast gəlinən problemlər
  • Köhnə Node.js versiyası: Vite müasir Node.js (18+) tələb edir. "Unsupported engine" və ya anlaşılmaz build xətaları görsəniz, ilk növbədə node -v ilə versiyanı yoxlayın.
  • npm install zamanı asılılıq konflikti: köhnə paket qalıqları problem yaradanda node_modules qovluğunu və package-lock.json faylını silib yenidən npm install etmək çox vaxt kömək edir.
  • Port məşğuldur (Port already in use): başqa layihə eyni portu tutubsa, Vite avtomatik başqa boş port seçir — konsoldakı yeni ünvana diqqət edin.
  • Fayl adları həssaslığı: Windows/macOS-dan fərqli olaraq Linux server-lərdə fayl adları böyük/kiçik hərfə həssasdır — Button.jsx və button.jsx fərqli fayllardır, import zamanı bu, "modul tapılmadı" xətasına səbəb ola bilər.
✓ Yaxşı təcrübə
  • create-react-app yerinə Vite istifadə edin — daha sürətli, daha yüngül və aktiv dəstəklənir.
  • Layihəyə başlar-başlamaz .gitignore-da node_modules olduğuna əmin olun və Git-ə qoşun.
  • Qovluq strukturunu əvvəldən nizamlayın: src/components, src/pages kimi.
✓ YEKUN

Dərsin xülasəsi

Bu dərsdə öyrəndiklərimizi yoxlama siyahısı ilə bir daha xatırlayaq:

  • ✓ React-ın niyə yarandığını və jQuery/vanilla JS-in hansı problemlərini həll etdiyini izah edə bilirəm.
  • ✓ SPA və MPA arasındakı fərqi, hər birinin üstünlük/mənfi cəhətlərini bilirəm.
  • ✓ Virtual DOM-un nə olduğunu və diffing/reconciliation prosesini izah edə bilirəm.
  • ✓ Komponent → render → DOM yeniləmə zəncirini başa düşürəm.
  • ✓ JSX-in HTML-dən fərqlərini (className, camelCase, self-closing) sadalaya bilirəm.
  • ✓ JSX daxilində {'{ }'} ilə JS ifadəsi, şərti render və siyahı render yaza bilirəm.
  • ✓ Vite ilə yeni React layihəsi qura bilirəm.
