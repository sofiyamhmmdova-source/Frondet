01

Funksional vs Class komponentlər

React-də komponent yazmağın tarixən iki yolu olub. Bu gün demək olar ki, yalnız birindən istifadə olunur, amma ikincisini tanımaq vacibdir — çünki köhnə layihələrdə, kitabxanalarda və müsahibə suallarında hələ də qarşınıza çıxa bilər.

Class komponentlər (2013–2019)

React-in ilk illərində state və lifecycle metodları (componentDidMount və s.) yalnız class sintaksisi ilə yazılan komponentlərdə mümkün idi.

Daha çox boilerplate kod, this açar sözü ilə bağlı çaşqınlıq, mürəkkəb sintaksis.

Funksional komponentlər (2019 →)

React 16.8 (fevral 2019) Hooks-u (useState, useEffect və s.) təqdim etdi. Bundan sonra adi funksiyalar da state və lifecycle idarə edə bildi.

Daha az kod, oxunması asan, bugünkü standart yanaşma. Bu kursda yalnız funksional komponentlərdən istifadə edəcəyik.

2013 — React elan olundu (yalnız class) → 2015 — funksional "stateless" komponentlər (yalnız props üçün) → 2019 — Hooks: funksional komponentlər state ala bilir → bu gün — sənaye standartı funksional komponentlərdir

Funksional komponent, sadəcə JSX qaytaran adi bir JavaScript funksiyasıdır:

Greeting.jsx
function Greeting() {
  return <h1>Salam, dünya!</h1>;
}

export default Greeting;
02

Props nədir və necə ötürülür?

Props ("properties" sözünün qısaldılmışı) — valideyn komponentin uşaq komponentə ötürdüyü məlumatdır. Onları HTML atributlarına bənzədə bilərsiniz, fərq ondadır ki, props vasitəsilə istənilən JavaScript dəyərini (mətn, rəqəm, obyekt, massiv, funksiya, hətta başqa komponent) ötürmək mümkündür.

Düşünün ki, komponent bir funksiyadır, props isə onun parametrləridir. Eyni funksiyanı fərqli arqumentlərlə çağırdığınız kimi, eyni komponenti fərqli props dəyərləri ilə dəfələrlə istifadə edə bilərsiniz.

App.jsx
// Props ötürülməsi — adi HTML atributu kimi görünür
<UserCard name="Aygün Məmmədova" age={24} isOnline={true} />

// Komponent daxilində qəbul edilməsi
function UserCard(props) {
  return (
    <div>
      <h3>{props.name}</h3>
      <p>Yaş: {props.age}</p>
    </div>
  );
}

Praktikada destructuring ilə yazmaq daha təmiz və oxunaqlıdır — hansı props-ların gözlənildiyi funksiyanın imzasından dərhal görünür:

UserCard.jsx
function UserCard({ name, age, isOnline }) {
  return (
    <div className="user-card">
      <h3>{name}</h3>
      <p>Yaş: {age}</p>
      <span>{isOnline ? "🟢 Online" : "⚪ Offline"}</span>
    </div>
  );
}
Diqqət: Dinamik JavaScript dəyərləri JSX daxilində həmişə fiqurlu mötərizə { } içində yazılır. Sabit mətn üçün isə adi dırnaq işarələri ("...") kifayətdir.
03

Props immutable-dır (dəyişməzdir)

Bu, React-in ən vacib qaydalarından biridir: uşaq komponent özünə ötürülən props-u heç vaxt birbaşa dəyişə bilməz. Props yalnız oxumaq üçündür — "yuxarıdan aşağı" axan, bir istiqamətli (one-way) məlumat axınıdır.

Props bir istiqamətli axındır: Parent → Child. Uşaq props-u dəyişə bilməz, yalnız oxuya bilər.
✕ Səhv — props mutasiya edilir
function UserCard(props) {
  props.name = props.name.toUpperCase();
  // ⚠️ Runtime xəta / React xəbərdarlığı
  return <h3>{props.name}</h3>;
}
✓ Düzgün — yeni dəyişən yaradılır
function UserCard({ name }) {
  const displayName = name.toUpperCase();
  return <h3>{displayName}</h3>;
}

Niyə belədir? Çünki React-in "unudulmaz" qaydası "proqnozlaşdırıla bilən data axını"dır (predictable data flow). Əgər hər komponent özünə gələn props-u istədiyi kimi dəyişə bilsəydi, tətbiqin hansı anda hansı məlumatı göstərdiyini izləmək mümkün olmazdı.

04

children props

children — komponentin açılış və bağlanış teqləri arasına yerləşdirilən istənilən JSX-i təmsil edən xüsusi propdur. Bu, komponentə "içini kənardan doldurmaq" imkanı verir.

Panel.jsx
function Panel({ title, children }) {
  return (
    <div className="panel">
      <h3>{title}</h3>
      <div className="panel__body">{children}</div>
    </div>
  );
}

// İstifadəsi — Panel öz daxilini bilmir, valideyn ötürür:
<Panel title="Diqqət">
  <p>Bu əməliyyatı geri qaytarmaq mümkün deyil.</p>
  <button>Bağla</button>
</Panel>

Nə vaxt lazımdır? Konteyner/wrapper xarakterli komponentlərdə — Modal, Card, Layout, Panel, Button kimi — burada komponent özü strukturu (çərçivəni) təmin edir, məzmunu isə valideyn müəyyən edir. Bu, komponenti həddindən artıq çox prop qəbul etməkdən (məsələn bodyText, bodyIcon, bodyButton...) xilas edir və onu daha çevik edir.

05

Composition və Reusability

Composition — kiçik komponentlərin bir-birinin içinə yerləşdirilərək daha böyük, mürəkkəb interfeyslər qurulması prinsipidir. Necə ki Lego bloklarından böyük bir konstruksiya yığılır, React tətbiqi də kiçik komponentlərdən yığılır.

App komponenti Header-i və 3 ədəd Card-ı (hər biri öz Button-u ilə) tərtib edir — eyni Card və Button hər dəfə fərqli props ilə təkrar istifadə olunur.

Bu diaqramda diqqət edin: Card və Button yalnız bir dəfə yazılıb, amma üç dəfə fərqli props ilə istifadə olunur. Bu, reusability (təkrar istifadəlilik) prinsipidir — eyni kodu köçürüb-yapışdırmaq (copy-paste) əvəzinə, bir komponenti fərqli data ilə çağırırıq.

Nə üçün bu vacibdir?

  • DRY prinsipi (Don't Repeat Yourself) — dizayn dəyişəndə (məsələn, kartın kənar radiusu) yalnız bir yerdə — Card.jsx-də — düzəliş etmək kifayətdir.
  • Test etmək asanlaşır — kiçik komponenti təcrid olunmuş şəkildə test etmək, 500 sətirlik bir komponenti test etməkdən qat-qat sadədir.
  • Komanda işi rahatlaşır — bir developer Header üzərində, digəri Card üzərində paralel işləyə bilər.
06

Praktiki hissə — Card, Button, Header

İndi nəzəriyyəni real komponentlərə çevirək. Üç kiçik, təkrar istifadə oluna bilən komponent yaradacağıq: Header, Button və Card.

1) Header komponenti

components/Header.jsx
function Header({ title, subtitle }) {
  return (
    <header className="app-header">
      <h1>{title}</h1>
      {subtitle && <p>{subtitle}</p>}
    </header>
  );
}

export default Header;

Qeyd: {subtitle && ...} qısa qapanma (short-circuit) texnikasıdır — subtitle ötürülməyibsə, heç nə render olunmur.

2) Button komponenti

components/Button.jsx
function Button({ children, onClick, variant = "primary" }) {
  return (
    <button className={`btn btn--${variant}`} onClick={onClick}>
      {children}
    </button>
  );
}

export default Button;

Diqqət: variant = "primary" — bu, funksiyanın default parametr sintaksisidir. Əgər variant propu ötürülməzsə, avtomatik "primary" istifadə olunur.

3) Card komponenti

components/Card.jsx
function Card({ name, image, description, children }) {
  return (
    <div className="card">
      <img src={image} alt={name} className="card__image" />
      <h3 className="card__title">{name}</h3>
      <p className="card__description">{description}</p>
      {children}
    </div>
  );
}

export default Card;

4) Hamısını birləşdirmək (composition)

App.jsx
import Header from "./components/Header";
import Card from "./components/Card";
import Button from "./components/Button";

function App() {
  return (
    <div className="app">
      <Header title="Komandamız" subtitle="Bizim inkişaf komandası" />

      <main className="grid">
        <Card
          name="Aygün Məmmədova"
          image="/avatars/aygun.jpg"
          description="Frontend developer, React həvəskarı"
        >
          <Button onClick={() => alert("Profilə keçid")}>
            Profilə bax
          </Button>
        </Card>

        {/* Digər Card komponentləri eyni qaydada... */}
      </main>
    </div>
  );
}

export default App;

PropTypes və default props ilə tanışlıq

JavaScript tip yoxlaması etmədiyi üçün, prop-a səhv tipli dəyər (məsələn, rəqəm əvəzinə mətn) ötürmək asanca bugə səbəb ola bilər. prop-types kitabxanası inkişaf zamanı (development-də) konsola xəbərdarlıq çıxararaq bunun qarşısını almağa kömək edir.

components/Card.jsx
import PropTypes from "prop-types";

function Card({ name, image, description }) {
  // ...komponentin gövdəsi
}

Card.propTypes = {
  name: PropTypes.string.isRequired,
  image: PropTypes.string,
  description: PropTypes.string,
};

export default Card;
Vacib qeyd: Köhnə tədris materiallarında tez-tez Card.defaultProps = {'{'} image: "/default.png" {'}'} formasını görəcəksiniz. Bu üsul funksional komponentlərdə deprecated (React 19-dan etibarən dəstəklənmir) elan olunub. Bunun əvəzinə birbaşa funksiya parametrlərində default dəyər verin: function Card({ image = "/default.png" }).
07

Tapşırıq — Profil kartları siyahısı

Praktiki tapşırıq

Bir massiv daxilində saxlanılan istifadəçi məlumatlarını (ad, şəkil, təsvir) yuxarıda yaratdığınız Card komponenti vasitəsilə ekrana çıxaran bir siyahı qurun.

data/users.js
export const users = [
  { id: 1, name: "Aygün Məmmədova", image: "/avatars/aygun.jpg", bio: "Frontend developer" },
  { id: 2, name: "Elvin Həsənov",    image: "/avatars/elvin.jpg",  bio: "Backend developer" },
  { id: 3, name: "Nərmin Əliyeva",   image: "/avatars/nermin.jpg", bio: "UI/UX dizayner" },
];
ProfileList.jsx
import { users } from "./data/users";
import Card from "./components/Card";
import Button from "./components/Button";

function ProfileList() {
  return (
    <div className="grid">
      {users.map((user) => (
        <Card
          key={user.id}
          name={user.name}
          image={user.image}
          description={user.bio}
        >
          <Button variant="secondary">Əlaqə saxla</Button>
        </Card>
      ))}
    </div>
  );
}

export default ProfileList;

Yoxlama siyahısı (checklist)

  • Məlumatlar (ad, şəkil, təsvir) komponentə props vasitəsilə ötürülür, komponent daxilində sabit (hardcoded) yazılmayıb.
  • Siyahı .map() ilə render olunur və hər elementə unikal, sabit key (id) verilib — indeks deyil.
  • Card komponenti həm öz props-larını, həm də children (Button) qəbul edir.
  • Komponent adları böyük hərflə başlayır: Card, Button, ProfileList.
  • Bonus: PropTypes əlavə edərək name propunu məcburi (isRequired) edin.
08

Ola biləcək xətalar və buglar

Bu bölmədə başlanğıc React öyrənənlərin ən çox rastlaşdığı problemlər toplanıb — hər birinin necə tanınacağı və düzəldiləcəyi ilə birlikdə.

1

Siyahıda key propunu unutmaq

Konsolda Warning: Each child in a list should have a unique "key" prop xəbərdarlığı görünür. Nəticədə React siyahını yenidən render edərkən elementləri düzgün izləyə bilmir, animasiya/state qarışıqlığı yarana bilər.

// ✕ key yoxdur
{users.map(user => <Card name={user.name} />)}

// ✓ unikal, sabit id istifadə olunur (massivdəki indeks yox!)
{users.map(user => <Card key={user.id} name={user.name} />)}
2

Komponent adının kiçik hərflə başlaması

React JSX-də böyük/kiçik hərfə görə fərq qoyur: kiçik hərflə başlayan teqlər (<card />) adi HTML elementi kimi qəbul olunur, sizin komponentiniz kimi yox.

✕ Səhv
function card() { return <div />; }
<card /> {/* tanınmır */}
✓ Düzgün
function Card() { return <div />; }
<Card /> {/* düzgün */}
3

children-i render etməyi unutmaq

Komponent children propunu qəbul edir, amma {'{children}'}-i JSX-də yazmağı unudur. Nəticədə valideyndən ötürülən bütün daxili elementlər "yoxa çıxır" — heç bir xəta mesajı da olmadan.

✕ children itir
function Card({ name }) {
  return <div className="card">
    <h3>{name}</h3>
  </div>;
}
✓ children göstərilir
function Card({ name, children }) {
  return <div className="card">
    <h3>{name}</h3>
    {children}
  </div>;
}
4

Props-u birbaşa dəyişmək (mutasiya)

Bax: yuxarıdakı Immutability bölməsi. Bu, ən çox rast gəlinən konseptual səhvdir və gələcəkdə React-in state idarəetməsini başa düşməyi çətinləşdirir.

5

defaultProps-un funksional komponentlərdə istifadəsi (deprecated)

React 19-dan başlayaraq Component.defaultProps funksional komponentlər üçün konsolda xəbərdarlıq verir. Bunun əvəzinə default parametrlərdən istifadə edin: function Card({ image = "/default.png" }).

6

Props və state-in qarışdırılması

Yeni başlayanlar tez-tez props-u dəyişərək komponenti "interaktiv" etməyə cəhd edir. Amma props yalnız valideyndən gəlir və oxunur. Əgər komponentin öz daxili, dəyişə bilən məlumatı lazımdırsa (məsələn, checkbox-un işarələnib-işarələnməməsi), bu useState hook-u ilə idarə olunan state-dir — bunu növbəti dərsdə ətraflı öyrənəcəyik.

7

Hər renderdə yeni obyekt/massiv yaratmaq

Məsələn <Card style={'{{'}color: "red"{'}}'} /> hər render zamanı təzə bir obyekt yaradır. Kiçik tətbiqlərdə problem yaratmasa da, performans optimallaşdırması (React.memo) tətbiq olunan komponentlərdə lazımsız yenidən renderlərə səbəb ola bilər. Bu mövzuya performans dərsində geri qayıdacağıq.

8

"Prop drilling" — propların çox səviyyədən ötürülməsi

Komponent ağacı böyüdükcə, bir propu 4-5 səviyyə aşağı ötürmək lazım gələ bilər, halbuki yalnız ən aşağıdakı komponentə lazımdır. Bu, kodu çirkli edir. Həll yolu (Context API) irəliləyən dərslərdə ələ alınacaq — hələlik bunun mövcud olduğunu bilmək kifayətdir.

09

Nələri etsək daha yaxşı olar

Kodu yazmaq bir şeydir, onu sürdürülə bilən etmək başqa. Aşağıdakı tövsiyələr komponentlərinizi daha etibarlı, oxunaqlı və komanda ilə işləmək üçün rahat edəcək.

01Tək məsuliyyət prinsipi

Hər komponent bir işi görsün. Əgər komponent 150+ sətir olub çoxlu iş görürsə, onu kiçik alt-komponentlərə bölün.

02Həmişə destructuring

props.name əvəzinə { name } yazın — hansı props-ların istifadə olunduğu funksiyanın imzasından dərhal görünür.

03Tip təhlükəsizliyi

Kiçik layihələrdə prop-types, böyüyəndə isə TypeScript-ə keçməyi düşünün — bu, bugləri kodu işə salmazdan əvvəl tutur.

04Sabit, unikal key

Siyahılarda massivin index-i deyil, məlumatın öz unikal id-si key kimi istifadə olunmalıdır.

05Məntiqi qovluq strukturu

components/Card/Card.jsx + öz stili — hər komponentin öz qovluğu, tapılması asan olsun.

06Configuration əvəzinə Composition

Komponentə 10 fərqli boolean prop (showIcon, showFooter...) əlavə etmək əvəzinə, children ilə çevik struktur qurun.

07ESLint + Prettier

Bu alətlər key unudulması, istifadə olunmayan props kimi səhvləri kodu çalışdırmazdan əvvəl aşkarlayır.

08Adlandırma konvensiyası

Komponent adları — PascalCase (UserCard), props/dəyişənlər — camelCase (isOnline).

10

Tez-tez verilən suallar

Props ilə state arasında əsas fərq nədir?

Props — valideyn komponentdən gələn, uşaq komponentin dəyişə bilmədiyi (read-only) məlumatdır. Komponentin "girişi" (input) kimi düşünün — funksiyanın parametrləri kimi.

State — komponentin öz daxili yaddaşıdır, useState hook-u ilə idarə olunur və komponentin özü onu dəyişə bilər. State dəyişəndə komponent avtomatik yenidən render olunur.

Sadə formula: props = kənardan gələn, state = daxildə yaşayan. useState-i növbəti dərsdə ətraflı öyrənəcəyik.

Komponentləri nə vaxt ayırmaq lazımdır, nə vaxt bir yerdə saxlamaq olar?

Ayırın, əgər: komponent bir neçə yerdə təkrar istifadə olunacaq; komponent artıq böyüyür (100-150+ sətir) və içində bir neçə fərqli məntiq var; UI-də aydın, adlandırıla bilən bir bölmə mövcuddur (Header, Sidebar, Footer).

Bir yerdə saxlayın, əgər: komponentlər bir-biri ilə sıx bağlıdır və heç vaxt ayrı istifadə olunmayacaq; ayırma süni mürəkkəblik yaradır (over-engineering) — məsələn, 3 sətirlik bir <span>-i ayrıca komponentə çıxarmaq adətən mənasızdır.

Qızıl qayda yoxdur, amma yaxşı bir test: "Bu hissəni başqa bir yerdə təkrar istifadə edə bilərəmmi, yoxsa onu izah etmək üçün ayrıca ad lazımdırmı?" Cavab "bəli"dirsə — ayırın.

children props nə vaxt lazım olur?

Lazımdır: komponent bir "konteyner" və ya "wrapper" rolunu oynayanda — Modal, Card, Panel, Layout kimi — burada məzmun əvvəlcədən bilinmir və hər çağırışda fərqli ola bilər.

Lazım deyil: komponentin strukturu həmişə sabitdirsə (məsələn, sadə bir "Avatar" komponenti yalnız şəkil göstərir) — belə hallarda adi props (image, alt) kifayət edir və children əlavə mürəkkəblik yaradar.
