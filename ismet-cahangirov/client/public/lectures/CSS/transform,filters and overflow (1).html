Transform/Filter/Overflow

Elementi hərəkətə gətir, görünüşünü dəyiş, çərçivəsini təyin et

CSS-in görüntü ilə bağlı ən vizual üç xüsusiyyəti — transform (hərəkət və forma), filter (görünüş və işıq) və overflow (çərçivə) — bir dərslikdə, canlı nümunələrlə və tipik xətalarla.

Üç fərqli sual, üç fərqli xüsusiyyət

Bu üç CSS xüsusiyyəti üç sadə sualı cavablandırır:

  • Transform — element haradadır, necə fırlanıb, nə qədər böyükdür? (hərəkət və forma)
  • Filter — element necə görünür? (işıq, rəng, bulanıqlıq — şəkil redaktorundakı süzgəclər kimi)
  • Overflow — məzmun konteynerdən böyük olanda nə baş verir? (çərçivə qaydaları)

Üçü ayrı-ayrı sadədir. Problemlər məhz onlar bir-biri ilə qarşılaşanda başlayır: overflow:hidden bəzən position:sticky-ni sındırır, transform isə position:fixed elementi "tələyə salır". Dərsin sonunda — Birlikdə bölməsində — bunların hamısını bir yerə yığacağıq.

1Transform

Elementi hərəkətə gətir, fırlat, böyüt

CSS transform xüsusiyyəti elementin mövqeyini, ölçüsünü, fırlanma bucağını və əyilməsini dəyişir — bunu sənədin normal düzülüşünə (layout) təsir etmədən edir.

Başqa sözlə: transform elementi vizual olaraq hərəkət etdirir, amma onun sənəddə tutduğu "yer" (boş sahə) yerində qalır. Ona görə də ətrafdaki elementlər sanki heç nə baş verməyib kimi davam edir.

misal 
.kart {
  transform: translateX(40px) rotate(8deg) scale(1.05);
}

Əsas funksiyalar

  • translate(x, y)Elementi üfüqi/şaquli sürüşdürür. translateX() və translateY() ayrıca da yazıla bilər.
  • scale(x, y)Böyüdür/kiçildir. 1 = orijinal ölçü, 0.5 = yarıya, 2 = iki dəfə böyük.
  • rotate(deg)Saat istiqamətində fırladır (mənfi qiymət — əks istiqamətdə).
  • skew(x, y)Elementi paralelogram şəklində əyir. skewX() / skewY() ayrıca.
  • matrix(...)Bütün 2D çevirmələrin riyazi əsası — adətən birbaşa yazılmır, animasiya kitabxanaları üçün faydalıdır.

transform-origin — fırlanma "mərkəzi"

rotate() və scale() elementin transform-origin nöqtəsi ətrafında baş verir. Defolt qiymət mərkəzdir (50% 50%). Sağ aşağıdaki demoda origin düymələrini dəyişərək fırlanmanın necə dəyişdiyinə bax.

Sıra niyə vacibdir?

CSS bir-birinin ardınca yazılan transform funksiyalarını sol tərəfdən sağa, ardıcıl tətbiq edir. Eyni iki funksiya, fərqli sırada yazılsa, fərqli nəticə verə bilər — çünki ikinci funksiya birincinin artıq dəyişdirdiyi koordinat sistemi üzərində işləyir.

⇄Eyni dəyərlər, fərqli sıra → fərqli nəticə

translate → rotate

A
transform: translateX(70px) rotate(45deg);

rotate → translate

B
transform: rotate(45deg) translateX(70px);
Diqqət et: A öz oxu üzrə sağa sürüşüb, sonra fırlanıb. B isə əvvəlcə fırlanıb, ona görə "sağ" istiqaməti artıq dönmüş oxa görədir — nəticədə tamam başqa nöqtəyə gedir. Dəyərlər eynidir, nəticə fərqlidir.

3D transform — bir addım da dərinə

Eyni məntiq üç ölçülü fəzada da işləyir: rotateX(), rotateY(), rotateZ(), translateZ(). Amma 3D effekti görmək üçün ataya perspective (məsələn 800px) verilməlidir — əks halda brauzer dərinliyi göstərmək üçün "kamera bucağı" təyin edə bilmir. Bir neçə 3D elementi həqiqi fəzada birləşdirmək istəyəndə isə transform-style: preserve-3d lazımdır, yoxsa hər element öz müstəvisinə "yastılanır".

flip-kart konsepti 
.sehne { perspective: 900px; }
.kart  { transition: transform .5s; transform-style: preserve-3d; }
.kart.cevrildi { transform: rotateY(180deg); }
.kart .arxa { backface-visibility: hidden; }

Tipik xəta və buglar — Transform

⚠Layout dəyişmir, deyəsən "yerini dəyişdirmir"

Problem: Element vizual olaraq köçür, amma ətrafdaki elementlər sanki heç nə baş vermədiyi kimi qalır, üst-üstə düşmə yarana bilər.
Niyə: transform yalnız rəsm mərhələsində təsir edir, sənədin axınına (flow) qarışmır — orijinal sahə "rezerv" olaraq qalır.
Həll: Elementin həqiqi yerini dəyişmək lazımdırsa, margin, position və ya flex/grid xüsusiyyətlərindən istifadə et.

⚠position:fixed övladı "tələyə düşür"

Problem: Atasında transform olan bir elementin daxilindəki position:fixed uşaq, ekranın küncünə yox, həmin ataya görə sabitlənir.
Niyə: transform (none-dan fərqli hər hansı dəyər) ata üçün yeni containing block yaradır — fixed artıq "ev sahibini" dəyişir.
Həll: Bunu bilərəkdən etmirsənsə, fixed elementi həmin transform olan konteynerin xaricinə çıxar. (Ətraflı: Birlikdə bölməsi)

⚠Bulanıq mətn və kənarlar

Problem: Transform tətbiq olunan mətn/şəkil kənarları bulanıq və ya "titrəyən" görünür.
Niyə: Qeyri-tam piksel qiymətləri (məs. translate(10.5px)) və ya bəzi brauzerlərdə subpixel renderləmə bunu yaradır.
Həll: Mümkün olduqda tam piksel dəyərləri işlət, animasiya zamanı backface-visibility: hidden əlavə et.

⚠Gözlənilməz fırlanma nöqtəsi

Problem: Künc ətrafında fırlatmaq istəyirsən, amma element mərkəzdən fırlanır.
Niyə: transform-origin defolt olaraq 50% 50% (mərkəz) təyin olunub.
Həll: transform-origin: top left; kimi açıq şəkildə təyin et — yuxarıdaki demoda özün sına.

⚠will-change-in həddən artıq istifadəsi

Problem: Performans üçün əlavə etdiyin will-change: transform əksinə səhifəni ləngidir.
Niyə: Hər will-change brauzerə ayrıca "qrafik qat" (layer) yaratmağı bildirir — çoxlu elementə tətbiq olunanda yaddaş istifadəsi artır.
Həll: Yalnız həqiqətən animasiya olunan elementlərə, animasiyadan əvvəl (hover/JS ilə) əlavə et, sonra sil.

⚠Sıra ilə bağlı qarışıqlıq

Problem: Eyni dəyərləri yazdığın halda gözlədiyin vizual nəticəni almırsan.
Niyə: Funksiyalar soldan sağa, ardıcıl tətbiq olunur — yuxarıdaki müqayisə demosunda gördüyün kimi.
Həll: Adətən məntiqli sıra: translate → rotate → scale. Şübhə yarananda DevTools-da canlı yoxla.
2Filter

Elementin görünüşünü süzgəcdən keçir

CSS filter xüsusiyyəti elementə qrafik effektlər tətbiq edir — şəkil redaktə proqramındakı (Instagram, Photoshop) süzgəclər (filter) kimi: bulanıqlıq, parlaqlıq, kontrast, rəng çaları.

Əsas funksiyalar

  • blur(px)Bulanıqlaşdırır.
  • brightness(%)Parlaqlığı artırır/azaldır. 100% = dəyişiklik yox.
  • contrast(%)Kontrastı tənzimləyir.
  • saturate(%)Rəng doyğunluğu — 0% = tam rəngsiz.
  • grayscale(%)Qara-ağ effekti.
  • sepia(%)Köhnə foto (sepiya) effekti.
  • hue-rotate(deg)Bütün rəng çalarlarını rəng çevrəsi üzrə fırladır.
  • invert(%)Rəngləri tərsinə çevirir.
  • drop-shadow(x y blur rəng)Elementin formasına uyğun kölgə (aşağıda box-shadow ilə fərqinə bax).

Bir neçə funksiyanı boşluqla ayıraraq birləşdirə bilərsən: filter: brightness(110%) contrast(105%) saturate(120%); — Instagram-bənzəri "ön ayarlar" elə beləcə qurulur.

backdrop-filter — fərqli oyuncaq

filter elementin özünə tətbiq olunur. backdrop-filter isə elementin arxasında olan məzmuna təsir edir — "buzlu şüşə" (glassmorphism) effektinin sirri elə budur. İşləməsi üçün elementin fonu şəffaf və ya yarı-şəffaf olmalıdır.

▢backdrop-filter — şüşə effekti
buzlu şüşə kart
backdrop-filter: blur(10px); -webkit-backdrop-filter: blur(10px); /* köhnə Safari üçün */

drop-shadow ilə box-shadow fərqi

box-shadow həmişə elementin düzbucaqlı qutusunun kölgəsini çəkir. filter: drop-shadow() isə elementin həqiqi formasına (şəffaf hissələr çıxılmaqla — məsələn SVG və ya şəffaf fonlu PNG-nin konturuna) uyğun kölgə yaradır.

Tipik xəta və buglar — Filter

⚠Bulanıqlıq kənarda kəsilir

Problem: blur() tətbiq etdiyin element ata qutusunun kənarında "kəsilmiş" görünür.
Niyə: Bulanıqlıq vizual sahəsini elementin öz qutusundan kənara çıxarır; ata elementdə overflow:hidden varsa, bu artıq sahə kəsilir.
Həll: Ataya əlavə padding ver, ya da kəsilmə lazım deyilsə overflow:visible saxla.

⚠Animasiya zamanı "donma" (jank)

Problem: Filteri olan böyük elementi animasiya edəndə səhifə ləngiyir.
Niyə: blur və drop-shadow hər kadrda yenidən hesablanması ağır effektlərdir, GPU/CPU yükünü artırır.
Həll: Filter dəyərini animasiya etmək əvəzinə, mümkünsə statik saxla; mobil cihazlarda performansı yoxla.

⚠filter də containing block yaradır

Problem: Filteri olan atanın daxilindəki position:fixed element ekrana görə yox, məhz bu ataya görə sabitlənir.
Niyə: Eynilə transform kimi, filter (none-dan fərqli) də yeni containing block yaradır.
Həll: Bu davranışı gözləmirsənsə, fixed elementi həmin konteynerin xaricinə çıxar.

⚠backdrop-filter "işləmir"

Problem: backdrop-filter yazırsan, amma şüşə effekti görünmür.
Niyə: Adətən üç səbəbdən biri: fon tam şəffaf deyil (yarı-şəffaf rəng lazımdır), brauzer dəstəyi yoxdur (köhnə Safari -webkit- prefiksi istəyir), və ya arxada görünən başqa məzmun yoxdur.
Həll: Yarı-şəffaf background ver, hər iki prefiksi yaz, arxada hərəkət edən/rəngli məzmun olduğunu yoxla.

⚠Yalnız fonu deyil, hamısını dəyişir

Problem: Kartın fonunu sepiya etmək istəyirsən, amma içindəki mətn də rəngini dəyişir.
Niyə: filter ata elementə qoyulanda onun bütün vizual məzmununa (mətn də daxil) tətbiq olunur.
Həll: Yalnız fonu filtrlə — ayrıca ::before pseudo-elementi və ya overlay <div> istifadə et, mətni ondan kənarda saxla.

⚠drop-shadow performansı

Problem: Sadə kölgə üçün drop-shadow() işlədirsən, amma box-shadow-dan daha ağır işləyir.
Niyə: drop-shadow elementin alfa konturunu hesablamalıdır — adi düzbucaqlı kölgə üçün bu lazımsız xərcdir.
Həll: Forma şəffaflığı (kontur kölgəsi) lazım olmayan adi qutular üçün box-shadow seç.
3Overflow

Məzmun konteynerdən böyük olanda nə baş verir?

CSS overflow xüsusiyyəti elementin daxilindəki məzmun onun ölçüsündən böyük olduqda nə ediləcəyini təyin edir: görünsün, kəsilsin, ya da scroll (sürüşdürmə) zolağı yaransın.

Dəyərlər

  • visibleDefolt. Məzmun konteynerdən kənara çıxsa belə görünür.
  • hiddenKənara çıxan hissə tamamilə gizlədilir (kəsilir).
  • scrollHəmişə scroll zolağı göstərir — lazım olsun ya olmasın.
  • autoYalnız lazım olduqda scroll zolağı yaranır.
  • clipYeni dəyər: hidden-ə bənzəyir, amma JS ilə də scroll edilə bilməz, daha "sərt" kəsmədir.

overflow-x və overflow-y oxları ayrıca da təyin oluna bilər; sadəcə overflow: hidden; yazsan, hər ikisinə tətbiq olunur (qısa yazılış).

overflow position:sticky-ni necə sındırır

Bu, ən çox rast gəlinən "sirli bug"-lardan biridir: position:sticky elementin istənilən əcdadında (hətta görünməz şəkildə — heç bir scroll zolağı yaratmasa belə) overflow dəyəri visible-dan fərqli olsa, sticky effekti dayanır. Aşağıdaki nümunədə əhatə edən (wrapper) elementin overflow dəyərini dəyiş və bu səhifəni özü sürüşdürərək sticky başlığın necə davrandığına bax.

📌 Sticky başlıq — scroll edərkən bura yapışmalıdır

Aşağı sürüşdür (məsələn ssəhifəni siçan diyircəyi ilə) — "visible" seçilibsə başlıq ekranın yuxarısına yaxın yapışıb qalacaq. "hidden" və ya "auto" seçəndə isə wrapper-in hündürlüyü məzmuna uyğun olsa belə (heç nə vizual kəsilmir!) sticky sakitcə dayanacaq.

Maraqlısı budur: bu wrapper-in nə hündürlüyü məhduddur, nə də nəzərə çarpan kəsilmə var — ona görə bu bug çox vaxt fərqinə belə varılmadan komponentin başqa yerində "clearfix" və ya görünüş üçün qoyulmuş overflow:hidden tərəfindən yaranır.

Davam et, daha bir az sürüşdür — sticky başlığın vəziyyətini izlə.

Bölmənin sonu. İndi yuxarıdaki üç düyməni növbə ilə sınayıb fərqi müşahidə et.

Tipik xəta və buglar — Overflow

⚠Sticky birdən-birə işləmir

Problem: position:sticky qoyduğun element heç yapışmır, sadəcə adi element kimi davranır.
Niyə: Aralarındaki istənilən əcdadda (görünməz şəkildə belə) overflow dəyəri visible-dan fərqlidir.
Həll: DevTools-da bütün əcdadları yoxla, lazımsız overflow:hidden/auto-ları tap və sil.

⚠X və Y oxu bir-birini "korlayır"

Problem: overflow-x:hidden; overflow-y:visible; yazırsan, amma gözlənilməz scroll zolağı çıxır.
Niyə: Spesifikasiyaya görə bir ox visible-dan fərqli olanda, digər ox visible qala bilmir — avtomatik autoya keçir.
Həll: Yuxarıdaki demoda gördüyün kimi, hər iki oxu açıq şəkildə təyin et, "computed" dəyərini DevTools-da yoxla.

⚠Görünməli elementlər kəsilir

Problem: Badge, tooltip, dropdown və ya kölgə (box-shadow) gözlənilmədən yarımçıq görünür.
Niyə: overflow:hidden olan ata, mənfi margin, transform və ya absolute mövqe ilə "kənara çıxan" hər şeyi kəsir.
Həll: Bu elementi başqa, overflow-u olmayan bir ataya köçür, ya da overflow:visible saxla.

⚠Ellipsis görünmür

Problem: text-overflow:ellipsis yazmısan, amma "..." görünmür, mətn sadəcə kəsilir və ya heç kəsilmir.
Niyə: Adətən white-space:nowrap unudulur — mətn sətirlərə bölünəndə ellipsis-in "kəsiləcək sona" ehtiyacı qalmır.
Həll: Yuxarıdaki demoda olduğu kimi, həmişə üç xüsusiyyəti birlikdə yaz.

⚠Scroll zolağı düzülüşü "atlatdırır"

Problem: Məzmun bir az artanda scroll zolağı çıxır və bütün düzülüş bir neçə piksel sola "tullanır".
Niyə: Bəzi sistemlərdə (məsələn Windows-da) scroll zolağı öz sahəsini konteynerin daxilindən "yeyir".
Həll: scrollbar-gutter: stable; ilə scroll zolağı üçün yer həmişə ayrılmış olsun, görünsə də, görünməsə də.

⚠fixed elementi tək başına saxlamır

Problem: Atasında overflow:hidden olduğu üçün position:fixed elementin onun daxilində qalacağını gözləyirsən, amma element yenə bütün ekrana görə hərəkət edir.
Niyə: overflow:hidden TƏK BAŞINA fixed üçün containing block yaratmır — fixed yalnız ekrana (viewport) görə işləyir, nə qədər ki ata əlavə olaraq transform/filter/will-change almayıb.
Həll: Fixed elementi məhdudlaşdırmaq istəyirsənsə, ataya transform: translate(0) kimi "boş" bir transform əlavə et. Ətraflı: aşağıdaki Birlikdə bölməsi.
4Birlikdə

Üçü qarşılaşanda: "containing block" sirri

İndiyə qədər gördüyün üç "tələ" — fixed-in transform/filter tərəfindən tutulması və sticky-nin overflow tərəfindən sındırılması — eyni bir konsepsiyaya bağlıdır: containing block (əhatə edən qutu).

Normalda position:fixed elementi ekranın özünə (viewport) görə yerləşir. Amma əgər bu elementin istənilən əcdadında transform (none-dan fərqli), filter (none-dan fərqli), perspective və ya will-change: transform varsa — həmin əcdad fixed elementin yeni "ev sahibi" olur. Fixed artıq ekrana görə yox, məhz bu əcdadın qutusuna görə sabitlənir.

Bu, çox vaxt qəsdən belə qurulur (məsələn modal pəncərə daxilində bir elementi yalnız o modala görə sabit saxlamaq üçün) — amma gözlənilmədən baş verəndə (məsələn animasiya kitabxanası hər karta avtomatik transform əlavə edəndə) çox vaxt itirə bilərsən.

Praktik nümunə: üçünü bir komponentdə birləşdirmək

Aşağıdaki "polaroid" kartı dərsin əvvəlində gördüyün heroya bənzəyir — indi onun necə qurulduğunu addım-addım görəcəksən. Kartın üzərinə gəl (hover et):

✦Polaroid kart — transform + filter + overflow
üzərinə gəl →
.polaroid { overflow: hidden; /* ÇƏRÇİVƏ */ border-radius: 6px; transform: rotate(-4deg); /* HƏRƏKƏT */ transition: transform .3s; } .polaroid .foto { filter: sepia(.4) saturate(1.2); /* GÖRÜNÜŞ */ } .polaroid:hover { transform: rotate(0deg) scale(1.04); }

Üç xüsusiyyət, üç ayrı rol: overflow şəkli çərçivəyə "kəsir", filter ona köhnə-foto görünüşü verir, transform isə kartı bir az əyib hover-də canlandırır.

Nəsə işləmir? Yoxlama siyahısı

  1. position:fixed elementim gözlədiyim yerdə deyil → əcdadlardan birində transform, filter və ya will-change axtar.
  2. position:sticky yapışmır → əcdadlardan birində (görünməz olsa belə) overflow dəyəri visible-dan fərqlidirmi, yoxla.
  3. Kölgə/bulanıqlıq/badge kəsilir → ən yaxın overflow:hidden olan atanı tap, lazım olmayan yerdə sil.
  4. Vizual effekt gözlədiyim kimi deyil → DevTools-da elementi seç, "Computed" tabında overflow, transform, filter dəyərlərinin həqiqi (hesablanmış) qiymətlərinə bax.

Özünü sına

Cavabı təxmin et, sonra düyməyə basıb yoxla. Tam başa düşdüyünə əmin olmaq üçün ən yaxşı yol budur.

1translateX(50px) rotate(45deg) ilə rotate(45deg) translateX(50px) arasında fərq varmı?
Bəli, fərq var. Birincidə element əvvəlcə sağa sürüşür, sonra fırlanır. İkincidə əvvəlcə fırlanır — "sağ" istiqaməti artıq dönmüş koordinat sistemində hesablanır, nəticədə tamam başqa nöqtəyə gedir. Yuxarıdaki Transform bölməsindəki müqayisə demosunda bunu canlı gördün.
2Kartının küncündəki kiçik "badge" niyə görünmür, halbuki kodun düzgün olduğuna əminsən?
Çox güman, badge-i əhatə edən atada overflow:hidden var və badge mənfi margin və ya position:absolute ilə həmin atanın kənarından "çıxır" — overflow bu hissəni kəsir.
3position:sticky; top:0; yazmısan, amma element heç yapışmır. Səbəb nə ola bilər?
İstənilən əcdadında (görünməz olsa belə) overflow dəyəri visible-dan fərqlidir. DevTools-da bütün əcdadları yoxlamaq lazımdır.
4filter: blur(10px) tətbiq etdiyin elementin kənarları niyə kəsik görünür?
blur() elementin vizual sahəsini öz qutusundan kənara çıxarır. Ata elementdə overflow:hidden varsa, bu əlavə sahə kəsilir.
5text-overflow:ellipsis yazmısan, amma "..." görünmür. Ən çox unudulan şərt nədir?
Adətən white-space:nowrap unudulur. Ellipsis üçün white-space:nowrap + overflow:hidden + text-overflow:ellipsis — üçü birlikdə lazımdır.
6Transform tətbiq etdiyin element ətrafdaki elementləri "itələyirmi" (yerlərini dəyişdirirmi)?
Xeyr. transform yalnız vizual təsir edir, sənədin normal axınına (layout) qarışmır — elementin orijinal yeri "rezerv" olaraq qalır, ətrafdaki elementlər sanki o köçməyib kimi davranır.
